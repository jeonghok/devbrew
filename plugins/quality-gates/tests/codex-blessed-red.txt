# 검토를 마친 red. <파일명> <정규화된 실패 출력 sha256>
#
# 양방향이다: 미등재·해시 불일치 실패는 RED, 등재됐는데 GREEN이 된 항목도 RED.
# 목록은 줄어들기만 한다 — 새 red를 여기 넣는 것은 검토를 마쳤다는 선언이다.
#
# 정규화: <REPO>/<TMP> 경로 치환 + 숫자 → N + 실패 줄(FAIL|✗)만.
# 이유: 등재 대상 하나의 출력이 quality-pipeline/SKILL.md의 grep 카운트를 담아,
#       그 파일을 고칠 때마다 원시 해시가 바뀐다. 어떤 assert가 실패하는지(문구)는
#       남으므로 같은 파일이 **다른 이유로** 실패하기 시작하면 해시가 바뀐다.
#
# 2026-08-22 현재 **등재 0건**이다. 빈 원장은 고장이 아니라 규약("목록은
# 줄어들기만 한다")의 도달점이며, 메커니즘은 그대로 살아 있다 — 새 red를 여기
# 등재하지 않으면 test_codex_backward_compat.sh가 `미등재`로 RED를 낸다.
#
# 마지막 두 항목이 빠진 경위 (기준선 RED 4건 해소 사이클):
#  - consent-marker 판: 그 **테스트 자체가 삭제**됐다. 지키던 메커니즘(SKILL.md의
#    cost-consent 마커)이 `753c9e2`의 v2.0.0 재작성에서 사라져 테스트만 남아
#    RED였다. 소비자 루프는 실재하는 파일만 도는지라 등재만 남겨도 조용했겠지만,
#    대상이 없어진 등재는 같은 커밋에서 지운다.
#  - security-reviewer kill switch 판: 그 테스트가 **GREEN이 됐다**. 약속만 있고
#    집행이 없던 kill switch를 실제로 dispatch 지점에 구현했기 때문이다. 등재를
#    남겨두면 위 양방향 래칫이 `stale 등재`로 RED를 낸다(실측 확인).
