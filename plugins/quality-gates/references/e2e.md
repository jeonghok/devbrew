# e2e — 걷기 절차

판단과 기록 규칙이다. 스크립트는 SKILL.md `## e2e` 절의 펜스로만 부른다.

## 1. 시나리오 만들기

diff 와 의도 출처(`intent:` 줄의 출처)를 읽고, 이 변경이 바꾼 동작을 사람이 보는 표면에서 확인할 시나리오를
1~3개 만든다. 시나리오마다 다음 다섯을 적는다.

| 칸 | 내용 |
|---|---|
| 표면 | `웹 UI` · `API` · `CLI` 중 하나 |
| 부팅 명령 | 리포 루트에서 실행할 명령을 **글자 그대로**. 추측으로 플래그를 더하지 않는다 |
| 명령 출처 | 그 명령을 읽은 자리(`CLAUDE.md` · `README.md` · `package.json` 의 `scripts` · `Makefile` 등)와 줄 |
| 준비 신호 | 포트 번호 하나, 또는 부팅 출력에 나타날 줄의 정규식 하나 |
| 걸을 단계 · 기대 상태 | 단계 목록과, 각 단계 뒤 **관측 가능한** 기대 상태 목록 |

- 부팅 명령의 출처를 찾지 못하면 그 시나리오를 만들지 않는다. CLI 표면이고 띄울 서버가 없으면 부팅 명령 칸에
  `없음(CLI 직접 실행)` 을 쓰고 준비 신호를 비운다. 대신 걸을 단계에서 실행할 CLI 명령 줄을 전부 **글자 그대로**
  적고 그 출처를 적는다 — 이 시나리오가 실행할 명령은 그 줄들이 전부다.
- 기대 상태는 의도 출처가 약속한 동작에서 뽑는다. 의도 출처에 없는 동작을 기대 상태로 만들지 않는다.
- 이 변경이 사람이 걸을 표면을 바꾸지 않았으면(문서 · 내부 리팩터 · 테스트만) 시나리오를 만들지 않는다.
- 현재 체크아웃만 걷는다. 리뷰 범위가 토픽(`Spec:` 트레일러)으로 다른 브랜치를 묶었으면 질문 본문에 「토픽의 다른
  구성원 브랜치는 걷지 않는다」를 적는다.

**걸을 도구** — 표면마다 도구를 고른다.
- `API` · `CLI` 는 Bash 로 걷는다(API 는 `curl` 로 `127.0.0.1` 의 승인된 포트만 부른다).
- `웹 UI` 는 이 세션의 도구 목록에 페이지를 열고 접근성 트리 스냅숏을 돌려주는 브라우저 자동화 도구가 있을 때만
  걷는다. 지금 도구 목록(지연 로드 목록 포함)에서 찾는다. 없으면 그 시나리오에 `걸을 도구 없음` 을 표시하고, 같은
  동작을 API 로 확인할 수 있으면 그 시나리오를 따로 만든다.

## 2. 질문

`AskUserQuestion` 질문 하나, 단일 선택이다. 선택지는 넷을 넘지 않는다.

- 시나리오가 있으면: 시나리오마다 선택지 하나 + `안 한다`. 시나리오가 둘 이하면 `걸을 것 없음` 도 넣는다.
  `걸을 도구 없음` 시나리오는 선택지로 내지 않고 질문 본문에 그 사실을 적는다.
- 걸을 표면이 없다고 판단했으면: `걸을 것 없음 — <한 줄 사유>` 를 **첫 선택지**로, 그다음 `안 한다`.
- 시나리오 선택지의 `label` 은 `시나리오 <n> — <표면> <한 줄 요약>`, `description` 은 부팅 명령 글자 그대로 ·
  명령 출처 · 기대 상태 수 · 「고르면 이 명령을 이 컴퓨터에서 실행하는 것을 승인한다」 를 담는다.
- CLI 직접 실행 시나리오의 `description` 은 부팅 명령 자리에 실행할 CLI 명령 줄을 전부 글자 그대로 담는다. 고르면 그 줄들만 실행을 승인한다.
- 질문 본문 · 선택지의 `label` · `description` 은 SKILL.md `## 사람에게 쓰는 글` 을 따른다. 부팅 명령은 글자 그대로 둔다.
- 「기타」 로 받은 답은 시나리오 수정으로 읽는다. 바뀐 부팅 명령이 있으면 그 명령을 글자 그대로 다시 보이고 같은
  질문을 한 번 더 띄운다(그 선택이 실행 승인이다). 두 번째에도 「기타」 면 `안 한다` 로 닫는다.

시나리오를 고르는 것이 그 부팅 명령(CLI 직접 실행이면 적힌 CLI 명령 줄들)을 실행해도 된다는 승인이다. 승인되지 않은
명령은 실행하지 않는다.

## 3. 걷기 규칙

- 승인된 명령이 띄운 `127.0.0.1` · `localhost` origin 만 연다.
- 다른 origin 으로 가는 링크 · 리다이렉트는 따라가지 않고 그 사실을 관측으로 적는다.
- 파일 업로드 · 다운로드 저장 · 외부 계정 로그인 · 결제는 하지 않는다.
- 걷다가 버그를 보면 고치지 않는다. 관측으로 적는다. 고침은 Fix-loop 의 Retry 로만 한다.
- 걷는 동안 리포의 파일을 Edit · Write 하지 않고, git 명령으로 상태를 바꾸지 않는다. qg 상태 폴더
  (`.claude/quality-gates/<session-id>/`)에 증거표를 쓰는 것만 한다.
- 각 기대 상태의 관측은 도구 출력 원문을 짧게 인용한다(HTTP 상태 줄 · 응답 본문 일부 · 스냅숏의 노드 텍스트 ·
  CLI 출력 줄). 인용할 출력이 없으면 그 기대 상태는 `미확인` 이다.

## 4. 증거표

증거표는 탭으로 나눈 세 칸이다: `기대 상태` · `판정` · `증거`. 첫 줄은 그 머리줄이다. `판정` 은 `충족` · `불충족` ·
`미확인` 중 하나다. 증거 안의 탭은 공백으로, 줄바꿈은 ` ⏎ ` 로 바꿔 한 줄에 둔다. 증거가 없으면 `-` 를 쓴다.

판정안은 `e2e-state.sh propose` 가 낸다 — 직접 정하지 않는다. 규칙은 이렇다.
- 증거 없는 `충족` 은 `미확인` 으로 강제된다.
- `불충족` 이 하나라도 있으면 `fail`.
- 그 밖에 `미확인` 이 있거나 기대 상태가 없으면 `미확인`.
- 나머지는 `pass`.

판정안을 덮는 세 경우가 있다.
- 부팅이 `boot-failed: …` 로 끝났으면 걷지 않았다. 판정안은 `미확인(부팅 실패)` 이고, 부팅 출력 끝부분을 증거로 보인다.
- `compare` 의 마지막 줄이 `changed: <N>` 이면 판정안은 `무효(코드 변경)` 이고, `changed:` 줄들을 경로 목록으로 보인다.
  걷기 앞 지문이 낸 `sha256:` 값을 `compare --before-sha256` 로 넘기므로, 걷는 사이 before 지문 파일이 고쳐 쓰였으면 그것도
  `changed: before 지문 파일(…)` 한 줄로 센다.
- 지문을 잴 수 없었으면 무효인지 알 수 없다. 판정안은 걷기 앞이면 `미확인(지문 실패)` · 부팅 호출까지 실패했으면
  `미확인(지문 · 부팅 호출 실패)` · 걷기 뒤면 `미확인(걷기 뒤 지문 실패)` 이고, stderr 사유를 보인다.

`compare` 의 판정은 **마지막 줄**(`same` · `changed: <N>`)이 정한다. 경로 이름에 줄바꿈이 든 파일은 `changed:` 줄
여러 개에 걸쳐 찍힐 수 있다 — 경로 목록은 보이는 그대로 옮기고, 개수는 마지막 줄에서 읽는다.

## 5. 걷기 직후 게이트

증거표와 판정안을 보인 뒤 `AskUserQuestion` 하나를 띄운다. 선택지는 판정안의 행을 따른다.

| 판정안 | 선택지 |
|---|---|
| pass | 승인 / fail 로 뒤집기 / 다시 걷기 |
| fail | Fix-loop 게이트(고치고 다시 돌기 / 지금 판정으로 끝내기 / 멈추기) + pass 로 뒤집기 |
| 미확인(괄호 안 사유 포함) | 다시 걷기 / fail 로 뒤집기 / 그대로 둠 |
| 무효(코드 변경) | 리뷰·테스트부터 다시(CAP 에서는 한 번 더 돌기) / 바뀐 경로가 앱 실행 산출물임을 확인하고 판정안 유지 / 그대로 둠 |

- `fail` 행은 Fix-loop 게이트와 같은 질문이다. Retry 의 「적용」 목록은 불충족 기대 상태마다 오케스트레이터가 쓴
  고칠 계획이다 — 범위는 그 기대 상태를 만족시키는 데 필요한 변경에 한정하고, Fix-loop 의 의도 대조와 제외 사유
  셋을 그대로 거친다. CAP 에 닿았으면 fail 행에 「고치고 다시 돌기」 대신 「한 번 더 돌기」를 넣고, 고르면 SKILL.md 의
  Max-iter decision 과 같이 `extra-iterations.md` 에 한 줄을 기록한다(출처 `label` · `typed` 와 원문). 반복 하나만 열린다.
  「기타」 칸 글이 뒤집기 사유면 뒤집기이고 반복을 열지 않는다 — 여는 뜻이 분명할 때만 `typed` 로 열고, 모르겠으면 아무것도
  열지 않고 게이트를 다시 띄운다.
- `다시 걷기` 는 코드 상태가 그대로인 판정안(pass · 미확인)에만 있고 iteration 을 쓰지 않는다. 같은 시나리오 · 같은
  명령으로 SKILL.md 의 걷기 펜스부터 다시 돈다. `미확인(걷기 뒤 지문 실패)` 에는 넣지 않는다 — 걷는 사이 코드가
  바뀌었는지 모른다.
- `리뷰·테스트부터 다시` 는 iteration 하나를 쓴다. CAP 에 닿았으면 그 자리에 「한 번 더 돌기」를 넣는다 — 고르면 위와 같이
  `extra-iterations.md` 에 기록하고 `리뷰·테스트부터 다시` 와 같은 경로로 간다. CAP 를 넘어 반복을 쓰는 길은 모두 이 기록을 거친다.
- `바뀐 경로가 앱 실행 산출물임을 확인하고 판정안 유지` 는 앱이 부팅 · 실행 중에 스스로 쓰는 파일(lockfile 갱신 ·
  로컬 DB · 로그 · 생성물)만 바뀐 경우를 위한 것이다. 바뀐 경로 중 소스 파일이 하나라도 있으면 이 선택지를 넣지
  않는다. 고르면 `propose` 의 판정안이 무효를 대신하고, 그 판정안의 행으로 이 게이트를 한 번 더 띄운다. 이 선택은
  「사람이 뒤집음」으로 기록한다.
  이 선택 뒤에는 추적 파일(예: lockfile)이 바뀐 채 남을 수 있다. 그러면 `## Publish` 는 「커밋 안 된 변경이 있다」로
  게시하지 않는다 — 판정이 본 코드가 PR 의 커밋과 달라서이고, 맞는 동작이다.
- 뒤집기(`fail 로 뒤집기` · `pass 로 뒤집기` · 산출물 확인)는 사람에게 한 줄 사유를 받는다. 「기타」 칸의 글을 그
  사유로 쓰고, 비어 있으면 사유를 한 번 더 묻는다.
- 게이트는 걷기마다 띄운다. Retry 뒤 다시 걸을 때도 띄운다.

## 6. 게이트 결과 → e2e 칸

| 게이트 결과 | e2e 칸 | 사람이 뒤집음 |
|---|---|---|
| pass 승인 | `pass` | 아니오 |
| fail 에서 지금 판정으로 끝내기 | `fail` | 아니오 |
| fail 에서 멈추기 | `fail` | 아니오 |
| fail 로 뒤집기 | `fail` | 예 |
| pass 로 뒤집기 | `pass` | 예 |
| 미확인 · 무효에서 그대로 둠 | `미확인` | 아니오 |
| 무효인데 CAP 에 닿아 그대로 둠 | `미확인` | 아니오 |
| 산출물 확인 뒤 다시 띄운 게이트의 결과 | 그 결과의 칸 | 예 |
| 질문에서 안 한다 | `안 함` | 아니오 |
| 질문에서 걸을 것 없음 | `걸을 것 없음` | 아니오 |
| 시나리오 전부가 걸을 도구 없음 | `걸을 도구 없음` | 아니오 |
| kill switch(지문 · 부팅의 exit 3) | `꺼짐(kill switch)` | 아니오 |
| 루프가 「멈추기」(aborted)로 끝나 e2e 를 건너뜀 | `안 함` | 아니오 |

fail 에서 「멈추기」를 고르면 실행은 aborted(`aborted iter <N>`)다. 판정 줄의 e2e 칸은 `fail` 이고, 게시는
`skipped: aborted` 다.

## 7. 기록

걷기마다 세션 폴더의 `e2e-record.md` 에 `### 걷기 <n>` 소제목을 두고 시나리오(표면 · 부팅 명령 · 명령 출처 ·
준비 신호) · 증거표 원문 · 판정안 · 게이트 선택을 덧붙인다. 뒤집었으면 `e2e-flip.md` 에
`- e2e: <판정안> → <결과> — <사람의 한 줄 사유>` 한 줄을 덧붙인다. 걷는 동안 `result.md` 에는 쓰지 않는다 —
`## Final verdict` 의 기록 펜스가 두 파일을 로컬 결과(`result.md`)의 `## 차등 테스트` 뒤 `## e2e` · `## 뒤집기` 절로
옮긴다.
