# 로드맵 온톨로지

지휘자와 화면은 컨트롤 플레인에서 출발해 식별자로 아래 층을 타고 내려간다. 사실마다 주인은 하나다 — 주인만 쓰고 나머지는 읽거나 계산한다. 고칠 때는 주인을 고친다. 주인과 캐시가 어긋나면 주인을 믿고 캐시를 고친 뒤 알린다.

## 계층

| 층 | 무엇 | 예 |
|---|---|---|
| 컨트롤 플레인 | 보고 조작하는 곳 — 자기 상태가 없고 아래 층에서 계산한다 | 지휘자 skill · `/spec-distill:roadmap-status` · 상태줄 · 작업 목록 |
| 계획 | 무엇을 왜 하나 — 정본 | 로드맵 → 에픽 묶음 → 설계문서 · 산출물 → 계획 |
| 실행 | 실제로 일어나는 것 | 세션 · agent · worktree · 브랜치 · 커밋 · PR |
| 기록 | 무엇이 일어났고 무엇을 정했나 | 결정 기록 · 재분해 이력 · 판정 · 구현 대조 · 지휘 기록 · 기계 상태 · 실행 원장 · 리뷰 원장 |

## 객체

| 객체 | 층 | 식별자 | 속성 | 링크(칸 · 키) | 주인 |
|---|---|---|---|---|---|
| 로드맵 | 계획 | 레포 상대 경로 | 에픽 · 결정 기록 · 재분해 이력 · 위험 번호표 | `source_brief` → brief · `specs_dir` · `plans_dir` · `test_command` · `review_model` · `parallel_default` → 레포 설정 | 로드맵 파일(git) — 인터뷰가 만든다 · 에픽 경계 · 범위 · 의존 · 흐름 · 산출물은 재분해 절차로 · 레포 설정 · 결정 기록은 로드맵 수정 PR 로 |
| 에픽 | 계획 | 블록 번호(예: R5) | 칸: 의도 · 범위 · 의존 · 브랜치 · 묶음 · 경로 예약 · spec · 발화 · 항목 · 완료 · 크기 · 병렬 · 순서 이유 · 근거 · 흐름 · 산출물. 종류(묶음 · 브랜치 · 결정)마다 필수 · 금지 칸이 다르다(`REQUIRED` · `FORBIDDEN`) | `묶음:` → 에픽 묶음 · `의존:` → 에픽 · `브랜치:` → 브랜치 · `산출물:` → 산출물 · `spec:` → 설계문서 | 로드맵 — 읽기는 `roadmap_model.py` |
| 에픽 묶음 | 계획 | 로드맵 옆 `<에픽>.md` | 배정 번호 · brief 발췌 · 인터페이스 | `epic` → 에픽 · `roadmap` → 로드맵 · `source_brief` → brief · `ids` → 번호 | 생성기(`roadmap_write.py` · `roadmap_render.py`) |
| 설계문서 | 계획 | 레포 상대 경로 | AC · 번호 대조 · 미룸 · 결정 기록 | `source_interview` → 에픽 묶음 · `roadmap` → 로드맵 | 그 에픽의 설계 세션 |
| 산출물 | 계획 | 레포 상대 경로 | 설계문서 대신 내는 결과 · 판정 · 구현 대조 · 지휘 기록 절 | `산출물:` ← 에픽 | 그 에픽의 세션 |
| 계획 | 계획 | 레포 상대 경로 | task · 이 계획의 AC | `**Spec:**` → 설계문서 | 계획을 쓴 세션 |
| 레포 설정 | 계획 | 로드맵 frontmatter 키 | 설계문서 · 계획 폴더 · 테스트 명령 · 리뷰 모델 · 병렬 권장 수(기본값이지 상한이 아니다) | `specs_dir` · `plans_dir` · `test_command` · `review_model` · `parallel_default` | 로드맵 frontmatter, 없으면 기본값 — 갱신은 로드맵 수정 PR · 기본값 · 검증은 `repo_defaults.py` |
| 브랜치 | 실행 | 브랜치 이름 | 끝 커밋 · 머지 여부 | `브랜치:` ← 에픽 · PR 의 head → PR | git — 상태 계산은 `roadmap_status.py` |
| 커밋 | 실행 | SHA | 메시지 · 트레일러 | `Spec:` → 설계문서 | git |
| PR | 실행 | `#<n>` | 상태(열림 · 머지됨 · 닫힘) · 통합 리뷰 인계 절 | `PR` → 캐시 · PR 의 head → 브랜치 | GitHub(있으면) — 기계 상태의 것은 캐시 |
| worktree · agent | 실행 | 경로 · agent 이름 | 용도 · 만든 때 · 맡은 일 | `자원` · `살아 있는 agent` → 에픽 | 돌고 있는 agent 의 원천은 하니스 agent 목록 — 지휘자 기계 상태(이 기계에서만)는 사본이고 말하기 전에 맞춘다 |
| 작업 | 실행 | 종류 + 이름 | 단계 · 담당 agent · 근거 경로 | `작업` → 에픽 또는 「로드맵 밖」(수리 PR · 정리 일) | 지휘자 기계 상태(사본) — 에픽 단계의 원천은 상태 계산, 과제 진행의 원천은 실행 원장 |
| 스위트 잠금 | 실행 | `<기계 상태 폴더>/files/suite-lock` | 주인 · 잡은 시각 | 지휘자 스위트 대조 · 하위 agent 전체 스위트 | `suite_lock.py` — 경로는 `conductor_ledger.py suite-lock` 이 기계 상태에서 도출해 하위에게 싣는다 |
| 결정 기록 줄 | 기록 | 블록 · 종류 · 날짜 | 원문 「…」 | `## 결정 기록` → 에픽 | 로드맵 — 갱신은 로드맵 수정 PR 로 |
| 재분해 이력 항목 | 기록 | `### <날짜> · <사유>` | 바뀜 · 원문 | `## 재분해 이력` → 에픽 | 로드맵 — 재분해 절차로만 |
| 번호 대조 행 | 기록 | brief 번호(C7 · S36 · «key») | 반영/기각 · 자리 또는 이유 | `## 번호 대조` → `ids` · `받듦` → 에픽 | 설계문서 — 점검은 `check_bundle_coverage.py` |
| 미룸 · 넘김 줄 | 기록 | 준 에픽 + 항목 | 이유 · 상태(열림 · 처리됨 · 확인됨 · 이슈 · 받는 곳 없음) | `받는 곳` → 에픽 · `#<n>` | 준 쪽 설계문서 — 상태 계산은 `roadmap_model.py`(읽기 전용) |
| 넘김 확인 줄 | 기록 | 준 에픽 + 항목 해시 8자 | 근거 | `- 넘김 확인` → 미룸 / 넘김 줄 | 받는 쪽 설계문서 `## 지휘 기록` — 쓰기 `conductor_state.py` · 읽기 `roadmap_model.py`(CONFIRM_RE) |
| 판정 | 기록 | 원장 줄 | 무엇 — 왜 — 틀리면 비용 | `실행 원장` → 계획 / 에픽 · `## 판정` ← 원장 줄(보관본) | 실행 중엔 실행 방식 원장, 끝나면 설계문서 `## 판정` |
| 구현 대조 | 기록 | `## 구현 대조 — <계획 경로>` | AC 보고 요약 | `## 구현 대조` → 계획 | 설계문서(지휘자가 쓴다) |
| 지휘 기록 | 기록 | 설계문서 절 | 고른 흐름 · 건너뛴 확인과 이유 · 보낸 일 · 넘김 확인 | `## 지휘 기록` → 에픽 | 설계문서(지휘자가 쓴다) |
| 기계 상태 | 기록 | `<state-root>/<지휘자 상태 폴더>/<로드맵 폴더>/machine.md`(폴더 이름은 `repo_defaults.CONDUCTOR_DIR`) | PR 캐시 · 실행 원장 위치 · 자원 · agent · 작업 · 기다리는 질문 · 쌓인 기록 · 임시 레포 설정 | `PR` · `실행 원장` · `자원` → 실행 층 | 지휘자 — 이 기계에서만 뜻이 있는 것. 쌓인 기록만은 다시 만들 수 없다 — 지우기 전에 커밋한다. 형식 · 읽기 · 쓰기 · 잠금 `conductor_state.py` · 화면 `control_plane.py` |
| 리뷰 원장 | 기록 | 문서별 상태 디렉토리 | 라운드 · 재리뷰 상한 · finding | 문서 경로 → 설계문서 | 리뷰 엔진 |

## 타고 내려가기

`/spec-distill:roadmap-status <로드맵> <에픽>` 이 에픽 하나의 묶음 · 설계문서 · 계획 · 브랜치 · PR · 동시에 갈 수 있는 에픽 · 열린 넘김 · 판정 줄 · 자원을 경로와 번호로 보인다. 줄마다 경로나 번호가 있어 한 단계 더 내려간다 — 설계문서 경로로 그 문서를, 계획 경로로 그 계획을, `#<n>` 으로 그 PR 을 연다.
