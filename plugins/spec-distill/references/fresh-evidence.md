# 신선한 근거 — 조사 주문을 쓸 때 · 웹 근거를 받을 때

시간에 따라 바뀔 수 있고 열린 결정에 닿는 사실(버전 · API · 공식 사용법 · 제품 정책 · 표준 · 제도 등, 예시에 한정하지 않음)을 다룰 때의 기본 행동이다. 형식 칸을 채우라는 게이트가 아니라 기본 행동이다. 일의 모양이 다르면 모델이 판단하고 이유를 적는다.

## 원칙과 행동

| 원칙(원문) | 행동 |
|---|---|
| 1 「모델이 자신의 지식이 오래되었는지 정확히 안다고 가정하지 말고, 시간에 따라 변할 수 있으며 현재 결정에 영향을 주는 사실을 검증 대상으로 삼는다.」 | 열린 결정이 시간에 따라 바뀌는 사실에 기대면, 모델의 확신과 무관하게 그 사실을 조사 주문에 넣는다. request-framing seed 의 «다시 검증할 것» 문단이 첫 목록이다 |
| 2 「조사 에이전트가 잘못된 지식을 가져왔을 수 있으니 항상비판적으로 봐야한다. 향후에도 항상 검증을 통해 뒤집힐 수 있는 컨텍스트이며 조사해온 내용으로 인해 잘못된 방향으로 빠지면 안된다」 | 결정에 닿는 웹 주장은 본체가 1차 자료로 한 번 더 확인하거나 불확실로 둔다. 조사 결과가 방향을 바꿀 만하면 사용자에게 결정으로 보인다. brief §4 항목은 뒤에 반증되면 다시 연다 |
| 3 「기술 정보는 현재 프로젝트가 실제로 사용하는 버전과 최신 upstream 버전을 혼동하지 않는다.」 | 기술 주장은 «이 레포가 쓰는 판»과 «최신 upstream»을 따로 적는다. 레포 버전은 추측하지 않고 읽는다(잠금 파일 등) |
| 4 「최신과 신뢰성 간 스윗포인트를 생각해야하며 사용자에게 선택지를 줄 수 있어야 한다 모델이 혼자 결정하지 않음」 | 최신과 안정이 갈리면(새 판 · 실험 기능 · 막 바뀐 정책) 차이를 보이고 선택지로 묻는다 |
| 5 「가능한 경우 공식 문서와 1차 자료를 우선한다.」 | 조사 주문의 기본 지시다. 2차 자료는 2차로 표시한다 |
| 6 「확인하지 못한 내용은 현재 사실처럼 단정하지 말고 불확실성을 드러낸다.」 | 확인 못 한 주장은 «지금 이해» · brief 에 「확인 못 함」으로 적는다 |
| 7 「조사 능력을 제한하는 임의의 검색 횟수·출처 수 상한이나, 형식만 채우는 무거운 게이트를 추가하지 않는다.」 | 검색 · 출처 수 상한을 두지 않는다. 아래 칸은 선택이고 게이트가 없다 |
| 8 「사용자 판단과 외부 사실의 교정을 구분하고 기존 사용자 결정권을 유지한다.」 | 조사가 사용자 발화와 어긋나면 갈라 본다. 사실 주장이면 출처와 함께 교정을 보이고 묻는다. 판단 · 선호면 덮지 않고 정보로 기록한다. 확정 항목은 근거를 보이고 사용자 동의로만 재결정한다 |

## 낡은 지식 바로잡기

조사가 앞서 믿던 사실이 낡았음을 보이면, 다음 «지금 이해»에 바로잡은 사실을 명시하고 audit 에 앞 믿음을 「대체됨」으로 남긴다. 잘못된 지식이 활성 컨텍스트에 그대로 남게 두지 않는다.

## 주문에 싣는 요약

<!-- order-summary:begin -->
- 시간에 따라 바뀔 수 있고 열린 결정에 닿는 사실은 확신과 무관하게 조사한다. 예시 목록에 한정하지 않는다.
- 공식 문서와 1차 자료를 먼저 찾는다. 2차 자료는 2차로 표시한다.
- 기술 주장은 이 레포가 쓰는 판과 최신 upstream 판을 따로 보고한다. 레포 판은 추측하지 말고 레포에서 읽는다.
- 최신과 안정이 갈리면 둘 다 보고하고 고르지 않는다. 고르는 것은 사용자다.
- 확인하지 못한 것은 단정하지 말고 `certainty: uncertain` 으로 낸다.
- 각 주장에 확인한 날과 출처 종류(1차 · 2차)를 가능하면 붙인다.
- 검색 횟수 · 출처 수 상한은 없다. 필요한 만큼 조사한다.
- 사용자 발화와 어긋나는 사실을 찾으면 출처와 함께 그대로 보고한다. 사용자 판단 · 선호는 교정 대상이 아니다.
