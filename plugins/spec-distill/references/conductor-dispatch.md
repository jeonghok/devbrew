# 지휘 — 하위 agent 에게 보내는 글

지휘 순환(같은 폴더 `conducting.md`)이 계획 · 구현 · 다시 보는 리뷰를 하위 agent 에게 보낼 때 쓰는 틀이다. 하위가 구현하는 쪽이든 리뷰하는 쪽이든 같다. `<SD>` 는 spec-distill 플러그인 폴더의 절대경로다.

## 늘 싣는 것

1. **자리.** 그 에픽 브랜치와 일할 worktree(지휘 순환 걸음 3 의 「하위 agent 의 자리」). 기본은 `isolation: "worktree"` 로 띄운 agent 가 자기 worktree 에서 `git switch --ignore-other-worktrees <에픽 브랜치>` 로 그 브랜치에 서는 것이고(지휘자는 보내기 전에 에픽 worktree 가 그 브랜치를 놓게 한다), 앞 agent 의 작업 기록(실행 방식의 작업 폴더)이 있으면 그 백업 경로를 함께 주어 되살리게 한다. 다른 길(지휘 세션이 그 에픽 worktree 에 머문 채 격리 없이 보낼 때)은 그 에픽 worktree 의 절대경로를 준다. 자기 worktree 밖의 git 은 조작하지 않는다. 격리된 자리의 셸은 복합 명령을 막으니 스크립트 파일로 돌리고, 공유 체크아웃 쪽 파일은 임시 파일에 쓴 뒤 `cp` 로 옮긴다.
2. **흐름.** 고른 흐름과 그 이유 한 줄(기본은 설계 흐름), 조사 · 결정 흐름이면 산출물 경로.
3. **같은 skill 그대로.** 이 흐름의 skill 을 단일 세션과 똑같이, 단계를 빼거나 다시 쓰지 말고 끝까지 돈다. skill 안의 테스트 실행도 그대로 둔다.
4. **미리 받은 답.** 아래 `## 사람 자리` 의 미리 받은 답 가운데 이 일에 닿는 것.
5. **임시 폴더.** `TMPDIR` 를 이 agent 몫 폴더(지휘자가 `python3 "<SD>"/scripts/conductor_ledger.py resource-dir --roadmap <로드맵> --kind tmp --name <agent 이름>` 으로 만들어 `## 자원` 에 적은 것)로 준다. 하위는 자기 폴더만 쓰고 지운다.
6. **금지.** 공유 임시 폴더의 glob 삭제(자기 하위 폴더만 지운다) · `git stash` · 다른 worktree 의 git 조작. 그리고 HEAD 를 뒤로 옮기지 않는다(reset · rebase · force 없음) — 커밋은 pathspec 으로 한다. 같은 worktree 에서 일하면(다른 길) 지휘 세션이 그 설계문서를 고칠 수 있으니 그 파일을 되돌리지 않는다.
7. **트레일러.** 구현 커밋마다 `Spec: <설계문서 레포 상대경로>` — 품질 게이트의 의도 출처가 이것을 읽는다.
8. **마지막 보고.** 아래 `## 마지막 보고` 의 칸.
9. **스위트 잠금.** 전체 스위트(레포의 테스트 전부)는 공유 스위트 잠금 아래서만 돌린다 — 지휘자의 스위트 대조(`merge_check.py`)와 같은 잠금 하나다. 경로는 지휘자가 `python3 "<SD>"/scripts/conductor_ledger.py suite-lock --roadmap <로드맵>` 의 첫 줄로 얻어 싣는다(레포 전용 경로를 박지 않는다). 하위는 `python3 "<SD>"/scripts/suite_lock.py run --lock <스위트 잠금 경로> --owner <agent 이름> --wait <초> -- bash -c '<스위트 명령>'` 한 번으로 잡고 · 돌리고 · 푼다(셸 연산자가 잠금 밖으로 새지 않게 명령은 `bash -c` 하나로 감싼다). 하위가 띄우는 하위 agent(실행 방식의 과제 구현 · 리뷰)에게 보내는 글에도 이 잠금 줄과 경로를 그대로 싣는다. 잠금이 잡혀 있으면 기다리는 것은 멈춤이 아니라 줄이다 — 기다림 끝에도 못 잡으면(종료 코드 75) 그 줄의 주인 · 잡은 시각을 보고한다. 과제 안의 좁은 테스트는 잠금 없이 돌린다.
10. **처분.** 지휘자 자신의 몫이다 — 보내는 자리(지휘자의 dispatch)마다 아래 줄을 단다. 하위에게 보내는 글에는 넣지 않는다.

**처분** — consumer=orchestrator · fail-closed · disclosure=하위가 돌려보낸 사람 자리 원문(쉬운 배경 뒤 늘 첨부) · 판정 목록 · AC 보고를 빠짐없이 사용자에게 보인다

## 사람 자리

미리 받은 답이 있는 자리 — 하위는 그 답을 그대로 쓰고, 쓴 자리와 답을 보고에 적는다.
- 머지 메뉴(`superpowers:finishing-a-development-branch`) — 「브랜치 그대로 두기」(3번). Push 와 PR 은 지휘자가 구현 대조 뒤에 한다.
- finishing 이 묻는 기준 브랜치 — 보내는 글에 적은 브랜치.
- 실행 방식 — writing-plans 가 권한 방식. 구현 agent 를 보낼 때만 이 답을 싣는다. 계획 agent 에게는 싣지 않는다 — writing-plans 끝의 계획 검토 · 실행 방식 질문은 지휘자가 「설계에 없던 결정」 을 가르는 자리라서 돌려보내야 한다. 사용자가 다른 방식을 말하면 그 말을 따른다.

그 밖의 자리(미리 받은 답이 없는 것, 그리고 writing-plans 끝의 질문처럼 지휘자가 가를 자리)에서 하위는 멈추고 두 부분을 함께 돌려보낸다.
- (a) 사람에게 보일 쉬운 요약 — 무엇을 정하나 · 고르면 무엇이 달라지나(그대로 두면 · 고치면) · 배경. 내부 기호는 괄호에만.
- (b) skill 이 낸 문면 원문 — 앞 글 · 경고 · 질문 · 선택지.

지휘자는 배경을 먼저 쉬운 말로 쓰고 질문만 봐도 결정할 수 있게 묻는다(지휘자 skill 의 쉬운 말 규칙 블록). 선택지는 (b) 의 수 · 순서 · 라벨 · 「(권장)」 를 글자 그대로 두고, 각 선택지 설명에 원문의 「고르면 무엇이 달라지나」 를 빠뜨리지 않는다. 지휘자 의견은 선택지 밖 「지휘자 의견:」 한 줄로만 쓴다. 원문은 늘 붙인다. 사용자 답은 글자 그대로 같은 agent 에 돌려준다. 선택지로 받을 수 없는 답(사용자가 직접 써야 하는 것)은 게이트 밖에서 따로 묻고 그 사실과 이유를 적는다. 옮길 때마다 받은 원문 · 실제로 띄운 질문 · 사용자 답 · 돌려보낸 글을 `python3 "<SD>"/scripts/conductor_ledger.py resource-dir --roadmap <로드맵> --kind relay --name <에픽>` 폴더의 파일(`relay-<번호>.md`)에 남기고, 에픽이 끝나면 쓰기 권한 없는 agent 가 둘의 선택지 수 · 라벨 · 순서를 대조한다(옮김 대조 agent `relay-checker` — 지휘자 skill 의 dispatch 자리). 그대로 전할 수 없는 자리는 그 자리만 지휘자가 직접 돌리는 길로 되돌리고 이유를 그 에픽 설계문서 `## 지휘 기록` 에 적는다 — 사용자가 결정하지 못하게 되는 것이 가장 큰 실패다.

## 단계마다 새 agent

- 계획 agent 는 writing-plans 로 계획을 쓰고 커밋한 뒤 대조를 돌리고, writing-plans 끝의 질문에서 두 부분을 돌려보내고 멈춘다.
- 구현 agent 는 새로 보낸다 — 계획 agent 를 이어 쓰지 않는다(한 agent 가 리뷰~계획을 이으면 맥락이 백만 토큰 가까이 커진다). 입력은 커밋된 계획 경로 · 설계문서 경로 · 미리 받은 답(실행 방식 포함) · 기준 브랜치뿐이다.
- 하위가 돌린 리뷰를 다시 돌거나 좁은 재리뷰를 할 때는 같은 agent 를 이어 부른다(`SendMessage`). 그 agent 가 없으면 리뷰 엔진의 문서별 상태 경로를 넘겨 라운드 수와 재리뷰 상한이 처음부터 다시 세어지지 않게 한다.
- writing-plans 끝의 실행 방식 답은 계획 agent 에 돌려주지 않고 새 구현 agent 의 미리 받은 답으로 싣는다. 계획 검토에서 고치라는 답은 계획 agent 에 「계획만 고치고 커밋한 뒤 다시 멈춘다 — 실행 skill 로 넘어가지 않는다」 와 함께 돌려준다.

## 마지막 보고

하위의 마지막 메시지는 아래를 모두 싣는다 — 실행 방식이 작업 폴더를 지울 수 있어 경로만으로는 부족하다.
- 판정 전체 — 실행 방식의 마지막 목록 그대로(줄마다 `Ruling:`).
- AC 보고 내용 전체 — AC 마다 `AC<번호>: 구현됨 | 미룸 | 빠짐 — 근거`.
- 쓴 미리 받은 답과 그 자리 · 커밋 목록(해시와 한 줄) · 브랜치 · 남긴 파일.
- 하위가 본 테스트 실패와 그 이름. 진짜 실패인지는 지휘자의 잠긴 스위트 대조(`merge_check.py`)만 판정한다 — 그 대조에서 사라지는 실패는 경합으로 보고 알린다.

