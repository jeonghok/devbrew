### 4. 돌아오기
- 기본값: 백그라운드 agent 가 끝나면 알림이 온다 — 걸음 1 로 가서 맞추기 순서(① agent 목록 → ② 상태 계산 → ③ 돌고 있는 수 대 권장 수 → ④ 채우기 → ⑤ 기준 시각 붙여 보고)대로 다시 세고 작업 목록을 갱신한다. 실행 방식은 writing-plans 가 권하는 방식이고, 계획 검토는 계획에 설계에 없던 결정이 있을 때만 기다린다.
- 판단: 계획 agent 가 돌아오면 이 세션이 계획을 읽고 「설계에 없던 결정(범위 · 인터페이스 · 파일 배치 등)」 이 있는지 가른다 — 계획을 쓴 agent 가 스스로 가르지 않는다. 없으면 계획 경로만 보이고 걸음 3 의 「차례로」 확인 뒤 새 구현 agent 를 보낸다(writing-plans 가 권한 실행 방식을 미리 받은 답으로). 있으면 그 결정들을 배경과 함께 사용자에게 묻고(걸음 2), 답 전에는 그 에픽의 구현을 보내지 않는다. 권하는 쪽이 있으면 첫 자리로 옮기고 라벨 끝에 「(권장)」을 단다. 구현 중에는 맞추기마다 실행 방식 원장(SDD 면 그 worktree 작업 폴더의 `progress.md`)의 `Ruling:` 줄을 읽어 화면의 판정 줄에 올린다. 판정이 승인된 설계의 수용 기준 · 의도를 바꾸거나 구현이 막히면(SDD 의 BLOCKED 포함) 그 에픽만 멈추고 배경과 함께 묻는다(권하는 쪽이 있으면 첫 자리로 옮기고 라벨 끝에 「(권장)」을 단다) — 다른 에픽은 계속한다. 설계 안의 판정은 멈추지 않고 끝에 목록 전체를 보인다. 같은 자리(한 메커니즘의 보안 리뷰 등)가 라운드마다 새 막는 지적을 내면 라운드를 더하지 않고 설계의 대안 갈래로 일찍 옮긴다 — 설계 의도가 바뀌면 사용자에게 묻는다(권하는 쪽이 있으면 첫 자리로 옮기고 라벨 끝에 「(권장)」을 단다). 계획 중간에 돌아온 구현 agent 를 새 agent 로 바꿀 때는 먼저 옛 agent 가 띄워 아직 도는 하위 agent 를 하니스의 작업 멈추기(`TaskStop`)로 내린다 — 같은 브랜치에 두 writer 가 커밋하지 않게. agent 를 보내거나 거둘 때마다 상태 계산의 동시 가능 목록과 승인된 설계의 남은 계획을 훑어, 의존 · 같은 파일 겹침 · 기다리는 답이 없는 일은 규모를 알리고 바로 보낸다 — 동시에 돌리는 큰 작업의 권장 수는 기본 3(레포 설정 파일이나 로드맵 머리말의 `parallel_default` 로 바꾼다)이고 상한이 아니다(사용자가 늘린다). 구현 담당자를 보낼 때는 먼저 걸음 3 의 「차례로」 확인을 한다.
  - 구현 agent 가 돌아오면 보고에서 판정 전체와 AC 보고 내용 전체를 거둔다(작업 폴더는 지워질 수 있어 경로에 기대지 않는다): 보고를 `ledger resource-dir --roadmap <로드맵> --kind report --name <에픽>` 폴더의 파일로 두고 → `ledger rulings --report <보고 파일> --ledger <원장 사본> --out <판정 파일>`(보고에도 원장에도 판정이 없으면 「판정 줄 — 셀 수 없음」 을 보인다) → 구현 담당자가 처음 돌아온 때(머지 앞 리뷰를 보내기 전)에만 에픽 브랜치에 기본 브랜치를 merge 해 받는 곳 규칙이 최신 로드맵을 보게 한다 — 되돌리기를 고치고 돌아온 때에는 합치지 않는다(머지 앞 리뷰를 보낸 뒤 그 PR 의 되돌리기가 끝날 때까지 그 브랜치에는 기본 브랜치를 합치지 않는다 — `qg-review.md` 의 `## 되돌리기`) → `python3 "<SD>"/scripts/check_bundle_coverage.py --impl <설계문서> <AC 보고 파일>`(계획을 나눴으면 `--acs`)의 경고를 사용자에게 보인다 → `ledger write-sections --spec <설계문서> --plan <계획> --rulings <판정 파일> --impl-line "<대조 첫 줄>" --counts "<AC n개 중 …>"` → 에픽 worktree 에서 커밋 · push → `gh pr create -R "$(python3 "<SD>"/scripts/gh_repo.py slug)"` 로 PR 을 열고 그 출력의 마지막 줄(PR URL)로 `ledger pr-record --roadmap <로드맵> --session <세션> --epic <에픽> --pr <그 URL>` 을 부른 뒤 `ledger pr-refresh --roadmap <로드맵> --session <세션> --epic <에픽>` 으로 PR 캐시를 채운다. PR 이 이미 있어 `gh pr create` 가 실패하면 그 PR 의 번호를 `--pr <번호>`(숫자만)로 적고 그 판단과 이유를 보인다. `pr-record` 의 종료 코드 4 는 출력 줄 `PR #<번호> 이 에픽 <에픽> 와 맞지 않는다(…) — 아무것도 적지 않았다` 의 괄호 안 어긋난 칸이 `baseRefName` 하나뿐일 때만(앞 계획의 브랜치를 바탕으로 연 쌓인 PR) 예상된 결과이고 멈출 오류가 아니다 — 적지 않고 넘어가고 걸음 5 가 바탕을 바꾼 직후에 적는다. 그 밖의 0 아닌 종료 코드(다른 칸 — `headRefName` · `isCrossRepository` · `number` — 가 어긋났거나 PR URL 의 레포가 origin 이 아닌 4, 번호를 읽지 못한 2, 기계 상태 · gh · origin · 기본 브랜치를 확인하지 못한 3, 표지를 쥐지 않은 5)는 그 줄의 사유를 그대로 보이고 이 에픽의 번호 적기를 멈춘다 — `pr-refresh` 는 그대로 부른다.
  - 세션 담당자 거두기: 끝의 근거는 결과 파일과 세션 상태다 — 「끝」 알림은 알림일 뿐이다. 띄운 직후의 기다리기(`hc wait`)는 첫 턴이 시작되기 전에 `idle` 로 돌아올 수 있으니 끝으로 읽지 않는다. 거두는 순서는 결과 파일을 읽는다 → 지금 걸음 4 의 처리(판정 · 수용 기준 보고 거두기)를 그 파일로 한다 → 사용자 말 파일을 읽고 아직 옮기지 않은 글을 결정 줄로 옮긴다 → 세션을 닫는다(`hc kill` → `hc rm`) → 표에서 그 줄을 뺀다 → 내가 띄운 살아 있는 터미널 가운데 표에 없는 것이 0 인지 본다(`hc ls` 에서 `parent` 가 내 주소인 것). 남의 세션은 건드리지 않는다 — `parent` 가 내 주소인 것만 닫는다. 세션을 닫은 뒤 `hc ls` 에 그 담당자가 부모인 터미널이 남았으면 사용자에게 알린다. 기다릴 때는 끊어서 기다리고 세션 길에서는 `hc wait --children any --timeout <초>` 를 쓴다 — 돌아올 때마다(글이 왔다 · 상태가 바뀌었다 · 시간이 다 됐다) 내 자식의 상태와 결과 파일 · 물음 파일 · 사용자 말 파일을 본 뒤 다시 기다린다. 질문 창에서 사용자 답을 받은 직후에도 한 번 본다 — 그동안 온 글은 닿지 않았을 수 있다. 얼마마다 볼지는 리더가 정한다.
  - 세션 담당자의 물음과 사용자 말: 물음 파일을 읽고 `conductor-dispatch.md` 의 `## 사람 자리` 대로 사용자에게 묻는다 — 옮김 기록의 「받은 원문」 은 담당자가 쓴 그 파일의 글 그대로다. 기다리는 질문 줄은 리더가 사용자에게 묻기 직전에 올린다 — 담당자 세션이 올리는 길은 없다. 사용자가 담당자 세션에서 직접 한 말은 담당자가 사용자 말 파일에 원문으로 알린다 — 리더는 그 원문을 그 일의 기록 자리에 결정 줄로 옮기고(team 형식은 과제 파일의 결정 기록에 `결정` 줄로, 옛 형식은 설계문서 `## 결정 기록` 의 지금 갈래대로) 줄에 「담당자 세션에서 들음 · <세션 이름>」 을 붙인다. 승인 줄로는 적지 않는다. 그 말이 설계의 글자 · 수용 기준 · 보이는 동작을 바꾸면 설계문서의 그 글자를 고쳐 반영하고(담당자가 도는 중이면 리더가 고칠 글을 써 보내 담당자가 반영하고, 멈췄거나 끝났으면 리더가 고친다) 승인은 리더 세션에서 다시 받는다. 답과 방향 고침 · 받은 고침 확인 · 「중간」 알림은 `conductor-dispatch.md` 의 `### 리더 쪽` 을 따른다.
  - 멈춘 담당자: 담당자가 권한 물음이나 질문 창에 멈추면 세션 상태에서 무엇을 묻는지 읽을 수 있다. 리더는 담당자의 질문 창 · 권한 창에 답하지 않고 어느 세션이 무엇을 묻고 있는지 사용자에게 알린다. 키를 대신 넣지 않고 억지로 글을 보내지도 않는다 — 사용자가 그 세션에 붙어 답하거나 닫으라고 한다. 권한 물음으로 거듭 멈추면 사용자에게 알리고 그 일을 하위 agent 길로 돌릴지 묻는다. 「거듭」 의 수는 박지 않고 리더가 판단하며 띄우는 명령에 리더의 권한 방식을 넘기지 않는다.
  - 막힘 되풀이: 같은 걸음에서 담당자가 두 번 이어 막히면 세 번째로 보내지 않고 사용자에게 간다. 스크립트는 세지 않는다.
- team 형식 로드맵이면 아래 `## team 형식 로드맵` 절을 따른다 — 걸음표와 이 절의 문장이 다르면 걸음표를 따른다.
- 부를 skill: writing-plans 가 권한 실행 방식(`superpowers:subagent-driven-development` · `superpowers:executing-plans`) — 구현 agent 안에서.
- 기록: 「설계에 없던 결정」 을 가른 결과와 이유 → 설계문서 `## 지휘 기록` · 판정 보관본(`## 판정` 아래 `### <계획>`) · `## 구현 대조 — <계획>` → 설계문서. 리뷰가 열려 있는 문서의 `## 결정 기록` 에 손으로 쓴 줄은 다음 리뷰에서 「허가 없이 바뀜」 으로 돌아온다. 사용자 결정 원문을 설계문서 `## 결정 기록` 에 남겨야 하면 갈래가 셋이다 — ① 그 문서의 리뷰가 열려 있으면 그 리뷰의 결정 줄 펜스(`decision-line` — 엔진 `log-decision`)로 쓴다 ② 리뷰 원장이 없으면(리뷰 전) 손으로 쓴다 — 첫 라운드가 기준선으로 받는다 ③ 리뷰가 닫혔으면 `## 결정 기록` 절 끝(마지막 계수 줄 아래)에 손으로 쓴다 — 다음 재리뷰가 그 줄을 기록으로 읽는다(재리뷰를 시작한 뒤에 쓴 줄은 다시 묻는다). 끝맺음을 건너뛰어 계수 줄이 없거나 계수 줄에 표지가 없는 옛 원장이면 재리뷰가 그 줄을 한 번 묻는다 — 「고친 대로 둠」으로 닫는다. 하위가 그 브랜치에서 일하는 중이면 바로 쓰지 않고 `ledger add --section "쌓인 기록"` 으로 쌓았다가 돌아온 뒤 `ledger flush` 로 한 번에 옮겨 커밋한다 — 같은 worktree 에 두 writer 를 두지 않는다.
- 기계 상태: `## 실행 원장`(에픽 · 계획 · 원장 경로 · 읽은 줄) · `## PR` · `## 에픽 PR`(적은 번호) · `## 살아 있는 agent`(구현 agent) · `## 작업` · `## 쌓인 기록`.
