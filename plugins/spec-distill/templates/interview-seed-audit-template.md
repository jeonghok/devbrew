# <Topic> — Intent Seed Audit

> 순수 텔레메트리 — 다음 세션의 첫 턴 `/spec-distill:context-build @<seed 경로>` 가 가리키는 것은 payload(seed)
> 파일이고, 여기에는 확산·압축이 어떻게 진행됐는지의 과정 기록만 남는다. payload 의 `audit_file`
> 이 이 파일을 가리킨다.

## 1. 원문

(사용자가 준 글 — 요청 · 생각 · 대화 로그 · 자료를 받은 글자 그대로 옮긴다. 질문 라운드에서 직접 적은 답도
 줄 나눔을 접지 않은 글자 그대로 이 절 끝에 덧붙인다(고른 라벨만 있는 답은 덧붙이지 않는다).
 **append-only**: 이후 라운드에서 나온 글도 요약하지 않고 여기에 계속 덧붙인다 — 지금 요약하면 압축이 무엇을 떨어뜨렸는지 이 절이 못 남긴다.
 허용 변환은 둘이다 — token · key · credential 로 보이는 값은 쓰기 전에 가림 표시(`<REDACTED>` · `<REDACTED:라벨>` 등 — 라벨은 공백 없이 글자 · 숫자 · `.` · `_` · `-` 로 64자까지)로 바꾸고,
 절 제목과 같은 줄이나 `### ` 로 시작하는 줄은 사용자가 고르면 그 줄 앞에 `> ` 만 붙인다.
 저자가 쓸 수 있는 줄은 받은 글마다 그 바로 앞에 두는 구분 줄 하나뿐이다 — `### 받은 글 — <갈래> · <준 이> · <날짜>[ · 라운드 <n> 의 답]`
 (갈래는 직접 친 글 · 붙여 넣은 글 · 다른 세션이 넘긴 글).
 구분 줄과 받은 글 사이에는 빈 줄 하나를 둔다 — 붙여 쓰면 받은 글의 첫 문장이 구분 줄과 한 문단이 되어 사용자의 원문으로 세지지 않는다.
 설명 문장을 따로 두지 않는다. 그 밖의 줄은 전부 받은 글자 그대로다.
 `### ` 로 시작하는 줄은 저자가 쓴 구분 줄이라 읽되 사용자의 말이 아니다.)

## 2. 질문 전체

(라운드마다 블록 하나 — 답하지 않은 질문도 남긴다. **«당신이 답한 것» 줄과 «사용자가 적은 말» 칸만 사용자의 말이다** —
 질문 문구 · 선택지 · 내가 읽은 것은 저자가 쓴 것이다. 리뷰는 이 구분으로 정답을 가른다.
 «기타» 로 적은 말이나 「아니다」 뒤에 덧붙인 말이 있으면 그 풀이 줄 끝에 ` — 사용자가 적은 말: 「…」` 를 붙인다 — 이 칸도 사용자의 말이다.
 두 칸의 값은 `seed_review_log.py one-line` 을 통과시켜 **한 줄로** 적는다 — 여러 줄 답이 풀이 줄 모양의 줄을 만들지 못하게 한다.
 «당신이 답한 것» 줄의 괄호 표시는 출처다 — `(라벨)` 은 선택지 라벨을 골랐다, `(적음)` 은 직접 적었다, `(라벨 · 적음)` 은 둘 다이고 고른 라벨을 앞에 적는다. 「라벨」 이 붙은 답은 사용자가 고른 모델 문장이다. 풀이 줄의 「고름」 · 「고르지 않음」(풀이를 확인했는가)과 다른 축이고, 추가 라운드 승인의 `label` · `typed` 와 같은 뜻이다.)

  - 선택지: <선택지 라벨을 « / » 로 잇는다 — 자유 입력만 받았으면 «자유 입력»>
  - 당신이 답한 것 (<라벨 | 적음 | 라벨 · 적음>): <고른 라벨 또는 적은 말 — one-line 을 거친 그대로, 답이 없으면 표시 없이 «(답 없음)»>
- 확인 질문: <어느 라운드의 풀이인지>
