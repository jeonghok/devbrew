## 컷오버 사이 계약

아래 이름과 형식은 다섯 plan 이 같은 글자로 쓴다. 바꾸려면 이 색인을 먼저 고치고 영향받는 plan 을 함께 고친다.

경로는 `.claude/quality-gates/<sid>/` 다. `<sid>` 는 `[A-Za-z0-9_-]{8,}` 를 `fullmatch` 로 통과해야 한다(E1 · V11).

### K-3 판정 줄 (② 가 만들고 ③ 이 게시하고 ④ 가 칸을 더한다)

판정 줄은 모델이 옮겨 적지 않는다(R24). `verdict.py` 가 렌더한다 — 판정 어휘가 사는 파일이 그 문자열도 만든다(V1).

- ② 형식: `qg: <verdict>[ (<reason>)] · 막는 지적 <N> · 선택 <M> · 차등 새 실패 <K> · 제외 패치 <X> · iter <I> · <short sha>`
- ④ 는 `차등 새 실패 <K>` 뒤에 ` · e2e <상태>` 를 끼운다. `<상태>` 는
  `pass` · `fail` · `미확인` · `안 함` · `걸을 것 없음` · `걸을 도구 없음` · `꺼짐(kill switch)` 중 하나이고, 사람이 뒤집었으면
  뒤에 ` (사람이 뒤집음)` 이 붙는다.
- `verdict.py` CLI 는 기존 플래그를 그대로 두고 판정 줄 플래그를 더한다:
  `--line --blocking N --optional M --new-failures K --excluded X --iter I --sha SHA` (④ 가 `--e2e STATE` 를 더한다).
  `--line` 이 있으면 기존 `verdict:` · `reason:` · `reasons:` 줄 뒤에 판정 줄 한 줄을 더 낸다. 합성기처럼 `verdict` 를
  import 하는 소비자는 같은 렌더 함수를 직접 부른다.
- 판정 줄의 숫자는 셸이 기계 출력에서 뽑는다 — 막는 지적·선택은 합성기 출력(`$RV/synth.out`)의 `blocking:` ·
  `optional:`, 차등 새 실패는 차등 집계 출력(⑤ 뒤에는 그 `new_failures:` 줄), 제외 패치는 `excluded.md` 의 항목 수다.
  펜스에 `<N>` 같은 자리표시를 두고 모델이 숫자를 채우게 하지 않는다(R24). iteration 번호와 `<session-id>` 만 오케스트레이터가 채운다.
- 우선순위(`defect > not-certified > clean`)를 합치는 일은 언제나 `verdict.py` 안에서 한다. ④ 가 e2e 결과를 최종 판정에
  더할 때도 오케스트레이터가 머릿속으로 합치지 않고 `verdict.py` 를 다시 부른다.

### K-4 합성기 출력 (②)

`synthesize_findings.py` 는 원장 요약에 `blocking: <N>`(살아남은 CRITICAL·IMPORTANT 수) · `optional: <M>`(SUGGESTION 수)를
내고, 판정 입력 `defect` 는 `blocking >= 1` 이다. confidence 필드·억제 수는 출력에서 사라진다.

### K-5 `discover-spec.sh` (② 가 새로 쓰고 ⑤ 가 줄인다)

- 호출: `discover-spec.sh --intent-out <file> [--base <sha>]` (리포 루트에서). 의도 본문을 `<file>` 에 쓴다.
- stdout 한 줄 JSON 키: `spec_path` · `intent_source` · `intent_note` · `intent_file`.
  - `intent_source`: `spec-trailer` · `commits+pr` · `commits` 중 하나.
  - `intent_note`: 빈 값이거나 `gh 없음` · `열린 PR 없음` · `gh 오류` 중 하나. 미인증은 `gh pr view` 의 실패에서
    종료 코드 말고는 가를 근거가 없어 `gh 오류` 로 접는다(gh 2.88.1 실측, plan ② Task 2).
  - `spec_path` 는 ②~④ 동안만 낸다(`spec-trailer` 면 그 경로, 아니면 빈 값). ⑤ 가 이 키를 지운다.
- 파일 mtime 을 읽지 않는다(AC9). gh 는 읽기 전용 `gh pr view` 하나만 부른다(AC15).
- 오케스트레이터는 매 실행 `intent: <intent_source>[ (<intent_note>)] — <출처 요약>` 한 줄을 정확히 한 번 낸다.

### K-6 게시 sink `publish-comment.sh` (③)

- 호출: `publish-comment.sh --body-file <file> [--base <sha>]`. 오케스트레이터는 본문을
  `.claude/quality-gates/<sid>/comment.md` 에 쓴다.
- 마지막 stdout 줄: `posted: <url>` 또는 `skipped: <사유>`. 사유 리터럴은 `no-pr` · `pr-closed` · `kill-switch` ·
  `scan-failed` · `gh-unavailable` · `too-long` 여섯이다. 둘 다 exit 0, 잘못된 호출은 exit 2.
- aborted 실행은 sink 를 부르지 않고 오케스트레이터가 `skipped: aborted` 한 줄을 직접 낸다.
- gh 가 코멘트를 만들고도 URL 을 내지 않으면 `posted: unknown` 이다. `gh pr view` 가 「PR 없음」 밖의 이유로 실패하거나
  코멘트 쓰기가 실패하면 `skipped: gh-unavailable` 이다(사유 리터럴은 여섯 그대로).
- sink 의 kill switch 는 `DEVBREW_QUALITY_GATES_DISABLE_PUBLISH=1` 과 전역 `DEVBREW_QUALITY_GATES_DISABLE=1` 둘 다다(값 `1` 전체 일치).

### K-7 e2e (④)

- `e2e-state.sh` 하위명령은 다섯이다: `fingerprint --out <file>` · `compare <before> <after>` · `boot`(승인된 명령을
  백그라운드로 띄우고 준비 신호를 기다림) · `stop`(띄운 프로세스 그룹을 내림) · `propose`(증거표에서 판정안을 정함).
  부팅 상한은 `DEVBREW_QUALITY_GATES_E2E_BOOT_TIMEOUT`(기본 90초)이다.
  `compare` 는 바뀐 경로를 `changed: <path>` 줄로 내고 마지막 줄에 `same` 또는 `changed: <N>` 을 낸다.
- 리뷰 대상 코드에 닿는 하위명령(`fingerprint` · `compare` · `boot`)은 `DEVBREW_QUALITY_GATES_DISABLE_E2E=1` ·
  `DEVBREW_QUALITY_GATES_DISABLE_DIFFERENTIAL_TEST=1` · 전역 `DEVBREW_QUALITY_GATES_DISABLE=1` 중 하나라도 켜져 있으면
  측정·실행 전에 비0(exit 3)으로 끝나고 stderr 에 사유 한 줄을 낸다(X5 · AC20). `stop` 은 스위치와 무관하게 돈다(X4).
- 최종 판정은 `verdict.py --prior <마지막 iteration 의 합성기 출력> --e2e <상태> --line …` 한 번이다. `--prior` 파일은
  ② 의 `$RV/synth.out` 이고, 판정 줄 숫자는 K-3 대로 셸이 뽑는다.
- `verdict.py` `REASONS` 맨 뒤에 `e2e-unconfirmed` 를 더한다. e2e 결과는 `--e2e STATE` 한 플래그가 판정 입력과 판정 줄 칸을
  함께 정한다 — `fail` 은 defect, `미확인` 은 `e2e-unconfirmed`, 나머지는 판정을 바꾸지 않는다. `--prior` 는 `--defect` ·
  `--reason` · `--differential` 과 함께 쓸 수 없다(exit 2, 앞 판정의 이중 주입 방지).

### K-8 파이프라인 SKILL.md 절 뼈대 (② 가 정하고 ③④ 가 절을 끼운다)

## 실행 전에 사용자가 정할 것
