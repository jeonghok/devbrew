# Framing 의도 이탈 — Interview Brief

> 이 brief는 단독 완결 산출물이다. superpowers가 있으면 §7대로 brainstorming 해답공간으로
> 넘어가고, 없으면 이 brief 자체가 다음 단계의 입력이다. 텔레메트리는 `audit_file`에 있다.

## 0. 한눈에

- **무엇** — spec-distill Phase 0(`/request-framing` command · `framing-requests` skill)이 만드는 interview-seed 가 사용자 의도에서 벗어나는 문제를 고친다.
- **왜** — 사용자는 과하다고 느낀 자리로 «초안 뒤 검증·게이트»를 골랐고, 문제를 «과함보다 의도와 seed 의 불일치»로 다시 불렀다(C2). 사용자가 짚은 누수 지점은 셋이다 — 사용자 없이 도는 리뷰→수정, 짧은 답이 에이전트 말로 굳는 것, 에이전트 추론이 seed 에 실리는 것(C3). 사용자는 문제 재구성에 동의했으나(audit §6 S5) 그 재구성 문구 자체는 원문에 기록되지 않았다. 9/5 의 대표 오독은 저자 단독 반영이 아니라 게이트에 공시된 뒤 사용자가 승인한 경로로 샜고(C9), 그보다 앞선 형성 도중의 공시도 응답 없이 지나갔다(C11).
- **방향 (ST1 보완 C7, PR 5 위에서 C13)** — 이 brief 는 docreview 재설계 PR 5(seed 자리를 공유 리뷰 엔진으로) 위에서 설계한다(C13). 리뷰어의 탐지 역할은 남기고 지적의 처분은 사용자 앞으로 옮긴다 — 저자가 지적을 혼자 반영하는 경로(게이트 전 선반영과 게이트 ③ 뒤의 반영 둘 다)를 닫고(C10), 9/5 식 공시와는 달라야 한다(C9). 새 단계를 둘지는 설계가 부담 제약 안에서 정한다(C10 · C12). 헤딩 없는 seed 에서는 엔진의 얼림 검사가 꺼지므로, 저자 단독 반영을 막는 수단은 설계가 정한다(C13). 엔진이 drop · reject 한 지적은 개수 공시로 충분하다(C15). 짧은 답은 원문과 질문 문구를 함께 싣고, 풀어 쓴 문장만 확인받는다. 에이전트 추론은 «다시 검증할 것 —» 문단으로만 보낸다. 원 설계 §2.4 에 있었으나 구현에서 빠진 «사용자 편집» 단계를 게이트 앞에 되살린다. 묶음 질문은 유지한다. 저자 자기보고 블록이 저자가 옳다고 믿은 오독을 실을 수 없다는 점을 설계 입력으로 삼는다(C11).
- **제약** — 초안 뒤 검증·게이트는 사용자가 과하다고 고른 자리라, 되살리는 사용자 편집과 처분이 그 자리의 부담을 늘리는지를 설계가 따진다(C12).
- **경계** — Phase 0 은 맡길 일을 사용자 말로 확정하는 자리이고, 조사·반론·원인 후보는 Phase 1 의 몫이다(C6).
- **열린 것** — 현행 판본에서의 재현 여부(C14, 설계의 첫 확인) · 헤딩 없는 seed 에서 저자 단독 반영을 막는 수단(C13) · 개선을 무엇으로 재나(불일치는 하류에서만 보였다, C8) · 사용자 편집 단계의 모양 · 처분 피로 · 풀이 확인 시점 · Phase 1 의 seed 출처 규약 · 추론이 머리말을 달고 남는 통로 · 짧은 왕복으로 함께 쓰기(§1 — 기각하지 않았다)(§3).
- **다음** — superpowers:brainstorming 으로 해답공간 설계. 설계 대상은 PR 5 의 seed 자리 배선과 그 위의 저자 단독 반영 차단 수단이다(C13). §7 의 «설계 대상은 framing-requests SKILL» 문장은 C13 이전의 서술이다.

## 1. Goal · Non-goal

- Goal: seed 가 사용자 의도와 맞는다. 사용자 원문(S2, audit §6): «과하다 보다, 내의도 보다 seed간 의도가 안맞음 내가 원하지 않는 방향으로 가는듯함» — 이 불일치가 사라진 상태.
- Non-goal:
  - 리뷰어의 탐지 역할(격리 critic · 다른 모델 계열 리뷰 · 냉독) 제거 — ST1 에서 기각. PR 5 가 `seed-critic` 파일을 엔진 탐지기로 바꾸는 것은 이와 부딪치지 않는다(audit §6 S23).
  - 질문 묶음을 한 번에 하나로 바꾸는 것 · 매 문장 확인 — ST1 에서 기각(풀어 쓴 문장만 확인한다, C7). 짧은 왕복으로 함께 쓰기는 기각하지 않았다 — ST1 에서 거부한 선택지는 그것과 리뷰어 제거가 한 묶음이었다(audit §6 S19).
  - Phase 0 과 Phase 1 병합 · Phase 0 을 짧은 요청 정리로 경량화 — C6.
  - 압축해서 새 세션으로 넘기는 인계 구조 변경 — C4.
  - Phase 0 에 웹 조사·원인 분석을 더하는 것 — C6.

- ☑ confirmed **C13** — 이 brief 는 docreview 재설계 PR 5(seed 자리를 공유 리뷰 엔진으로) 위에서 설계한다 — 헤딩 없는 seed 에서 저자 단독 반영을 어떻게 막을지(수단)는 설계가 정한다 ⟨S26⟩
- ☑ confirmed **C14** — 설계는 먼저 현행 판본(3.1.0)에서 이 누수가 재현되는지 확인한다 ⟨S18⟩

✎ C4 의 ①~④ 와 C7 의 다섯 항목은 사용자가 쓴 문장이 아니다. 각각 R3 질문과 ST1 게이트 선택지로 에이전트가 제시한 문구이고, 사용자는 그것을 보고 골랐다. 그 문구가 audit §6 S11 · S12 에 있다(S4 · S8 은 고른 사실만 담는다). C9 · C12 는 리뷰 라운드 1, C11 의 현재 문구와 C14 는 라운드 2, C10 · C13 의 현재 문구와 C15 는 라운드 3 에서 고른 결정의 선택지 문구다(S13 · S17 · S18 · S22 · S24~S26). C15 는 사용자가 에이전트의 추천(채택)과 반대로 고른 결정이다.

✎ C4 가 거부한 ④ 는 «번호 답 대신 사용자 자신의 말로 다시 확인받기»다. C7 의 사용자 편집 단계(원 설계 §2.4 — 사용자가 본문을 직접 고친다)는 번호 답을 없애는 처방이 아니라 게이트 앞에 되살리는 단계라 둘은 다른 것이다. 그 단계의 모양(필수인지 선택인지 포함)은 §3 OQ2 로 열려 있다.

✎ C5 는 두 해석이 실제 의도였다는 사실만 담는다. «그러니 확인 절차 자체는 작동했다»는 모델이 끌어낸 일반화이고, 그 확인도 형성 도중이 아니라 게이트에서 에이전트가 제시한 좁은 해석을 고른 것이었다(ST1 전제 비판 (1)). 확인 시점은 §3 OQ4 로 열려 있다. 풀어 쓴 문장을 확인받은 뒤 그 문장에 어떤 표시를 달지는 정하지 않았다 — 표시가 확인 표시 세탁(§5 위험 H1)의 통로가 될 수 있다.

## 3. Open Questions

- OQ0: 이 누수가 현행 판본(3.1.0)에서도 재현되는가 — 설계의 첫 확인 대상(C14). brief 의 사례는 전부 0.57.0 이전 판본으로 만든 9/5 seed 다.
- OQ1: 개선 여부를 무엇으로 재나. 불일치는 다음 단계로 넘어간 뒤에야 보였다(C8). 하류(인터뷰 · 설계)가 seed 의 어느 문장을 달리 읽었는지 되돌려 받는 자리가 필요한가, 필요하면 어떤 모양인가. 같은 세션에서 만든 게이트의 «맞다» 감각은 부풀려질 수 있다(§5 위험).
- OQ2: 되살리는 «사용자 편집» 단계의 모양. 사용자가 파일을 직접 여나, 대화로 고칠 곳을 말하나. 사용자가 편집한 문장은 누가 다시 검사하나 — 재리뷰를 하면 루프가 생기고, 안 하면 편집이 만든 결함이 남는다.
- OQ3: 리뷰 지적을 사용자 앞에서 처분할 때, 지적이 많으면(9/5 약 36건) 확인 피로와 형식적 승인을 어떻게 피하나.
- OQ4: 짧은 답의 풀이를 언제 확인받나 — 질문 라운드 직후(형성 도중)인가, 사용자 편집 단계(끝)인가.
- OQ5: Phase 1 이 seed 전문을 «사용자 출처»로 받는 규약(`plugins/spec-distill/skills/conducting-interview/references/seed-input.md:13-15`)을 이번 범위에서 고치나. 같은 파일 `:15-17` 이 status 는 provisional 로 두지만, «다시 검증할 것 —» 문단의 에이전트 문장까지 출처 라벨이 사용자가 된다.
- OQ6: 추론이 «Phase 0 관찰» 같은 머리말을 달고 seed 에 남는 통로를 어떻게 닫나 — 저자의 라벨 선택과 리뷰어의 접두 제안(`plugins/spec-distill/agents/seed-critic.md` 의 수정 제안 범위) 양쪽이 겨냥 대상이다.
