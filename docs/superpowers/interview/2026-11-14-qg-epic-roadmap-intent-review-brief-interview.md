# qg 에픽 · 로드맵 리뷰와 쓴소리 리뷰어 — Interview Brief

> 이 brief는 단독 완결 산출물이다. superpowers가 있으면
> §7 대로 다음 단계로 넘어가고, 없으면 이 brief 자체가 다음 단계의 입력이다. 텔레메트리는 `audit_file`에 있다.

## 0. 한눈에

- **무엇** — qg(quality-gates)가 에픽 단위 · 로드맵 단위 리뷰를 지원하고, 사용자가 고른 것 자체를 의심하는 「쓴소리 리뷰어」를 더한다. 쓴소리 리뷰어는 실제로 돌려 본 근거로 「이게 정말 의도가 맞냐」를 묻고, 그 질문은 qg 판정을 바꾸지 않는다.
- **왜** — 뿌리 문제는 사용자가 고른 것 자체를 의심할 자리가 없다는 것이다(S2). 사용자는 잘못 고른 것을 구현 뒤 써 보고, 로드맵을 끝내고, 한참 뒤 다른 일을 하다가도 알아챘다(S23). ✎ 인터뷰 단계엔 조건부 의심 장치(steelman · premortem)가 있으니 비어 있는 것은 구현 뒤 자리라는 것은 모델 추론이다. 지금 qg 리뷰어들은 의도 출처를 정답으로 놓고 어겼는지만 본다.
- **확정(잠정)** — 입구는 qg 하나이고, 통일은 지휘자가 늘 같은 qg 입구를 같은 입력으로 부르는 것이다 — 에픽 · 로드맵 이름 호출은 지휘자를 거치고 로드맵 없는 PR 하나는 qg 를 바로 부른다. 지휘자는 에픽 머지 뒤 · 로드맵 끝에 자동으로 부르고, 자동 호출은 두 박자(목록 · 규모 → 승인 → 걷기)다. 원문 · 묶음은 부르는 쪽이 넘기고, 직접 쓴 말과 고른 라벨은 갈라 보이며 라벨도 의심한다. 리뷰어는 먼저 의심 목록 없이 걷고, 그 뒤에 인터뷰가 남긴 의심을 반증할 가설로 대조한다. 동시에 도는 다른 세션 · 에픽 · 로드맵의 작업을 지금은 git(브랜치 · worktree · 열린 PR)으로 파악해 겹침 · 갈라짐을 짚고, 못 본 것은 「확인 못 함」으로 낸다. 모델의 걷기는 범위와 상관없이 qg 의 사람 승인 걷기다 — PR 범위는 가볍게, 에픽 · 로드맵은 넓게 걷고(PR 범위의 질문 기준은 OQ14), /verify 는 사람이 직접 불러 볼 자리로 짚는다. 모델이 먼저 걷고 사람이 써 볼 자리를 짚으며, 돌리기 전 사람 승인이 상한이고, 넓은 탐색은 시작 전에 규모를 공시한다. 근거 있을 때만 묻고 상한을 두며, 질문은 리뷰 끝에 한 번에 · 지휘자 자동 호출이면 docs 파일에 쌓아 게이트 사이에 묻는다. 답은 답마다 파일, 키는 질문이고 대상(에픽 · 로드맵은 끝 커밋, PR 은 리뷰한 트리의 해시)은 기록만 하며, 판단에 쓴 관찰이 달라졌을 때만 다시 묻는다. 「잘못 골랐다」는 지휘자를 거친 호출이면 머지 전엔 spec-distill 피벗 경로로 · 머지 뒤 · 로드맵 끝엔 새 일의 씨앗으로(✎ 머지 전후로 가른 것은 S31 · S15 를 맞춘 모델 추론), 로드맵 없는 PR 하나면 qg 가 docs 파일에 남기고 다음 할 일만 안내한다. 리뷰어 본체를 먼저 만들고 지휘자 경유 입구는 옆 세션(팀 구조 개편)의 지휘자 설계에 맞춰 붙인다.
- **열림** — 이름 풀이의 세부 · 두 갈래의 경계와 기존 비판 자리와의 겹침 · PR 범위의 질문 기준 · 걷기 자리 · 헤드리스 재측정 · 「한참 뒤」의 길.
- **다음** — 인터뷰 종료 단계의 분해 판단에서 에픽 셋으로 나뉘었다(R1 리뷰어 본체 → R2 넓은 걷기 · R3 지휘자 경유 입구). 그 판단과 승인은 이 brief 의 원문(S)이 아니라 인터뷰 상태 파일의 「## 분해안」 절과 로드맵 파일에 기록돼 있다. 로드맵과 에픽 묶음을 확정된 brief 로 다시 만든 뒤(S32) 지휘 절차로 진행한다.
