## 1. Goal · Non-goal

### 이 에픽의 Goal · Non-goal

- 의도: 에픽 · 로드맵 리뷰와 설계 단계에서 intent-critic 이 만들어진 것과 다른 팀의 계획을 읽어 사용자가 놓치거나 잘못 고른 것 · 팀 사이의 갈라짐 · 조율 안 된 중복을 짚는다
- 범위: 한다 에픽 · 로드맵 리뷰와 의도 문서가 바뀐 변경에서 조언자 부르기 · 읽은 인용을 근거로 받고 스크립트가 확인 · 다른 팀 읽기(팀 지도 · 진행 중인 의도 문서 · 파일 겹침) · 근거의 종류 보이기 / 안 한다 걷기 · 실행 · 새 입구 · 팀 사이 조율 자체

### 공통 목표

- Goal: qg 가 에픽 단위 · 로드맵 단위 리뷰를 지원한다 ⟨S1⟩
- Goal: 사용자가 고른 것 자체(큰 방향 · 기능 · 동작)를 의심해 「이게 정말 의도가 맞냐」고 묻는 쓴소리 리뷰어를 더한다 ⟨S1⟩
- Goal: 쓴소리의 근거는 실제로 돌려 본 것이다 — 모델이 먼저 걷고 사람이 직접 써 볼 자리를 짚는다 ⟨S5⟩
- Non-goal: 쓴소리 예시 목록을 닫힌 점검표로 굳히는 것 ⟨S1⟩
- Goal: devbrew 안 동작을 통일해 갈라지지 않게 — 지휘자는 늘 같은 qg 입구를 같은 입력으로 부른다 ⟨S28⟩
- Non-goal: 쓴소리 질문으로 qg 판정(통과 · 막힘)을 바꾸는 것 ⟨S1⟩
- Non-goal: 머지된 에픽을 다시 열어 고치는 길을 새로 만드는 것 ⟨S15⟩
- Non-goal: 늘 반대하는 역할의 리뷰어 · 상한 없는 질문 ⟨S6⟩

  > 새 리뷰어는 사용자 원문과 설계·에픽 묶음에 비춰 보되 그것을 정답으로 삼지 않고, 사용자의 선택 자체가 틀렸거나 빠뜨린 것까지 큰 방향·기능·동작에 걸쳐 쓴소리한다. (사용자 확인) 내가 잘못 골랐거나 놓쳤을 수 있기 때문이다. 지금 qg 리뷰어들은 의도 출처를 정답으로 놓고 그것을 어겼는지만 보므로, 의도 자체를 비판하는 자리가 없다. 내가 든 예는 잘못된 방향, 잘못된 것 같은 것, 의도가 갈라지는 것이다. 내가 목록을 늘어놓아 달라고 해서 Phase 0 이 문제를 잘못 고름, 더 단순한 길을 놓침, 들인 무게만큼 얻는 것이 없음, 내가 원한 것끼리 부딪침, 써 보면 당연히 필요한데 빠진 기능, 아무도 안 쓸 기능, 조용히 범위가 줄어듦, 모호한 말을 한쪽으로 읽고 굳힘, 앞 결정이 조용히 뒤집힘, 맞지 않는 기본값, 조용한 실패, 써 보면 생기는 마찰을 늘어놓았는데, 그 목록은 내가 하나하나 확인한 것이 아니다. 둘 다 느낌을 보여 주는 예시이지 닫힌 목록이 아니다.
