## 1. Goal · Non-goal

### 이 에픽의 Goal · Non-goal

- 의도: 새 기준으로 있는 테스트를 가르고 지우거나 합치거나 바꿔 테스트 양과 문구 수정 때의 깨짐, 값에 견줘 비싼 테스트가 쓰는 시간을 줄인다
- 범위: 한다: 교차 참조까지 본 판정, 묶음(갈래 · 플러그인별) 단위 승인, 지운 것 기록, 네 갈래 밖 테스트를 같은 기준으로, 판정 뒤 이력 주석 덜기, 지우는 테스트를 이름으로 부르는 규칙 문서 고치기, 앞단 에픽과의 앞뒤 정하기, 값 대비 비용과 필요성 판정에 따라 줄이기 · 합치기, 테스트 쪽 구조 고치기(준비 함께 쓰기 · 나누기 · 더 싼 확인으로 내리기) / 안 한다: 보안 갈래의 글자 확인 지우기, 머지 전 대조의 구조(E1 의 일)

### 공통 목표

- Goal: 이 레포의 테스트 방식이 너무 길고 문제가 있는 것을 맷 포콕의 skill 에 비춰 해소한다 ⟨S1⟩
- Goal: 전체 스위트가 지금보다 크게 짧게 돈다 — 가장 먼저 · 무겁게 ⟨S3⟩
- Goal: 동작이 같은 문구 수정에는 테스트를 고칠 일이 없다 — 행동을 정하는 문장과 보안 장치는 예외다 ⟨S12⟩
- Goal: 테스트 파일과 줄 수가 눈에 띄게 준다 ⟨S1⟩
- Goal: 테스트를 쓰고 지키는 절차가 가벼워진다 — 어디를 테스트할지 먼저 정해 하나씩 쓰되, 레포 문서로 닿는 데까지 ⟨S1⟩ · ⟨S4⟩ · ⟨S26⟩
- Non-goal: 플러그인이 다른 레포에 시키는 테스트 방식을 고치는 것 ⟨S1⟩
- Non-goal: 플러그인의 계획과 구현 안내를 고치는 것 ⟨S4⟩
- Non-goal: 교훈을 테스트로 남기는 규칙과 테스트 편집의 신중함 규칙을 고치는 것 ⟨S13⟩
- Non-goal: 스위트를 함께 돌리기와 바뀐 것에 닿는 테스트만 돌리기를 이번에 먼저 하는 것 — 겹치지 않은 한 바퀴를 다시 잰 뒤, 느린 소수와 두 바퀴 구조만으로 시간 목표에 못 미치면 이 둘을 다시 정한다 ⟨S11⟩ · ⟨S27⟩
- Non-goal: 테스트 파일 수와 줄 수에 숫자 목표를 두는 것 ⟨S17⟩

## 2. 제약

- ☑ confirmed **C4** — 「애매하면 지운다」는 두되 지울지는 교차 참조까지 본 뒤 가르고 시간은 삭제와 따로 잡는다 ⟨S6⟩
- ☑ confirmed **C6** — 보안 장치를 지키는 글자 확인에는 「글자만 바꾸면 안 깨진다」 · 「애매하면 지운다」 두 기준을 쓰지 않는다 ⟨S8⟩
- ☑ confirmed **C7** — 지운 테스트는 기록으로 남긴다 ⟨S9⟩
- ☑ confirmed **C8** — 행동을 정하는 문장만 글자로 지킨다 — 갈래 전체의 규칙은 테스트마다 가르는 구체 규칙이 정한다 ⟨S10⟩
- ☑ confirmed **C12** — 지울 테스트는 모델이 근거를 찾아 묶음으로 내고 묶음 단위로 승인받는다 ⟨S15⟩
- ☑ confirmed **C13** — 테스트 안의 이력 주석은 판정이 끝난 뒤 덜어 낸다 ⟨S16⟩
- ☑ confirmed **C15** — 네 갈래에 들지 않는 테스트도 같은 기준으로 가른다 ⟨S18⟩
- ☑ confirmed **C20** — 새 규칙만 바꾸지 않고 이미 있는 테스트를 지우거나 합치는 데까지 간다 ⟨S1⟩
- ☑ confirmed **C21** — 네 갈래 가운데 통째로 없애는 갈래는 없다 ⟨S1⟩
- ☑ confirmed **C25** — 문제 넷(글자에 묶인 테스트 · 미리 정하지 않고 어디든 다는 테스트 · 한꺼번에 먼저 쓰는 테스트 · 기대값을 검사 대상과 같은 식으로 내는 테스트)이 모두 이 레포의 문제다 ⟨S1⟩
- ☑ confirmed **C26** — 사례 넷 가운데 금지 문장 하나와 절차의 걸음 문장은 글자 확인을 남기기로 골랐고 질문 표의 한 줄 전체와 보고 글의 첫 줄 · 끝 문단은 고르지 않았다 — 걷을지 구조 확인으로 바꿀지는 테스트마다 가른다 ⟨S12⟩

  > 고친다 — 두 셋을 다 밝힌다 (권장) — 정리 문서 리뷰: 「셋 가운데 스위트 시간 먼저」의 셋이 이 인터뷰가 보인 셋임과 앞 회의에서 답한 셋을 함께 적는다

- **S31** ☑ 선택 (R12):
  > 고친다 — 로드맵 E2 에 적는다 (권장) — 정리 문서 리뷰: 규칙 문서를 고치는 에픽을 두 에픽 뒤에 여는 순서를 로드맵에도 싣는다
- **S32** ☑ 선택 (R12):
  > 승인 — 확인 블록 E0 를 더한다 (권장) — 분해안 고침: 규칙 문서를 쥔 두 에픽의 머지를 확인하는 결정 블록 E0 를 더하고 E2 가 E0 에 의존한다(E1 의 범위 문구 둘과 새 번호 배정도 함께 바뀐다)

- **S33** ☑ 선택 (R13):
  > 고친다 — 앞의 둘만 기다린다 (권장) — 정리 문서 리뷰: 규칙 문서를 예약한 일 넷을 이름으로 적고, 진행 중인 둘만 기다리며 뒤의 둘에는 알리기만 한다(확인 블록이 열릴 때 다시 센다)
