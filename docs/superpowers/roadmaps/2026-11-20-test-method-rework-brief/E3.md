## 1. Goal · Non-goal

### 이 에픽의 Goal · Non-goal

- 의도: 문구 확인을 걷은 자리를 무엇이 지킬지 후보 다섯을 따져 정하고 고른 것을 쓸 수 있게 한다
- 범위: 한다: 후보 다섯(구조 확인 · 코드 조각 실행 · 가짜 응답 · 실제 모델 평가 · 리뷰) 견주기, 공식 평가 기능의 비용과 문턱, 고른 장치의 첫 적용 / 안 한다: 있는 테스트의 대량 전환

### 공통 목표

- Goal: 이 레포의 테스트 방식이 너무 길고 문제가 있는 것을 맷 포콕의 skill 에 비춰 해소한다 ⟨S1⟩
- Goal: 전체 스위트가 지금보다 크게 짧게 돈다 — 가장 먼저 · 무겁게 ⟨S3⟩
- Goal: 동작이 같은 문구 수정에는 테스트를 고칠 일이 없다 — 행동을 정하는 문장과 보안 장치는 예외다 ⟨S12⟩
- Goal: 테스트 파일과 줄 수가 눈에 띄게 준다 ⟨S1⟩
- Goal: 테스트를 쓰고 지키는 절차가 가벼워진다 — 어디를 테스트할지 먼저 정해 하나씩 쓰되, 레포 문서로 닿는 데까지 ⟨S1⟩ · ⟨S4⟩ · ⟨S26⟩
- Non-goal: 플러그인이 다른 레포에 시키는 테스트 방식을 고치는 것 ⟨S1⟩
- Non-goal: 플러그인의 계획과 구현 안내를 고치는 것 ⟨S4⟩
- Non-goal: 교훈을 테스트로 남기는 규칙과 테스트 편집의 신중함 규칙을 고치는 것 ⟨S13⟩
- Non-goal: 스위트를 함께 돌리기와 바뀐 것에 닿는 테스트만 돌리기를 이번에 먼저 하는 것 — 겹치지 않은 한 바퀴를 다시 잰 뒤, 느린 소수와 두 바퀴 구조만으로 시간 목표에 못 미치면 이 둘을 다시 정한다 ⟨S11⟩ · ⟨S27⟩
- Non-goal: 테스트 파일 수와 줄 수에 숫자 목표를 두는 것 ⟨S17⟩

## 4. 웹 근거

- Anthropic 의 skill 작성 문서는 평가를 문서보다 먼저 만들라고 하고 글자 대조는 언급하지 않는다 «anthropic-skill-best-practices» — [중립] — 글을 지키는 길이 글자 대조만이 아니라는 근거다 (1차 · 확인 2026-11-20) [→ OQ4]
- Claude Code 의 공식 평가 기능은 플러그인을 실제로 돌려 채점하고 실행마다 실제 모델 호출이다 «cc-plugin-evals» — [중립] — 후보 다섯 가운데 하나이고 비용과 문턱은 설계가 따진다 (1차 · 확인 2026-11-20) [→ OQ4]
- 프롬프트는 뜻을 바꾸지 않는 서식만 바꿔도 결과가 최대 76점 흔들린다 «sclar-prompt-format» — [취함] — 글자 확인이 모두 구현에 묶인 테스트는 아니라는 근거다 (1차 · 확인 2026-11-20) [→ OQ3 · OQ18]

- 근거 — 검사기에 변이를 먹여 규칙을 재는 테스트가 있다 — RC29 (shared/tests/test_invocation_surface.sh#합성 리포) — [중립] — 구조 확인의 선례다 [RC29 → OQ4]
- 근거 — 하니스의 그 테스트는 skill 문구의 줄 순서와 거리만 재고 아무것도 돌리지 않는다 — RC49 (plugins/quality-gates/tests/harness/test_skill_orchestration_behavior.sh#first_line) — [피함] — 「가짜 응답으로 돌려 보기」의 선례가 아니다 [RC49 → OQ4]

- 근거 — 레포 코드에 실제 모델을 돌려 채점하는 장치의 흔적이 없다 — RC51 (plugins/quality-gates/tests/harness/run_consent_gate.sh#Real AskUserQuestion not invoked in harness) — [중립] — 실제 모델 평가는 새로 들이는 것이다 [RC51 → OQ4]

    ## 2. 질문 전체
    
    ### 라운드 1
    
    - 물은 것: 「테스트 방식이 너무 길다」에서 긴 것은 무엇인가요? (맞는 것을 모두 고르거나 기타에 적어 주세요)
      - 선택지: 도는 시간 / 테스트 코드의 양 / 쓰고 지키는 절차
      - 당신이 답한 것 (라벨 · 적음): 도는 시간, 테스트 코드의 양, 쓰고 지키는 절차, 맷폭콕이 이야기한거
    - 물은 것: 맷 포콕 스킬에 비춰 느끼신 문제는 어느 것에 가깝나요? (맞는 것을 모두 고르거나 기타에 적어 주세요)
      - 선택지: 글자에 묶인 테스트 / 어디든 다 테스트 / 한꺼번에 먼저 쓰기 / 기대값을 같은 식으로
      - 당신이 답한 것 (라벨): 글자에 묶인 테스트, 어디든 다 테스트, 한꺼번에 먼저 쓰기, 기대값을 같은 식으로
    - 물은 것: 어느 테스트를 말씀하시는 건가요?
      - 선택지: 이 레포의 테스트 / 플러그인이 시키는 방식 / 둘 다
      - 당신이 답한 것 (라벨): 이 레포의 테스트
    - 물은 것: 「해소」는 어디까지를 바라시나요?
      - 선택지: 앞으로 쓰는 방식만 / 있는 테스트도 정리 / 먼저 재 보고 정한다
      - 당신이 답한 것 (라벨): 있는 테스트도 정리
    
    ### 라운드 2
    
    - 물은 것: 있는 테스트를 정리할 때 어느 갈래를 남기나요? 포콕은 전부 테스트할 수 없으니 중요한 길과 복잡한 로직에만 테스트를 두라고 합니다. (남길 것을 모두 고르거나 기타에 적어 주세요)
      - 선택지: 스크립트 동작 확인 / 보안 장치 확인 / 복사본 일치 확인 / 문서 문구 확인
      - 당신이 답한 것 (라벨): 스크립트 동작 확인, 보안 장치 확인, 복사본 일치 확인, 문서 문구 확인
    - 물은 것: 문서 문구 확인을 지우거나 줄이면 그 자리는 무엇이 지키나요?
      - 선택지: 리뷰가 지킨다 / 돌려 보는 확인으로 / 다음 단계에서 정한다
      - 당신이 답한 것 (라벨): 다음 단계에서 정한다
    - 물은 것: 무엇이 되면 해소됐다고 보시나요? (맞는 것을 모두 고르거나 기타에 적어 주세요 — 숫자 목표가 있으면 기타에)
      - 선택지: 스위트가 짧게 돈다 / 글자만 바꾸면 안 깨진다 / 테스트가 크게 준다 / 쓰는 절차가 가볍다
      - 당신이 답한 것 (라벨): 스위트가 짧게 돈다, 글자만 바꾸면 안 깨진다, 테스트가 크게 준다, 쓰는 절차가 가볍다
    - 확인 질문: 라운드 1 의 풀이
      - 내가 읽은 것: 「긴 것은 스위트가 도는 시간, 테스트 코드의 양, 테스트를 쓰고 지키는 절차 셋 모두이고, 맷 포콕이 짚은 것들도 여기에 든다.」 — 고름
      - 내가 읽은 것: 「글자에 묶인 테스트, 미리 정하지 않고 어디든 다는 테스트, 한꺼번에 먼저 쓰는 테스트, 기대값을 검사 대상과 같은 식으로 내는 테스트 넷이 모두 이 레포의 문제다.」 — 고름
      - 내가 읽은 것: 「대상은 이 레포를 개발할 때 쓰고 돌리는 테스트이고, 플러그인이 다른 레포에 시키는 테스트 방식은 대상이 아니다.」 — 고름
      - 내가 읽은 것: 「새 테스트를 쓰는 규칙만 바꾸지 않고 이미 있는 테스트를 지우거나 합치는 데까지 간다.」 — 고름
    
    ### 라운드 3
    
    - 물은 것: 문서 문구 확인을 남기면서 글자만 바꾼 수정에는 안 깨지게 하려면, 「남긴다」는 어떤 뜻인가요?
      - 선택지: 꼭 필요한 것만 남긴다 / 글자 대신 구조를 본다 / 테스트마다 가른다
      - 당신이 답한 것 (라벨): 테스트마다 가른다
    - 물은 것: 「한꺼번에 먼저 쓰기」를 고치려면 계획이 테스트 코드를 통째로 싣고 구현이 뒤따르는 지금 방식에 닿습니다. 어디까지 고치나요?
      - 선택지: 이 레포의 규칙만 / 플러그인 안내도 고친다 / 다음 단계에서 정한다
      - 당신이 답한 것 (라벨): 이 레포의 규칙만
    - 물은 것: 스위트 시간 줄이기는 11월 14일 기록에 뒤 에픽의 입력으로만 적혀 있고 에픽으로는 올라 있지 않습니다. 이 일과 어떻게 두나요?
      - 선택지: 이 일이 가져온다 / 테스트를 줄인 결과로만 / 다음 단계에서 정한다
      - 당신이 답한 것 (라벨): 다음 단계에서 정한다
    - 확인 질문: 라운드 2 의 풀이
      - 내가 읽은 것: 「네 갈래(스크립트 동작 확인, 보안 장치 확인, 복사본 일치 확인, 문서 문구 확인) 가운데 통째로 없애는 갈래는 없다.」 — 고름
      - 내가 읽은 것: 「문구 확인을 지우거나 줄인 자리를 무엇이 지킬지는 지금 정하지 않고 인터뷰와 설계가 근거를 모아 정한다.」 — 고름
      - 내가 읽은 것: 「해소된 모습은 전체 스위트가 지금보다 크게 짧게 돌고, 동작이 같은 문구 수정에는 테스트를 고칠 일이 없고, 테스트 파일과 줄 수가 눈에 띄게 줄고, 어디를 테스트할지 먼저 정해 하나씩 쓰는 것이다.」 — 고름
    
    ### 라운드 4
    
    - 물은 것: 어떤 테스트를 지울지 남길지 애매할 때는 어느 쪽으로 기우나요?
      - 선택지: 애매하면 지운다 / 애매하면 남긴다 / 다음 단계에서 정한다
      - 당신이 답한 것 (라벨): 애매하면 지운다
    - 확인 질문: 라운드 3 의 풀이
      - 내가 읽은 것: 「문서 문구 확인은 테스트마다 지울지, 구조를 보는 확인으로 바꿀지, 글자 그대로 둘지를 다음 단계가 가른다.」 — 고름
      - 내가 읽은 것: 「고치는 곳은 이 레포의 문서에 적는 테스트 규칙이고, 플러그인의 계획과 구현 안내는 건드리지 않는다.」 — 고름
      - 내가 읽은 것: 「스위트를 돌리는 방식까지 이 일이 가져올지는 지금 정하지 않고 인터뷰가 시간이 어디서 드는지 잰 뒤 정한다.」 — 고름

  > 스위트 시간 — 셋 가운데 가장 먼저 · 무겁게 풀 것
- **S4** ☑ 선택 (R1):
  > 레포 문서로 닿는 데까지만 — 「한꺼번에 먼저 쓰기」를 푸는 범위
- **S5** ☑ 선택 (R1):
  > 구조 확인으로 바꾸기, 가짜 응답으로 돌려 보기, 리뷰에 맡기기, 실제 모델로 평가 — 문구 확인을 지운 자리를 지킬 후보로 설계가 따질 것
- **S6** ☑ 선택 (R2):
  > 보완 (builder·orchestrator 추천) — 「애매하면 지운다」 방향의 판정(ST1)
- **S7** ☑ 선택 (R3):
  > 옮겨 적고 고쳐 적는다 (권장) — 그 skill 본문 가운데 이 레포에 그대로 안 맞는 항목의 처리
- **S8** ☑ 선택 (R4):
  > 보안 갈래는 예외 (권장) — 보안 장치를 지키는 글자 확인에는 「글자만 바꾸면 안 깨진다」 · 「애매하면 지운다」를 쓰지 않는다
- **S9** ☑ 선택 (R4):
  > 지운 것을 기록으로 남긴다 (권장) — 지운 테스트가 스위트와 대조에 보이지 않는 것에 대해
- **S10** ☑ 선택 (R4):
  > 행동을 정하는 문장만 지킨다 (권장) — 「글자에 묶인 테스트」 가운데 무엇을 문제로 볼지
- **S11** ☑ 선택 (R4):
  > 느린 테스트 소수 손보기 (권장), 두 번 도는 구조 고치기 (권장) — 스위트 시간을 줄일 때 손댈 것
- **S12** ☑ 선택 (R5):
  > 금지 문장 하나 (권장), 절차의 걸음 문장 (권장) — 사례 넷 가운데 글자 확인을 남길 것(질문 표의 한 줄 전체 · 보고 글의 첫 줄과 끝 문단은 고르지 않음)
- **S13** ☑ 선택 (R6):
  > 망가뜨려 보기를 가볍게 (권장) — 상시 규칙 셋 가운데 이 일이 고칠 것(교훈을 테스트로 남기는 길 · 신중함 규칙 · 규칙은 두고 테스트만은 고르지 않음)
- **S14** ☑ 선택 (R6):
  > 시간 쪽부터 따로 간다 (권장) — 진행 중인 에픽들과의 순서
- **S15** ☑ 선택 (R6):
  > 묶음 단위로 승인 (권장) — 지울 테스트를 누가 가르고 어느 단위로 승인하는지
- **S16** ☑ 선택 (R6):
  > 판정이 끝난 뒤 덜어 낸다 (권장) — 테스트 안의 이력 주석
- **S17** ☑ 선택 (R7):
  > 시간만 숫자로 (권장) — 숫자 목표
- **S18** ☑ 선택 (R7):
  > 같은 기준으로 가른다 (권장) — 네 갈래에 들지 않는 테스트(테스트를 시험하는 테스트 · 규칙 문서가 이름으로 부르는 테스트)
- **S19** ☑ 선택 (R7):
  > 이대로 넘긴다 — 열린 채 설계로 넘길 여덟의 목록
- **S20** ☑ 선택 (R8):
  > 코드 조각 실행을 더한다 (권장) — 문구 확인을 걷은 자리를 지킬 후보 목록의 정정(후보는 다섯이 된다)
- **S21** ☑ 선택 (R8):
  > 안 겹치는 여덟부터 지금 (권장) — 느린 테스트 손보기의 시작 시점
- **S22** ☑ 선택 (R8):
  > 이 일이 고치고 알린다 (권장) — 머지 전 대조가 스위트를 두 번 도는 구조를 누가 고치는지
- **S23** ☑ 선택 (R8):
  > 알린다 (권장) — 글자 확인 기준을 앞단 글을 줄이는 에픽에 알릴지
- **S24** ☑ 선택 (R9):
  > 포화로 보고 종료 (권장) — 포화 판정 2 의 반복 빈 곳에 대해
- **S25** ☑ 선택 (R10):
  > 나눈다 — 분해안 보기 (권장) — 이 일을 spec 하나로 할지 나눌지

- **S26** ☑ 선택 (R11):
  > 고친다 — 가벼워진다를 목표로 (권장) — 정리 문서 리뷰: 다섯째 목표를 「쓰고 지키는 절차가 가벼워진다 — 자리를 먼저 정해 하나씩, 레포 문서로 닿는 데까지」로 고친다
- **S27** ☑ 선택 (R11):
  > 고친다 — 다시 잰 뒤 정한다로 (권장) — 정리 문서 리뷰: 함께 돌리기 · 닿는 테스트만 돌리기를 「이번에 먼저 하지 않는다 — 다시 잰 뒤 목표에 못 미치면 다시 정한다」로 고친다
- **S28** ☑ 선택 (R11):
  > 고친다 — 예외로 적는다 (권장) — 정리 문서 리뷰: 머지 전 대조의 두 바퀴 구조 고치기를 「이 레포만」 범위의 예외로 적는다(플러그인 스크립트를 고치고 판을 올리며 새 실패와 원래 실패를 가르는 결과는 지킨다)
- **S29** ☑ 선택 (R11):
  > 고친다 — 두 에픽 뒤에 연다 — 정리 문서 리뷰: 규칙 문서를 고치는 에픽은 그 문서를 쥔 진행 중 에픽 둘이 해당 문서를 머지한 뒤에 연다
- **S30** ☑ 선택 (R11):
  > 고친다 — 두 셋을 다 밝힌다 (권장) — 정리 문서 리뷰: 「셋 가운데 스위트 시간 먼저」의 셋이 이 인터뷰가 보인 셋임과 앞 회의에서 답한 셋을 함께 적는다

- **S31** ☑ 선택 (R12):
  > 고친다 — 로드맵 E2 에 적는다 (권장) — 정리 문서 리뷰: 규칙 문서를 고치는 에픽을 두 에픽 뒤에 여는 순서를 로드맵에도 싣는다
- **S32** ☑ 선택 (R12):
  > 승인 — 확인 블록 E0 를 더한다 (권장) — 분해안 고침: 규칙 문서를 쥔 두 에픽의 머지를 확인하는 결정 블록 E0 를 더하고 E2 가 E0 에 의존한다(E1 의 범위 문구 둘과 새 번호 배정도 함께 바뀐다)

- **S33** ☑ 선택 (R13):
  > 고친다 — 앞의 둘만 기다린다 (권장) — 정리 문서 리뷰: 규칙 문서를 예약한 일 넷을 이름으로 적고, 진행 중인 둘만 기다리며 뒤의 둘에는 알리기만 한다(확인 블록이 열릴 때 다시 센다)
