## 1. Goal · Non-goal

### 이 에픽의 Goal · Non-goal

- 의도: 맷 포콕 tdd skill 본문의 기준을 이 레포 문서에 옮겨 적고 안 맞는 항목을 고쳐 적어, 새 테스트가 지금 꼴로 쌓이는 길을 바꾼다
- 범위: 한다: (확인 블록 E0 가 닫힌 뒤에 연다 — 규칙 문서를 쥔 다른 로드맵의 진행 중 에픽 둘이 해당 문서를 머지한 뒤) 기준 옮겨 적기(고지 파일 포함), 「행동을 정하는 문장」을 가르는 구체 규칙, 「테스트할 자리를 미리 정한다」의 자리, 「망가뜨려 보기」 가볍게, 지운 것 기록의 자리와 꼴, 묶음 승인 절차, 보안 갈래 예외 적기, 앞단 에픽에 기준 알리기, 같은 규칙 문서를 예약한 뒤의 일에 알리기 / 안 한다: 플러그인의 계획 · 구현 안내 고치기, 교훈을 테스트로 남기는 규칙과 신중함 규칙 고치기, 있는 테스트 지우기

### 공통 목표

- Goal: 이 레포의 테스트 방식이 너무 길고 문제가 있는 것을 맷 포콕의 skill 에 비춰 해소한다 ⟨S1⟩
- Goal: 전체 스위트가 지금보다 크게 짧게 돈다 — 가장 먼저 · 무겁게 ⟨S3⟩
- Goal: 동작이 같은 문구 수정에는 테스트를 고칠 일이 없다 — 행동을 정하는 문장과 보안 장치는 예외다 ⟨S12⟩
- Goal: 테스트 파일과 줄 수가 눈에 띄게 준다 ⟨S1⟩
- Goal: 테스트를 쓰고 지키는 절차가 가벼워진다 — 어디를 테스트할지 먼저 정해 하나씩 쓰되, 레포 문서로 닿는 데까지 ⟨S1⟩ · ⟨S4⟩ · ⟨S26⟩
- Non-goal: 플러그인이 다른 레포에 시키는 테스트 방식을 고치는 것 ⟨S1⟩
- Non-goal: 플러그인의 계획과 구현 안내를 고치는 것 ⟨S4⟩
- Non-goal: 교훈을 테스트로 남기는 규칙과 테스트 편집의 신중함 규칙을 고치는 것 ⟨S13⟩
- Non-goal: 스위트를 함께 돌리기와 바뀐 것에 닿는 테스트만 돌리기를 이번에 먼저 하는 것 — 겹치지 않은 한 바퀴를 다시 잰 뒤, 느린 소수와 두 바퀴 구조만으로 시간 목표에 못 미치면 이 둘을 다시 정한다 ⟨S11⟩ · ⟨S27⟩
- Non-goal: 테스트 파일 수와 줄 수에 숫자 목표를 두는 것 ⟨S17⟩

## 2. 제약

- ☑ confirmed **C1** — 기준은 맷 포콕의 테스트 주도 개발 skill 본문 전체다 ⟨S2⟩
- ☑ confirmed **C3** — 「한꺼번에 먼저 쓰기」는 레포 문서로 닿는 데까지만 푼다 ⟨S4⟩
- ☑ confirmed **C5** — 그 skill 의 기준은 이 레포 문서에 옮겨 적고 안 맞는 항목은 고쳐 적는다 ⟨S7⟩
- ☑ confirmed **C10** — 상시 규칙 셋 가운데 이 일이 고치는 것은 「망가뜨려 보기」 하나이고 가볍게 한다 ⟨S13⟩
- ☑ confirmed **C18** — 글자 확인 기준을 앞단 글을 줄이는 에픽에 알린다 ⟨S23⟩
- ☑ confirmed **C19** — 대상은 이 레포를 개발할 때 쓰고 돌리는 테스트다 ⟨S1⟩
- ☑ confirmed **C22** — 플러그인의 계획과 구현 안내는 건드리지 않는다 ⟨S1⟩
- ☑ confirmed **C24** — 규칙 문서를 고치는 에픽은 규칙 문서 셋(CLAUDE.md · docs/plugin-authoring.md · 역할 문서 폴더)을 경로 예약한 다른 로드맵의 일 가운데 지금 진행 중인 둘(지휘 로드맵의 구현 중 에픽 · 앞단 로드맵의 설계 중 에픽)이 해당 문서를 머지한 뒤에 연다 — 같은 문서를 예약한 뒤의 둘(앞단 로드맵 스위치 에픽의 둘째 계획 · 지휘 로드맵의 대기 중 세션 담당자 에픽)은 기다리지 않고 알리기만 하며, 확인 블록이 열릴 때 경로 예약을 다시 센다 ⟨S33⟩
- ☑ confirmed **C25** — 문제 넷(글자에 묶인 테스트 · 미리 정하지 않고 어디든 다는 테스트 · 한꺼번에 먼저 쓰는 테스트 · 기대값을 검사 대상과 같은 식으로 내는 테스트)이 모두 이 레포의 문제다 ⟨S1⟩

## 4. 웹 근거

- 변이 점수 100% 를 쫓지 말고 위험이 큰 곳에 집중한다 «ms-stryker-net» — [취함] — 보안 갈래에만 무겁게 두는 길의 근거다 (1차 · 확인 2026-11-20) [→ OQ21]
- 변이 검사는 바꾸는 코드에만 거는 것이 가장 효과적이고 계산이 비싸다 «pitest-faq» — [취함] — 같은 방향이다 (1차 · 확인 2026-11-20) [→ OQ21]
- 맷 포콕의 테스트 주도 개발 skill 은 공개 경계로 동작을 확인하고 미리 합의한 자리에서만 테스트하라고 하며, 테스트를 지우라는 말과 글을 시험하는 법은 없다 «pocock-tdd» — [취함] — 기준으로 삼되 이 레포에 안 맞는 둘은 고쳐 적는다 (1차 · 확인 2026-11-20) [→ OQ1 · OQ9]
- 변이 검사를 큰 규모로 운영하는 곳은 바뀐 코드에만 걸고 수를 제한한다 «practical-mutation» — [취함] — 「망가뜨려 보기」를 가볍게 하는 바깥 기준이다 (1차 · 확인 2026-11-20) [→ OQ21]
- 바뀐 것만 보는 변이 검사는 가끔 전체를 한 번 돌려 어긋남을 막는다 «stryker-incremental» — [중립] — 가볍게 한 뒤의 보완 길이다 (1차 · 확인 2026-11-20) [→ OQ21]
