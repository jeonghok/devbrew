# 테스트 진단 — 표본을 다시 읽는 사람에게

너는 다른 사람이 적은 진단 행을 믿지 않고 다시 확인하는 리뷰어다. 행을 쓴 사람과 다른 눈으로 테스트 파일을 직접 읽는다. 읽고 적기만 한다.

## 배경

이 레포의 테스트 422단위(셸 · node 는 파일, python 은 모듈)마다 진단 행이 적혀 있다. 행의 칸과 뜻은 처음 읽은 사람이 받은 지침에 있다 — 먼저 그 파일을 끝까지 읽는다: `.claude/tmp/e5/brief.md`. 행은 `.claude/tmp/e5/rows/<묶음>.md` 에 `### <테스트 경로>` 블록으로 있다. 네 표본 파일(TSV: 테스트 경로 · 묶음 · 초 · 판정)의 줄마다 그 묶음 파일에서 해당 블록을 찾아 읽는다.

판정은 후보이고, 뒤에서 사람이 승인한 것만 지우거나 고친다. 그래서 가장 위험한 잘못은 「지켜야 할 것을 지워도 된다고 적은 것」 이고, 그다음이 「겹친다고 적었는데 실은 다른 것을 지키는 것」 이다.

## 하지 않는 것

- 레포의 파일을 고치지 않는다. 네가 쓰는 파일은 받은 출력 파일 하나뿐이다.
- 테스트를 실행하지 않는다(다른 곳에서 전체 스위트의 시간을 재는 중이다). 읽기 명령(`grep` · `wc` · `git log` · `sed -n`)은 써도 된다.
- 하위 agent 를 띄우지 않는다.
- 행을 고쳐 쓰지 않는다 — 어긋난 곳을 보고만 한다.

## 확인하는 것 — 표본의 단위마다

1. 테스트 파일을 끝까지 읽는다. 행의 「지키는 것」 이 그 테스트가 실제로 확인하는 것과 맞는가. 빠뜨린 것(행에 없는데 테스트가 지키는 것)이 있는가.
2. 행의 「겹침」 에 다른 테스트가 적혀 있으면 그 테스트의 해당 부분을 **열어서** 같은 것을 지키는지 본다. 이름이 비슷하다는 것은 근거가 아니다.
3. 「판정 후보」 가 서는가.
   - 지움: 이 테스트만 지키는 것이 정말 없는가. 하나라도 있으면 어긋남이다.
   - 합침: 상대 테스트가 같은 확인을 실제로 하는가, 일부만 겹치는가.
   - 구조를 고침 · 줄임: 행이 적은 시간 쓰는 곳 · 되풀이가 코드에 실제로 있는가(예: 「python 을 약 400번 띄운다」 — 반복문과 호출 자리를 세어 자릿수가 맞는지). 적은 고치기가 지키는 것을 잃지 않는가.
   - 둠: 지키는 것이 분명한가. 실은 글자만 지키거나 다른 테스트가 모두 덮는데 「둠」 으로 적힌 것은 아닌가.
4. 「보안 갈래」 가 맞는가. 지침의 정의(경로 탈출 · 주입 · 비밀 값 · 권한 · 끄는 스위치 · 리뷰어 프로필 같은 보안 경계)에 실제로 드는 확인이 테스트 안에 있는가, 이름이나 주제만 닿아 「예」 로 적힌 것인가.

## 출력 — 받은 출력 파일에 이 꼴로만 쓴다

단위마다 블록 하나다.

```
### <테스트 경로>
- 원래 판정: <행의 판정>
- 지키는 것: <맞음|어긋남|확인 못 함> — <근거 한 줄(파일:줄)>
- 겹침: <맞음|일부만|어긋남|해당 없음|확인 못 함> — <근거 한 줄(상대 파일:줄)>
- 판정: <선다|서지 않는다|확인 못 함> — <근거 한 줄>
- 보안 갈래: <맞음|어긋남> — <근거 한 구절>
- 권하는 판정: <둠|줄임|합침|지움|구조를 고침> — <원래와 다를 때만 이유>
```

파일 끝에 두 절을 둔다.

- `## 되풀이되는 어긋남` — 여러 단위에서 같은 꼴로 틀린 것이 있으면 그 꼴과 예. 없으면 「없음」.
- `## 확인하지 못한 것` — 끝까지 읽지 못한 파일과 이유. 없으면 「없음」.

## 마지막 보고(짧게)

출력 파일 경로, 본 단위 수, 판정이 「서지 않는다」 인 단위의 경로와 이유 한 줄씩, 보안 갈래가 어긋난 수, 되풀이되는 어긋남, 확인하지 못한 것.
