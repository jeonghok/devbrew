# 테스트 값 대비 비용 진단 — 읽는 사람에게

너는 이 레포의 테스트를 읽고 진단 표의 행을 적는 일을 맡았다. 읽고 적기만 한다.

## 배경

- 이 레포(devbrew)는 Claude Code 플러그인 마켓플레이스다. 플러그인은 `plugins/<이름>/` 아래에 스크립트(`scripts/` · `hooks/`), 모델이 읽는 글(`skills/` · `references/` · `agents/`), 테스트(`tests/`)를 둔다. 여러 플러그인이 함께 쓰는 것은 `shared/`, 레포 도구는 `tools/` 다.
- 전체 테스트는 한 바퀴에 약 60분이다. 테스트는 리뷰 라운드마다 확인이 한 줄씩 붙으며 자랐다. 사용자는 테스트마다 「쓰는 시간만큼 지키는 것이 있나 · 꼭 필요한가 · 테스트 쪽 구조를 고치면 나아지나」를 판정할 근거를 원한다.
- 이번 일은 진단이다. 지우거나 고치는 것은 뒤의 일이고, 네가 적는 판정은 후보다.

## 하지 않는 것

- 레포의 파일을 고치지 않는다. 네가 쓰는 파일은 받은 출력 파일 하나뿐이다.
- 테스트를 실행하지 않는다 — 지금 다른 곳에서 전체 스위트의 시간을 재고 있어, 테스트를 돌리면 그 숫자가 흐려진다. 읽기 명령(`grep` · `wc` · `git log` · `sed -n`)은 써도 된다.
- 하위 agent 를 띄우지 않는다.

## 읽는 법

1. 묶음 파일(TSV: 초 · 종류 · 경로 · 줄 수)의 줄마다 그 테스트 파일을 **끝까지** 읽는다. 머리 주석만 읽고 판단하지 않는다.
2. 테스트가 겨누는 대상(스크립트 · 문서)을 필요한 만큼 연다 — 테스트가 무엇을 확인하는지 알 만큼만.
3. `git log --oneline -- <경로> | wc -l` 로 그 테스트가 고쳐진 횟수를 센다.
4. 같은 것을 지키는 다른 테스트가 있는지 대상 이름으로 한두 번 찾아본다(`grep -rl "<대상 파일 이름>" plugins/*/tests shared/tests tools`). 찾지 못했으면 「못 찾음」, 찾아보지 못했으면 「확인 못 함」 이라고 적는다 — 둘은 다르다.

## 칸의 뜻

- **크기** — 그 테스트가 쓰는 자원. 작음: 한 프로세스 안이거나 파일 읽기 · grep 뿐 / 중간: 스크립트를 하위 프로세스로 실행 · 임시 git 레포 · 임시 폴더 / 큼: 다른 테스트나 러너를 다시 돌린다 · 사본을 여럿 만든다 · 시간을 기다린다(sleep · 시간 문턱) · 바깥 호출.
- **종류** — 확인의 갈래. 동작: 코드를 실제로 실행해 결과(출력 · 종료 코드 · 만든 파일)를 본다 / 구조: 파일 · 필드 · 형식이 있는지 본다 / 글자: 문서나 코드에 특정 문구가 있는지(없는지) grep 한다 / 변이: 코드를 일부러 망가뜨린 사본에서 테스트가 빨개지는지 본다. 섞였으면 어림 비율을 적는다.
- **지키는 것** — 「이 테스트가 깨지면 플러그인을 쓰는 사람(또는 플러그인을 고치는 사람)에게 무엇이 잘못되나」를 한 문장으로. 그 문장을 쓸 수 없고 특정 글자가 그 자리에 있다는 것만 확인하면 `글자만 지킴 — <어느 파일의 무슨 문구>` 라고 적는다. 지어내지 않는다 — 테스트가 실제로 확인하는 것만 적는다.
- **거짓 실패 위험** — 동작은 그대로인데 테스트만 깨지는 경우가 얼마나 쉬운가. 높음: 문구를 다듬거나 파일을 옮기기만 해도 깨진다 · 시간 문턱이 부하에 흔들린다 / 중간 / 낮음: 동작이 바뀔 때만 깨진다. 언제 깨지는지 한 구절을 붙인다.
- **겹침** — 같은 것을 지키는 다른 테스트의 경로와 겹치는 내용. 한 파일 안에서 같은 확인을 되풀이하는 것도 여기 적는다.
- **보안 갈래** — 경로 탈출 · 주입 · 비밀 값 · 권한 · 끄는 스위치(kill switch) · 리뷰어 프로필 같은 보안 경계를 지키면 「예」. 이 갈래의 글자 확인은 뒤에서도 지우지 않기로 돼 있다.
- **판정 후보** — 아래 다섯 가운데 하나와 근거 한 줄. 확신이 서지 않으면 「둠」 을 고르고 확신을 「낮음」 으로 적는다.
  - 둠: 지키는 것이 분명하고 비용이 그에 맞다.
  - 줄임: 지키는 것은 있으나 같은 확인을 되풀이하거나 필요 이상으로 많이 돈다 — 덜어도 지키는 것이 그대로다.
  - 합침: 다른 테스트와 같은 것을 지킨다 — 한쪽으로 모을 수 있다.
  - 지움: 지키는 것을 적을 수 없거나(글자만 지킴이고 그 글자가 동작을 정하지 않는다), 더 싼 다른 테스트가 이미 모두 지킨다.
  - 구조를 고침: 지키는 것은 그대로 두고 테스트의 짜임을 바꾸면 싸지거나 덜 깨진다(준비를 함께 쓰기 · 나누기 · 더 싼 확인으로 내리기 · 글자 확인을 동작 확인으로 바꾸기).
- **확신** — 네 판정에 대한 확신. 높음 · 중간 · 낮음.

## 깊게 읽는 묶음에만 더하는 칸

- **확인 수** — 그 파일의 확인(단언 · 케이스)이 대략 몇 개이고 갈래별로 몇 개인가.
- **시간을 쓰는 곳** — 어느 준비나 확인이 초를 쓰는지 읽어서 판단한다(예: 케이스마다 임시 git 레포를 새로 만든다 · 같은 스크립트를 케이스마다 python 으로 새로 띄운다 · sleep 으로 기다린다 · 사본을 케이스 수만큼 만든다). 실행하지 않았으므로 추정이라고 밝힌다.
- **구조 고치기 여지** — 준비 함께 쓰기 · 나누기 · 더 싼 확인으로 내리기 가운데 해당하는 것과 그 자리. 없으면 「없음」.

## 출력 — 받은 출력 파일에 이 꼴로만 쓴다

단위마다 아래 블록 하나다. 칸 이름과 차례를 바꾸지 않는다. 한 칸은 한 줄이다.

```
### <테스트 경로>
- 초: <묶음 파일의 값>
- 줄 수: <묶음 파일의 값>
- 고친 횟수: <n>
- 크기: <작음|중간|큼> — <한 구절>
- 종류: <동작|구조|글자|변이|섞임(동작 a · 구조 b · 글자 c · 변이 d)>
- 지키는 것: <한 문장> 또는 글자만 지킴 — <어느 파일의 무슨 문구>
- 거짓 실패 위험: <높음|중간|낮음> — <언제 깨지나>
- 겹침: <경로 — 무엇이 겹치나> 또는 못 찾음 또는 확인 못 함
- 보안 갈래: <예|아니오>
- 판정 후보: <둠|줄임|합침|지움|구조를 고침> — <근거 한 줄>
- 확신: <높음|중간|낮음>
```

깊게 읽는 묶음은 `- 확신:` 줄 뒤에 세 줄을 더한다.

```
- 확인 수: 약 <n>개 (동작 a · 구조 b · 글자 c · 변이 d)
- 시간을 쓰는 곳: <추정 — …>
- 구조 고치기 여지: <…> 또는 없음
```

파일 끝에 `## 읽지 못한 것` 절을 두고, 끝까지 읽지 못했거나 판단하지 못한 단위와 이유를 적는다. 없으면 「없음」.

## 마지막 보고(짧게)

출력 파일 경로, 적은 단위 수, 판정 후보별 수, 가장 눈에 띈 것 셋(한 줄씩), 읽지 못한 것.
