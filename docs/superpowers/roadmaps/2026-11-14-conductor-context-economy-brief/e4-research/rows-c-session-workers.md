### hc · claude 로 띄울 때 걸 수 있는 옵션 (읽기로 돌림: hc 0.1.22 · Claude Code 2.1.332)
- `hc run --help`: `--json --name --cwd --on --label --parent --no-parent --no-notify --outlive-parent --rm --keep --bg --timeout`. **hc 자체에는 도구 · 파일을 막는 옵션이 없다.** `hc templates` → `{"templates":[]}`.
- 막는 옵션은 띄우는 프로그램 `claude` 의 것이다(`claude --help`): `--disallowedTools/--disallowed-tools <tools...>`(예: `"Bash(git *)" Edit`) · `--allowedTools/--allowed-tools` · `--tools <tools...>`(쓸 내장 도구 목록) · `--permission-mode <acceptEdits|auto|bypassPermissions|manual|dontAsk|plan>` · `--settings <file-or-json>` · `--add-dir` · `--restricted`(명령 실행 도구 · WebFetch 를 빼고 파일 도구를 작업 폴더로 가둔다 — 「unless --tools names them」) · `--session-id <uuid>`.
- 레포에 남은 사실: 「allowlist는 *도구 종류*를 막지 경로를 막지 못한다」 · 「플러그인 `settings.json` 이 `agent`·`subagentStatusLine` 키만 지원해 `permissions.deny` 로 경로를 막을 수단이 없」다(`docs/superpowers/specs/2026-08-05-agent-transparency-design.md:1096-1100` · `:736`). 이것은 **플러그인 설정** 얘기이고 세션을 띄울 때의 `--settings` · `--disallowedTools` 인자는 다른 길이다.
- 조사자 해석(재지 않음): `Edit(<경로>)` · `Write(<경로>)` 꼴의 막기는 파일 도구에만 걸리고 셸(`Bash` 의 `>` · `sed -i` · `git apply`)로 쓰는 길은 그대로일 것이다. 담당자는 git · 테스트에 Bash 가 필요하다. E1 이 `hc keys` 막기를 기각할 때 쓴 논리와 같은 꼴이다 — 「좁힌 금지가 직접 호출을 막는 것까지는 쟀으나, 감싼 호출은 재지 못했고 … 구멍을 따라다니게 된다」(`:343`).
