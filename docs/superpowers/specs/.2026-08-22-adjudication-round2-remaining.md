### #1 (block) — 축 C 가 자기 자신으로 만족된다
`disclosure=<리터럴>` 이 적힌 앵커 줄이 검색 대상 파일 안에 있어 검색이 앵커 자신에 걸린다.

**수정**: §4.1·§5.2 에 "축 C 의 검색 코퍼스에서 **모든 앵커 줄을 제외한다**" 명시. body-unique.

### #3 (high) — 축 A 의 ∀-지배가 앵커 공유를 막지 않는다
선례의 실제 의미는 "가장 가까운 가드가 창 40 안에" 라 앵커 하나가 구간 내 dispatch 여럿을 덮는다.
실측 인접 쌍: quality-pipeline/SKILL.md:366·:377(11줄) · conducting-interview/SKILL.md:254·:269(15줄) ·
audit-workflow.js:18·:19(인접). 축 B/C 가 앵커를 순회하므로 덮인 dispatch 는 교차확인을 통째로 빠져나간다.
**수정**: 축 A 를 두 단언으로 — (i) `앵커 수 == dispatch 수` (ii) 앵커→dispatch **1:1 매칭 존재**
(각 앵커는 어떤 dispatch 의 창 40 안이고, 한 앵커는 한 dispatch 에만 귀속). 추가로
**각 dispatch 줄은 정확히 한 에이전트에 귀속** 단언(경계 규칙의 진짜 계측기).

### #4·#5 (high) — 출력이 없어 mutation 을 관측할 수 없고, 등식의 근거가 없다
§5.3 이 내는 것은 에이전트 수·dispatch 수·--emit-scanned 뿐. M10 이 요구하는 축별 대상 수가 없다.
그리고 "둘 다 출력"이 인쇄인지 단언인지 미정 — 단언이면 `에이전트 수 == dispatch 수` 를 강제하는데
그 등식은 구조적 근거가 없다(오늘 18/18 은 에이전트당 dispatch 가 우연히 하나라서).
**수정**: §5.3 출력 = 에이전트 수 · dispatch 수 · **앵커 수** · **축별 대상 수(B/C)** · **에이전트별 dispatch 수**
· --emit-scanned. 단언은 `dispatch 수 == 앵커 수` 하나만(구조적 근거 = 1:1 계약).
`에이전트 수 == dispatch 수` 는 **걸지 않는다**.
**M7 재작성**: 코퍼스를 skills/ 로 축소하면 scripts/*.js 3건이 빠져 plugin-auditor·audit-refuter·
smoke-probe 가 dispatch 0건 → §5.1⑤ 로 RED. (등식이 아니라 per-agent 0 이 기제)
**M13 재작성**: 락 **자신의** 경계 규칙을 제거 → critiquing-artifacts/SKILL.md:194 가
adversarial·artifact-adversarial 두 에이전트에 동시 귀속 → "정확히 한 에이전트" 단언 RED.
(기존 M13 은 dispatch 줄 삭제라 경계 규칙 없이도 RED 라 계측기가 아니었다)
**M11 재작성**: #1 수정 후에는 구성 가능 — 앵커 밖 본문에 없는 리터럴로 교체 → 축 C RED.
