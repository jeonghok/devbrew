# R1 — 쓴소리 리뷰어 본체 · Design

> qg 안에 사용자가 고른 것 자체를 의심하는 읽기 전용 리뷰어를 PR 범위부터 세운다. 리뷰어는 실제로 돌려 본 근거로만 묻고, 질문은 판정 밖에 남고, 답은 부른 흐름에 돌려준다. qg 는 리뷰만 한다 — 고치지 않고, 커밋하는 것은 사용자의 답 파일뿐이다(U12).

## Context / Why

뿌리 문제는 사용자가 고른 것 자체를 의심할 자리가 없다는 것이다(D1). 지금 qg 리뷰어들은 의도 출처를 정답으로 놓고 그것을 어겼는지만 본다. 의도 출처는 `discover-spec.sh` 가 고른다 — Spec 트레일러 설계문서, 없으면 커밋 메시지와 열린 PR 본문이다(범위 모드는 PR 본문을 읽지 않는다). 인터뷰 원문은 어느 경우에도 읽지 않는다(K7 · RC28). 재비판자(`code-recritic`)는 「이 변경이 하지 않은 일을 하라는」 지적을 과잉 처방으로 낮춘다(RC17). 그래서 「이게 정말 의도가 맞냐」는 물음은 지금 구조상 나올 수 없다.

사용자는 잘못 골랐다는 것을 구현 뒤 써 보고, 또 로드맵을 다 끝내고 알아챘다(C2 · S3 · S23 — 셋째 「한참 뒤 다른 일 하다가」는 S23 에서 함께 골랐다). R1 은 그중 PR 하나의 자리를 맡는다. 에픽 머지 뒤 · 로드맵 끝의 자리는 R3 가, 넓은 걷기는 R2 가 맡는다.

설계 대화에서 사용자는 원칙 하나를 더 정했다 — **qg 는 리뷰에만 집중한다**(결정 기록 U5). qg 의 리뷰 뒤 고치기가 지휘 흐름의 구현 길과 갈라지므로, 쓴소리 단계는 묻고 답을 돌려주는 데서 끝나고 고침은 qg 밖에서 한다. 기존 고치기 반복을 걷어내는 일은 새 에픽 R4 로 나눴다(재분해 2026-11-14).

## Goals

- qg 에 쓴소리 리뷰어 agent 하나를 더한다 — 사용자가 고른 것(큰 방향 · 기능 · 동작)이 정말 의도가 맞는지 묻는다(C3 · C4).
- 리뷰어의 자리는 **사수**다 — 프로젝트 밖에서 「이 일이 정말 잘 되고 있나」를 보는 경험 많은 선배의 시선이다(U8). 의도 출처 안에서 규칙 위반을 찾는 심사자도, 늘 반대하는 역할도 아니다. 이 PR 이 프로젝트를 원래 가려던 곳으로 데려가는지, 돌려 본 근거로 묻는다.
- 리뷰어는 PR 하나를 포함한 qg 의 모든 범위에서 돈다(C7). R1 은 PR 범위와 범위 모드에서 지금 qg 가 가진 근거(걷기 기록 · 차등 테스트 결과)로 돈다.
- 쓴소리는 실제로 돌려 본 근거가 있을 때만 내고, 실행당 상한을 두고, 없으면 없다고 말한다(D11 · U1).
- 질문은 qg 판정을 바꾸지 않고 따로 남는다(C6).
- 의심할 원문은 직접 쓴 말과 고른 라벨을 갈라 보이고, 고른 라벨도 모델이 제안한 것으로 의심한다(D19).
- 답은 답마다 파일 하나로 남기고, 판단에 쓴 관찰이 달라졌다고 인용할 때만 다시 묻는다(D22).
- 답은 정해진 꼴로 부른 흐름에 돌려준다 — 이 꼴이 R2 · R3 · R4 가 받는 계약이다.

## Non-goals

- 넓은 걷기(에픽 · 로드맵 범위의 오케스트레이터 실행 · 범위 끝 커밋 worktree 걷기) — R2.
- 지휘자 경유 입구 · 에픽 · 로드맵 이름 풀이 · 자동 호출의 두 박자 · 게이트 사이 질문 옮기기 — R3.
- qg 의 기존 고치기 반복을 걷어내기 · 고칠 일을 지휘 흐름으로 넘기기 — R4.
- 쓴소리 질문으로 qg 판정(통과 · 막힘)을 바꾸기(S1).
- 쓴소리 예시 목록을 닫힌 점검표로 굳히기(C26).
- 머지된 에픽을 다시 열어 고치는 길(S15).

## Anti-goals

- 늘 반대하는 역할의 리뷰어 — 근거 없이 매번 뭔가 찾아내면 실패다(K2 · «devils-advocate» · «claude-best-practices»).
- 질문 범람 — 사용자가 「맞다」로 일괄 통과시키게 되면 채널이 죽는다(K10).
- 「의도다」 답에 근거와 무관하게 물러서거나, 답이 남지 않아 같은 질문을 다시 내는 것(K11 · «bugbot-forum»).
- qg 가 답을 받아 스스로 고치는 것(U4 · U5). 답 파일을 쓰고 커밋하는 것은 기록이지 고치기가 아니다(U12).

## Constraints

- 리뷰어는 읽기 전용이다 — `tools: Read, Grep, Glob`(Law 2 · K19 · RC1). 실행은 오케스트레이터가 이미 하는 것(걷기 · 차등 테스트)만 쓴다. 리뷰어에게 실행 도구를 주지 않는다는 것은 확정이 아니라 모델 추론으로 남아 있다(S29) — 이 설계는 R1 범위에서 실행 도구 없이 충분하다고 판단했다(근거: 결정 U1 이 근거를 이미 돌린 결과로 한정했다).
- 입구는 qg 하나다 — 쓴소리 단계는 `/quality-gates:quality-pipeline` 안에 있다(D13 · S28).
- 판정 불변은 구조로 지킨다 — 쓴소리 출력은 `findings.yaml` 과 `qg-verdict-args:` 어디에도 들어가지 않는다. `synthesize_findings.py` 는 받은 항목을 모두 판정에 올리고, 못 판정한 항목은 `not-certified (findings-lost)` 로 만든다(조사 §2 — `## 지휘 기록` 첫 줄의 설계 전 조사. 코드 자리는 `synthesize_findings.py` 의 `ledger.items_unaccounted()` → `review_blocked` → `verdict.py` 의 `findings-lost` 렌더) — 그래서 섞으면 판정이 바뀐다.
- qg 는 코드를 고치지 않는다(U4 · U5). 쓴소리 단계가 저장소에 쓰는 것은 답 파일 하나뿐이고, qg 가 그 파일만 골라 커밋한다(U12 — push 는 하지 않는다). 지금 qg 의 고치기 반복은 사용자가 허락한 지적에 대해 작업 트리 파일을 고치고 커밋은 하지 않는다 — 그 반복을 걷어내는 일은 R4 다.
- qg 세션 폴더는 다음 실행이 지우고 TTL 24시간 뒤 GC 된다(RC12) — 오래 남을 것은 그곳에 두지 않는다.
- 레포 전용 값(답 파일 docs 자리 · 테스트 명령 · 기본 브랜치)은 박지 않고 레포 설정이나 도출로 읽는다(CLAUDE.md).
- 새 책임은 따로 된 파일로 — qg 본문(`SKILL.md` 1683줄)에는 진입 몇 줄만 더한다.
- 플러그인을 건드리므로 `plugin.json` minor bump · CHANGELOG `Added` · README(agent 수 · kill switch 표) 를 같은 PR 에서 맞춘다.

## Approaches

| 길 | 무엇 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **1. qg 흐름 안의 한 단계, 절차는 따로 된 파일 (고름)** | 걷기 뒤 · 최종 판정 근처에 쓴소리 단계. 본문엔 진입 몇 줄, 절차 · 스크립트 · agent 는 새 파일 | 같은 실행 안에서 걷기 기록 · 차등 결과를 그대로 받는다. 입구가 하나다(S28 · S19) | qg 본문이 조금 길어지고 새 agent 락들을 맞춰야 한다 |
| 2. qg 뒤에 따로 부르는 skill | qg 결과 폴더의 걷기 기록을 읽어 쓴소리만 | qg 본문을 거의 안 건드린다 | 입구가 둘(S19 와 어긋남), 결과 폴더가 24시간 뒤 지워져 늦게 부르면 근거가 사라진다 |
| 3. 기존 리뷰어 넓히기 | 재비판자나 통합 리뷰어에 쓴소리를 맡김 | 새 agent 없음 | 둘 다 의도를 정답으로 놓는다 — 인터뷰에서 기각(RC24 · ST1) |

길 1 은 지휘자(작성자) 추천이고 사용자가 이의 없이 설계문서 작성으로 넘어갔다(결정 기록 「작성자 판단」).

## 설계

### §1 자리 — qg 흐름 안의 한 단계

- **언제 도나.** 리뷰 · 테스트 반복과 e2e 단계가 끝나고 `## Final verdict` 가 판정 줄을 만들어 보인 뒤, `## Publish` 까지 끝난 다음에 돈다(범위 모드처럼 게시를 건너뛰는 실행은 그 건너뜀 공시 다음). 판정 코멘트는 사용자의 답을 기다리지 않고 먼저 나간다. 판정 줄은 쓴소리 단계 전에 이미 정해져 있다 — 쓴소리 단계는 그 줄을 읽지도 고치지도 않는다.
- **근거가 없으면 agent 를 부르지 않는다(U9).** 근거가 있다는 것은 걷기 기록에 관찰이 있거나, 차등 테스트 결과에 통과로 끝나지 않은 귀속이 하나라도 있다는 뜻이다. 통과로 끝난 귀속은 셋이다 — `STILL_GREEN`(계속 통과) · `FIXED`(실패하다 통과) · `NEW_TEST_GREEN`(새 테스트가 통과). 이 셋만 있는 차등 결과는 근거 없음으로 본다 — 차등 테스트는 매 실행 돌고 PR 대부분이 통과하는 새 테스트를 더하므로, 이 셋을 근거로 치면 리뷰어가 사실상 늘 불린다. 그 밖의 귀속은 모두 근거다(지금은 `NEW_REGRESSION` · `NEW_TEST_RED` · `PRE_EXISTING` · `SILENT_DROP` · `BASELINE_UNRUNNABLE` — 스크립트는 통과 셋이 아닌 것을 근거로 치므로 모르는 새 귀속도 근거 쪽이다). 근거가 없으면 리뷰어 호출 없이 「쓴소리 — 근거 없음」 한 줄로 끝난다. 범위 모드 · 걷기 건너뛴 PR 은 대개 여기서 끝나 비용이 0 에 가깝다.
- **안 도는 때.** 멈춘(aborted) 실행 · trivia escape · 빈 필터 diff · kill switch(§4 끝). 안 돌면 그 사유 한 줄을 공시한다.
- **리뷰어가 실패하면.** 리뷰어가 죽거나 정해진 펜스 블록을 읽어 낼 수 없는 출력을 내면 한 번 다시 부른다. 또 실패하면 「쓴소리 — 리뷰어 출력을 읽지 못함(셀 수 없음)」 을 공시하고 끝난다 — 「근거 없음」 · 「질문 없음」 과 다른 글자다. 두 번 나눠 부를 때 둘째 호출만 끝내 읽지 못하면 첫째 호출의 후보로 이어 가고 그 사실(의심 대조 없이 첫째 후보만)을 공시한다 — 첫째 후보는 그 자체로 근거를 인용한 질문이다. 첫째 호출을 끝내 읽지 못하면 셀 수 없음이다. 판정 밖 단계라 판정은 막지 않는다(fail-open). dispatch 처분 줄은 `consumer=plugins/quality-gates/scripts/intent_critic.py · fail-open` 이고, 스크립트가 셀 수 없음을 공시한다.
- **범위.** PR 범위(session · topic · branch · paths)와 범위 모드 모두 돈다. 범위 모드는 e2e 가 없으므로 근거는 차등 테스트 결과뿐이다(§3).
- **출력 자리.** qg 세션 폴더의 쓴소리 파일들(§6)과 `result.md` 의 새 절 `## 쓴소리`. 이 절은 맨 끝(`## 게시` 뒤)에 덧붙인다(qg SKILL 의 Rules R2 — 덧붙이기만. 로드맵 에픽 R2 와 다르다). PR 코멘트에는 싣지 않는다 — 판정 밖 질문이 판정 코멘트에 섞이지 않게(SUGGESTION 이 PR 코멘트에 안 가는 지금 규칙과 같은 결).

### §2 받는 것 — 입력 칸

리뷰어 agent 의 입력 칸(`input_slots`)이 R2 · R3 가 받는 계약이다.

| 칸 | 종류 | 내용 |
|---|---|---|
| `project_dir` | task | 리뷰 트리(범위 모드면 끝 커밋 임시 트리) |
| `diff` | artifact | 이번 실행의 필터 diff |
| `evidence` | artifact | 돌려 본 근거 — 걷기 기록(`e2e-record.md`)과 차등 테스트 결과(`differential.yaml`)를 줄 번호 붙여 한 파일로. 걷기 근거 파일 꼴이 R2 에서 넓어져도 이 칸 이름은 그대로다 |
| `origin` | artifact | 의심할 원문 — 직접 쓴 말(🗣)과 고른 라벨(☑)을 갈라 보인 목록과 확정 항목. 열린 질문 · 위험은 싣지 않는다(`doubts` 몫). 없으면 「원문 없음 — <이유>」 한 줄 |
| `roadmap` | artifact | 그 일이 속한 로드맵(U10) — 원문을 찾을 때 연 설계문서 · 묶음의 frontmatter `roadmap:` 을 아래 ② 의 경로 신뢰 경계로 따라가 통째로 싣되, 아래 「첫 호출은 내용으로 가른다」(D2.4)를 똑같이 적용한다 — 로드맵의 위험 줄 · 열린 질문 · 「다시 검증할 것」 문단은 첫 호출에서 빼 둘째 호출의 `doubts` 로 옮긴다. 리뷰어는 이것으로 로드맵 방향에 비춰 묻지만, 그 질문도 `evidence` 를 인용해야 한다(§3). 없으면 「로드맵 없음 — <이유>」 한 줄 |
| `intent` | artifact | qg 가 이미 고른 의도 출처(`intent.md`) — 원문과 다른 것임을 칸 이름으로 가른다 |
| `doubts` | artifact | 둘째 호출에만 — 인터뷰가 남긴 의심(묶음 §5 위험 · §3 열린 질문)과 첫째 호출의 후보 |
| `answered` | repo_context | 이미 답한 질문들의 정체와 답(§5) — 같은 것을 다시 내지 않게 |

**원문을 어디서 찾나(순서).**
1. 부른 쪽이 넘긴 원문 — qg 인자로 원문 파일 경로를 받는 자리를 둔다. R3(지휘자)와 옆 세션의 INTENT.md 가 이 자리를 쓴다(S10 · S20 — 이음매만 열어 둠).
2. 없으면 의도 출처가 Spec 트레일러 설계문서일 때 그 문서 frontmatter `source_interview` 를 따라가 묶음이나 brief 를 연다(RC81 — 지금 쓰이지 않는 링크를 쓴다). 자동으로 따라가는 링크에는 `discover-spec.sh` 의 경로 신뢰 경계를 그대로 쓴다 — 저장소 밖 경로 · 링크(symlink) · 추적되지 않는 파일은 거부하고, 리뷰한 버전(PR 범위는 리뷰 트리, 범위 모드는 끝 커밋)의 파일을 읽는다. 거부하면 이유만 공시하고 내용은 입력에 넣지 않는다. ① 의 부른 쪽 원문은 부른 쪽이 고른 것이라 이 자동 링크 경계와 따로, 저장소 안의 추적 파일만 받는다. 묶음 §6 · brief §6 의 🗣 · ☑ 표지가 이미 직접 쓴 말과 고른 라벨을 가른다(RC80).
3. 둘 다 없으면 `origin` 은 「원문 없음 — <이유>」 이고, 쓴소리는 diff · 근거만으로 본다(S28 — 로드맵 없는 PR 은 원문이 없으면 없다고 밝힌다 · K8).

**원문 · 의심을 어떻게 뽑나.** 스크립트는 묶음 · brief 를 제목으로 잘라 절을 통째로 넘긴다 — 원문 절(묶음 `## 6. 사용자 원문` · brief §6), 확정 절(묶음 `## 2. 제약` · brief §2), 의심 절(묶음 `## 5. 기각 · 위험` · `## 3. 열린 질문`, brief §5 · §3). 🗣 · ☑ 표지는 줄 단위로 알아보고 그대로 둔다(리뷰어가 읽는다). 절을 못 찾거나 표지가 없는 옛 문서면 파일 전체를 넘기고 「직접 쓴 말 · 고른 라벨을 가르지 못함」 한 줄을 공시한다 — 원문 없음으로 내리지 않는다.

**두 번 나눠 부른다(D13 · S33).**
1. 첫째 호출 — `doubts` 없이. 근거와 원문만 보고 쓴소리 후보를 낸다.
2. 둘째 호출 — 첫째 후보와 인터뷰가 남긴 의심을 `doubts` 로 주고, 의심을 **반증할 가설**로 대조하게 한다(확증 쪽으로 기우는 것을 막는다 · K5 · «failing-falsify»). 의심 가운데 근거로 뒷받침되는 것만 후보에 더한다.
3. 의심 목록이 없으면(로드맵 없는 PR) 둘째 호출을 하지 않는다.
4. 두 호출 입력(근거 · 원문 · 의심)의 합이 리뷰어 입력 상한을 넘으면 처음부터 한 번에 넣되 반례를 찾게 한다 — D13 의 예외 갈래. 상한은 바이트 수로 재는 레포 설정 값이고(키 이름과 기본값은 계획이 정한다), 스크립트가 시작 전에 재서 갈래를 고르고 그 판단과 잰 값을 공시한다.
5. **첫 호출은 내용으로 가른다.** 칸 이름만 가르지 않는다 — 원문 절 안에도 의심이 들어 있을 수 있다(예: 최초 요청 seed 끝의 「다시 검증할 것 —」 문단). 스크립트는 첫 호출의 `origin` · `intent` 에서 의심을 담은 부분을 빼고 둘째 호출의 `doubts` 로 옮긴다: 「다시 검증할 것」 으로 시작하는 문단, 묶음 · brief 의 위험 · 열린 질문 절, 의도 출처 문서의 제목이 위험 · 기각 · 열린 질문(또는 Risk · Rejected · Open Questions)인 절. 그래서 첫 호출에는 선택 · 요구(직접 쓴 말 · 고른 라벨 · 확정 · 목표)만 간다.
6. 이렇게 가를 수 없는 입력(절을 못 찾은 옛 문서의 파일 전체 갈래)은 문서가 새것이어도 첫 호출부터 의심이 함께 들어간다 — 이 예외는 「첫 호출에 의심이 섞였다」 로 공시한다. 위 표지로 잡히지 않는 의심은 스크립트가 알아챌 기준이 없어 첫 호출에 남는다(의도된 약함 — 공시하지 못한다).

### §3 근거와 상한

- **근거는 돌려 본 것만(U1 「가」).** 질문마다 `evidence` 의 줄을 하나 이상 인용해야 한다 — 걷기 몇 번째의 관찰 · 차등 테스트의 어느 결과. 코드만 읽어서 본 것은 근거가 아니다(«coderabbit-study» — 근거 없는 지적은 의도된 선택을 결함으로 몰기 쉽다). 로드맵 · 스펙 방향을 묻는 질문도 같다(U10) — 로드맵은 비춰 볼 자리이지 근거가 아니다. 근거 없이 방향만 지적하는 조언 칸은 두지 않는다.
- **스크립트가 거른다.** 인용이 없거나 인용한 줄이 `evidence` 에 없는 질문은 버리고 그 수를 센다(소실이 아니라 거름 — 「근거 없어 거름 <n>」 공시).
- **근거가 없으면** 질문 없이 「쓴소리 — 근거 없음」 한 줄이다. 걷기를 건너뛴 PR · 범위 모드는 대개 여기서 끝난다 — 의도된 결과다.
- **상한은 실행당 3(«ask-less»).** 넘는 후보는 버리지 않고 개수만 공시한다(「상한 넘어 남김 <n>」). 고르는 기준은 리뷰어가 매긴 무게(방향 > 기능 > 동작)이고, 남긴 것은 `result.md` `## 쓴소리` 에 목록으로 적는다 — 묻지 않을 뿐 숨기지 않는다.
- **늘 반대하지 않는다.** 리뷰어 페르소나는 쓴소리가 없으면 없다고 말하는 것을 정상 결과로 둔다. 예시(잘못된 방향 · 더 단순한 길 · 써 보면 빠진 기능 · 조용히 줄어든 범위 …)는 느낌을 보이는 것이지 점검표가 아니다(C26).

### §4 묻기 · 답 · 돌려주기

- **묻기(D16 · S12).** PR 범위 실행이면 qg 를 돌리는 세션에서 `AskUserQuestion` 한 번에 묻는다(질문 최대 3) — qg 의 다른 게이트(낮춘 지적 · 고치기 반복 · e2e)와 같이 대화형 세션을 전제한다. 질문마다 의심하는 것(어느 원문 · 어느 선택 — 직접 쓴 말인지 고른 라벨인지), 근거로 본 것을 쓴다.
- **범위 모드는 묻지 않는다(D2.6).** 범위 모드는 지금 지휘자가 로드맵 끝에 자동으로 부르는 길이라, R1 은 그 실행에서 묻기를 건너뛰고 모든 질문을 「아직 묻지 않음」 상태로 돌려주는 꼴에 싣고 `result.md ## 쓴소리` 에 목록으로 남긴다. 쌓인 질문을 게이트 사이에 묻는 일은 R3 가 이어받는다. R3 전까지는 그 질문을 읽는 곳이 없어, 질문은 세션 폴더와 함께 다음 실행이나 24시간 뒤 사라진다 — 정직하게 남기는 공백이고 `## 미룸` 의 R3 행에 싣는다(U11).
- **답 셋.** 「의도다」 · 「잘못 골랐다」 · 「지금은 모르겠다」(기록하되 다음에 다시 물을 수 있다). 이유는 질문 도구의 직접 입력 칸으로 받는다 — 질문 글에 「이유를 남기려면 직접 입력 칸에 「의도다 — 이유」 처럼 쓴다」 를 싣고, 스크립트는 입력 글의 맨 앞이 답 셋 중 하나면 그 답으로, 아니면 「지금은 모르겠다」 로 읽는다(거르지 않는 쪽 — 안전한 기본). 입력 글은 어느 경우든 답 원문으로 그대로 남긴다. 추천 표시는 달지 않는다 — 사용자의 선택을 의심하는 질문에 모델이 답을 권하면 그 자체가 라벨 유도다(«jakesch»).
- **답 파일(U12).** 답마다 파일 하나를 작업 트리의 docs 답 자리(레포 설정에서 읽은 폴더)에 바로 쓰고, qg 가 그 파일만 경로를 지정해 지금 브랜치에 커밋한다 — 다른 변경은 커밋에 넣지 않고, push 는 하지 않는다. 담는 것: 질문 정체(§5) · 질문 · 답 원문 · 근거로 본 관찰 · 대상(PR 하나는 리뷰한 트리의 해시 — 그 해시를 계산할 때 docs 답 자리의 답 파일은 뺀다 — 기록만, S30 · S35). 커밋이 실패하면 파일은 둔 채 그 사유를 공시하고, 완료 보고의 할 일 줄이 그 파일을 커밋하라고 안내한다. 묻는 실행은 PR 범위뿐이라 범위 모드는 답 파일을 쓰지 않는다. 세션 폴더에 초안을 두지 않는다 — 다음 실행이 세션 폴더를 지워 초안은 읽힐 수 없었다. 다음 실행의 리뷰 diff 에 답 파일 커밋을 넣을지는 계획이 정한다.
- **돌려주는 꼴.** 완료 보고 끝에 정해진 블록 하나를 낸다 — 질문마다 정체 · 상태(답함 · 아직 묻지 않음 · 상한 넘어 남김) · 답 · 답 파일 경로 · 그 커밋(또는 커밋 실패 사유), 그리고 docs 답 자리(레포 설정에서 읽은 값). 부른 흐름은 이 블록을 읽어 「잘못 골랐다」 를 이어 고친다 — 답 파일을 옮기거나 커밋할 일은 없다.
- **「잘못 골랐다」(U3).** 돌려주는 꼴에 표시만 한다 — qg 는 고치지 않는다.
  - qg 를 바로 부른 세션(로드맵 없는 PR)이면 완료 보고의 할 일이 「같은 브랜치에서 이어 고치기」 다. D13 · S31 의 「docs 파일에 남기고 다음 할 일만 안내」 를 U3 이 바꿨다.
  - 지휘자를 거친 호출이면 같은 브랜치에서 고칠지 새 에픽을 열지는 지휘 흐름이 정한다 — R3 · R4.
- **kill switch.** `DEVBREW_QUALITY_GATES_DISABLE_INTENT_CRITIC=1` 이면 쓴소리 단계 전체를 건너뛰고 「쓴소리 꺼짐(kill switch)」 한 줄을 공시한다. 판정에는 닿지 않는다 — 판정 밖 단계이므로 `not-certified` 사유가 아니다.

### §5 다시 묻지 않기

- **읽기.** 쓴소리 단계를 시작할 때 리뷰 트리(`project_dir` — 범위 모드면 끝 커밋 임시 트리)의 docs 답 자리 답 파일을 읽어 `answered` 칸으로 준다(U12 — 답은 바로 docs 에 커밋되므로 따로 읽을 초안이 없다). 답 파일이 PR 브랜치에 커밋돼 PR 과 함께 머지되므로 병렬 브랜치끼리 한 파일을 두고 부딪히지 않는다(K15 · RC84 · «gitlab-changelog»).
- **질문 정체(키).** 「출처 + 무엇을 의심하나 + 의심의 종류」 다 — 출처는 원문을 담은 문서의 저장소 경로(묶음이면 그 묶음의 원본 brief 경로로 이어 같은 선택이 같은 출처가 되게 한다), 무엇은 그 출처의 원문 번호(C · D · S 번호)나 원문이 없으면 의심하는 파일 경로다. 다른 인터뷰의 같은 번호는 출처가 달라 다른 정체다. 리뷰어가 인용한 의심하는 선택 구절은 키에 넣지 않고 질문 글과 답 파일에 기록으로만 남긴다(D2.5) — 인용 범위가 조금 달라도 같은 질문이 다른 질문이 되지 않게. 같은 항목 · 파일에 대한 같은 종류의 다른 질문을 가르는 일은 아래 「같은 질문」 칸이 맡는다.
- **거르는 자리는 스크립트 하나다(D2.5).** 리뷰어는 `answered` 를 보고도 후보를 스스로 빼지 않는다. 이미 답한 질문과 같다고 보면 그 답 파일의 정체를 `같은 질문: <정체>` 칸으로 적어 낸다. 스크립트는 그 칸이 있고 그 정체의 답 파일이 실재하며 후보의 정체(출처 · 무엇 · 종류)와 맞을 때만 거르고 수를 센다. 칸이 없으면 같은 정체여도 다른 질문으로 보고 묻는다. 종류는 닫힌 작은 어휘(방향 · 빠진 기능 · 쓰이지 않을 기능 · 범위 축소 · 모호한 말 굳힘 · 앞 결정 뒤집힘 · 기본값 · 조용한 실패 · 마찰 · 기타)다. 대상(커밋 · 트리 해시)은 키에 넣지 않는다(S35). 좌표(파일 · 줄 · 심각도)만으로 짝짓지 않는다 — qg 의 좌표 키가 다른 결함을 흡수한 전례가 있다(RC94).
- **정체는 리뷰어가 칸으로 낸다.** 리뷰어는 질문마다 정해진 칸(의심 대상 · 종류 · 근거 줄 · 관찰이 바뀌었다는 인용)을 펜스 블록으로 내고, 스크립트는 그 값을 글자로 비교한다 — 자유문에서 추론하지 않는다. 「관찰이 바뀌었다」 는 이전 답 파일의 관찰 글과 지금 `evidence` 의 줄을 둘 다 인용해야 인정한다(둘 다 실재하는지만 스크립트가 본다). 칸이 빠졌거나 모양이 틀리면 그 질문은 「정체를 가르지 못함」 으로 거르지 않고 묻는다.
- **「잘못 골랐다」 답도 같은 규칙으로 거른다.** 고치는 동안 같은 질문을 매 실행 다시 받지 않게, 같은 정체에 「잘못 골랐다」 답이 있으면 관찰이 바뀌었다는 인용이 있을 때만 다시 낸다. 거른 「잘못 골랐다」 질문은 `result.md ## 쓴소리` 에 목록으로 남겨 고칠 일이 보이게 한다. 단위 테스트에 이 경우를 넣는다.
- **거르기.** 「같은 질문」 칸이 가리킨 답이 「의도다」 면 스크립트가 그 질문을 거른다. 다만 판단에 쓴 관찰이 달라졌다고 이전 답의 관찰과 지금 근거 줄을 함께 인용하면 다시 낸다(D22 · «sonarqube-match» · «copilot-memory»). 「지금은 모르겠다」 답은 거르지 않는다.
- **확실히 가르지 못하면 다시 묻는다.** 정체가 같은지 스크립트가 판정하지 못하면 거르지 않고 묻는 쪽을 택한다 — 조용히 사라지는 쪽보다 한 번 더 묻는 쪽이 덜 위험하다.
- **조용히 거르지 않는다.** 거른 수를 「이미 답한 질문이라 거름 <n>」 으로 공시한다(K16 · RC89 — 억제가 썩지 않게 드러낸다).

## Acceptance Criteria

- **AC1** 새 agent `quality-gates:intent-critic` 이 있다 — `tools: Read, Grep, Glob` 만, `model` 키 없음, 색 · `cost_class` · `input_slots`(§2 칸 여덟)를 선언하고 첫머리에 맡는 일(고른 것 자체를 근거로 의심해 묻는다)과 맡지 않는 일(판정 · 고치기)을 밝힌다.
- **AC2** 페르소나가 사수 자리(밖에서 「프로젝트가 정말 잘 되고 있나」를 보는 선배 — U8)와 §3 의 규칙을 담는다 — 근거 인용 필수, 근거 없으면 「없음」이 정상, 예시는 닫힌 목록이 아님, 직접 쓴 말과 고른 라벨을 구분해 의심, 의도 출처를 정답으로 삼지 않음.
- **AC3** qg 흐름에 쓴소리 단계가 있다 — 판정 줄을 만들어 보이고 게시(또는 게시 건너뜀 공시)까지 끝난 뒤에 돌고, 근거가 없으면(걷기 관찰이 없고 차등 결과가 모두 통과로 끝난 귀속 `STILL_GREEN` · `FIXED` · `NEW_TEST_GREEN` — U9) agent 를 부르지 않고 「쓴소리 — 근거 없음」 으로 끝나며, 멈춘 실행 · trivia · 빈 diff · kill switch 에서는 사유 한 줄을 공시하고 돌지 않는다. qg 본문에는 진입과 공시 몇 줄만 있고 절차는 따로 된 파일에 있다.
- **AC4** 판정 불변 — 쓴소리 단계를 켜고 끈 두 실행에서 판정 줄이 같다. 쓴소리 출력은 `findings.yaml` · `qg-verdict-args:` · PR 코멘트에 들어가지 않는다(검사로 잠근다).
- **AC5** 입력 칸 — `evidence` 는 걷기 기록과 차등 결과를 줄 번호와 함께 싣고, `origin` 은 ① 부른 쪽 원문 ② `source_interview` 를 따라간 묶음 · brief(🗣 · ☑ 갈라 보임) ③ 「원문 없음 — <이유>」 순서로 채우며, `roadmap` 은 frontmatter `roadmap:` 을 같은 경로 신뢰 경계로 따라가 싣거나 「로드맵 없음 — <이유>」 다(U10).
- **AC6** 두 번 나눠 부른다 — 첫째 호출에는 `doubts` 가 없고, 의심 목록이 있을 때만 둘째 호출에 첫째 후보와 의심을 반증 가설로 준다. 한 번에 넣는 예외 갈래를 탔으면 공시한다.
- **AC7** 근거 거름 — 근거 인용이 없거나 인용 줄이 `evidence` 에 없는 질문은 스크립트가 버리고 「근거 없어 거름 <n>」 을 공시한다. 남은 질문이 없으면 「쓴소리 — 근거 없음」 한 줄이다.
- **AC8** 상한 — 실행당 질문 3. 넘는 후보 수를 공시하고 `result.md ## 쓴소리` 에 목록으로 남긴다.
- **AC9** 묻기 — PR 범위 실행에서 판정을 보인 뒤 `AskUserQuestion` 한 번(질문 최대 3, 답 셋 「의도다」 · 「잘못 골랐다」 · 「지금은 모르겠다」, 추천 없음). 범위 모드 실행은 묻지 않고 질문을 모두 「아직 묻지 않음」 으로 돌려준다. `shared/tests/fixtures/ask-sites.tsv` 에 그 자리의 행이 있다.
- **AC10** 답 파일 — 답마다 파일 하나가 docs 답 자리에 생기고(질문 정체 · 질문 · 답 원문 · 관찰 · 대상 기록) qg 가 그 파일만 경로 지정으로 지금 브랜치에 커밋한다(다른 변경은 넣지 않음 · push 없음). 커밋이 실패하면 파일을 둔 채 사유를 공시한다. 세션 폴더 초안은 없다(U12).
- **AC11** 돌려주는 꼴 — 완료 보고 끝에 정해진 블록 하나(질문마다 정체 · 상태 · 답 · 답 파일 경로와 커밋, docs 답 자리)를 낸다. 「잘못 골랐다」 는 표시되고, 바로 부른 세션이면 할 일이 「같은 브랜치에서 이어 고치기」 다.
- **AC12** 다시 묻지 않기 — 거르기는 스크립트 한 곳에서만 한다. 리뷰어가 「같은 질문」 칸으로 가리킨 답 파일이 실재하고 정체(출처 · 무엇 · 종류)가 맞을 때만, 그 답이 「의도다」 · 「잘못 골랐다」 인 질문을 거르고 「이미 답한 질문이라 거름 <n>」 을 공시한다. 관찰이 바뀌었다는 인용이 있으면 다시 묻고, 정체를 가르지 못하면 거르지 않는다. 「지금은 모르겠다」 는 거르지 않는다.
- **AC13** docs 답 자리는 레포 설정에서 읽고 기본값을 둔다 — 경로를 박지 않는다.
- **AC14** kill switch `DEVBREW_QUALITY_GATES_DISABLE_INTENT_CRITIC=1` — 쓴소리 단계를 건너뛰고 공시하며 판정에 닿지 않는다. SKILL `## kill switch` 와 README kill switch 표에 있다.
- **AC15** 범위 모드 — e2e 없이 차등 결과만 근거로 돌고, 묻지 않고 질문을 모두 「아직 묻지 않음」 으로 돌려주며 `result.md ## 쓴소리` 에 남긴다. 그 실행에서도 판정 불변(AC4)이다.
- **AC16** 레포 락 — dispatch 처분 줄 · 입력 칸 선언 · frontmatter 키 · 모델 비고정 · 색 · 이름 해석 · 질문 자리 락이 모두 통과하고, README 의 agent 수 문장 · `plugin.json` minor bump · CHANGELOG `Added` 가 맞는다.

## Rejected Alternatives

- 따로 부르는 skill(Approaches 2) — 입구가 갈라지고 근거가 24시간 뒤 사라진다.
- 재비판자 · 통합 리뷰어 넓히기(RC24 · ST1) — 의도를 정답으로 놓는 역할과 부딪힌다.
- 질문 · 답을 qg 결과 폴더에만 두기(RC12) — TTL 로 지워진다. 답은 docs 에 바로 쓴다(U12).
- 답 초안을 세션 폴더에 두고 부른 흐름이 옮기기 · 실행을 넘어 남는 초안 폴더(U12) — 앞은 다음 실행이 지워 초안이 읽히지 않고, 뒤는 CLAUDE.md 의 상태 수명 넷에 없는 새 수명을 만든다.
- 좌표 키로 답 억제(RC94) — 다른 질문을 흡수한다.
- qg 가 「잘못 골랐다」 를 스스로 고치기(U4 · U5) — qg 는 리뷰만 한다. 답 파일 커밋은 기록이라 이 금지에 들지 않는다(U12).
- 근거 없는 방향 조언 칸(U10) — 리뷰어가 매 실행 불려 늘 무언가 지적하는 리뷰어(K2)가 된다.
- 차등 결과 파일이 있기만 하면 부르기(U9) — 차등 테스트는 매 실행 돌아 리뷰어가 사실상 늘 불린다.
- `STILL_GREEN` 이 아닌 귀속이면 모두 근거로 보기(U9) — `FIXED` · `NEW_TEST_GREEN` 은 실패가 아닌데 PR 대부분이 통과하는 새 테스트를 더해 리뷰어가 사실상 늘 불린다. 사용자가 고른 「실패·관찰 있을 때만」 과 어긋난다.
- 쓴소리를 지적(SUGGESTION)으로 섞기 — 판정 합성에 올라 판정을 바꿀 수 있다(Constraints).
- 코드 읽기만으로 쓴소리(U1 「나」) — 「돌려 본 근거」 기준이 흐려진다.
