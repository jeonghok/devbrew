# R2 — 넓은 탐색 걷기 · Design

> 쓴소리 리뷰어의 근거를 실제로 써 보며 모은다. 기대 상태 없이 걷고 본 것만 적는 탐색 걷기를 확인 걷기 옆에 따로 두고, PR 하나에는 얹고 에픽 · 로드맵에서는 넓게 걷는다. 탐색에서 본 것은 qg 판정에 닿지 않는다.

## Context / Why

사용자가 처음 쓴 말은 「이게 진짜 의도가 맞는지 … 찾아 나에게 탐색해(실제 돌려봐) 질문을 하는 리뷰어」 다. R1 이 그 리뷰어(쓴소리 리뷰어)를 세웠고, 리뷰어는 실제로 돌려 본 것만 근거로 삼는다(R1 U1). 그런데 지금 qg 가 「실제로 돌려 본 것」 으로 가진 것은 둘뿐이다.

- **차등 테스트 결과.** 통과로 끝난 결과만 있으면 근거가 아니다(R1 U9).
- **확인 걷기 기록.** 의도 출처가 약속한 동작만 기대 상태로 두고 통과 · 실패를 가린다(`plugins/quality-gates/references/e2e.md` 1 절 — 「의도 출처에 없는 동작을 기대 상태로 만들지 않는다」). 시나리오는 셋까지, 표면은 웹 UI · API · CLI 뿐이고, 범위 모드(에픽 · 로드맵)에서는 걷지 않는다.

그래서 사용자가 쓴소리의 예로 든 「써 보면 당연히 필요한데 빠진 기능」 · 「써 보면 생기는 마찰」 은 지금 장치로는 찾을 수 없다 — 둘 다 의도 출처에 적혀 있지 않은 것이다. skill 을 써 보는 길, 다른 세션 · 에픽의 작업을 읽는 길, 사람이 직접 써 볼 자리를 싣는 칸도 없다.

R2 는 이 빈자리를 채운다. R1 의 리뷰어 · 판정 · 답 기록은 건드리지 않고, 리뷰어가 읽는 근거를 넓힌다.

## 원문 대조

사용자가 직접 쓴 말과 고른 답에서 출발한다(원문은 framing 기록 `docs/superpowers/interview/2026-11-14-qg-epic-roadmap-intent-review-interview.audit.md` 1 · 2 절과 묶음 §6). 「바꿈」 은 이유를 적고, 사용자가 답하지 않은 지휘자 제안은 「제안」 으로 표시한다.

| 원문 | 설계 | 그대로 / 바꿈 | 근거 |
|---|---|---|---|
| 「탐색해(실제 돌려봐) 질문을 하는 리뷰어」 | 탐색 걷기가 본 것을 리뷰어 근거 칸에 넣는다 | 그대로 | §1 · §5 |
| 「기능을 실제로 써보기, 테스트·스크립트 실행, 모델 판단」(셋 다 고름) | 써 보기 = 탐색 걷기(웹 · API · CLI · skill) · 테스트 실행 = 있는 차등 테스트 · 무엇을 걸을지는 모델이 고른다 | 그대로 | §2 · §4 |
| 「그리고 옆 세션 구현하는거도 파악해줘야겠어」 → 「이 일의 입력으로, 리뷰어의 능력으로」 | 동시 작업 읽기 — 겹치는 파일의 내용까지 | 그대로(깊이는 U6) | §6 |
| 「PR 하나에서도」 · 「에픽·로드맵 단위에서는 더 넓게 본다」 | PR 은 확인 걷기 승인에 얹고, 에픽 · 로드맵은 탐색이 주된 걷기 | 그대로(U2) | §2 |
| 「판정 밖 — 질문만」 | 탐색에서 본 것은 판정 인자에 닿지 않는다 | 그대로(U1) | §1 |
| 「돌리기 전 사람 승인」(S7) | 이 컴퓨터에서 실행하는 명령은 글자 그대로 보이고 고른 것만 돌린다 | 그대로 | §2 |
| 「규모 공시 + 승인이 상한」(S13) | 시작 전 규모 한 줄 · 걷기마다 고르기 · 숫자 상한 없음 | 그대로. 뒤따르는 제안 묶음의 횟수만 기본 상한을 둔다(제안) | §2 |
| 「질문 전까지 모델, 그 뒤 사람」(S9) | skill 은 헤드리스 실행 한 번으로 첫 질문까지 걷고, 그 뒤는 사람 자리 | 그대로 | §4 · §7 |
| 「모델이 먼저, 사람 자리를 짚음」(S5) | 걷기 기록의 사람 자리 → 실행 끝 목록 | 그대로 | §7 |
| 「지금은 git, 채널 생기면 그것도」(S11) | 브랜치 · worktree · 열린 PR 을 읽고 못 본 것은 「확인 못 함」 | 그대로 | §6 |
| 「qg 걷기, /verify 는 사람 자리」(S27 — 「재 본 뒤의 /run 포함」) | `/verify` 는 사람 자리로 짚는다. `/run` 은 모델이 부르지 않고 그 skill 파일을 명령 출처로 읽는다 | **바꿈(사용자 확인 필요)** | `/run` 은 띄울 명령을 스스로 정해 「명령을 글자 그대로 보이고 승인받는다」(S7)를 지킬 수 없다 — §4 |
| 「알리고 넘어가는게 아니라 나한테 허락을 받음 되지」(U4) | 임시 폴더에 커밋에 없는 것이 없어 띄우지 못하면 가져와도 되는지 묻는다 | 그대로 | §3 |

## Goals

- 기대 상태 없이 써 보고 본 것만 적는 탐색 걷기를 qg 에 둔다(U1).
- PR 하나에서는 확인 걷기 승인에 탐색 후보를 얹고, 에픽 · 로드맵(범위 모드)에서는 탐색을 주된 걷기로 넓게 걷는다(U2).
- 범위 모드의 탐색은 끝 커밋 임시 폴더에서 걷는다(U3).
- skill 을 표면으로 더한다 — 첫 질문까지 모델이 걷는다(D14).
- 다른 브랜치 · 열린 PR 이 같은 파일을 고치는지 읽어 근거에 싣는다(C8 · D15 · U6).
- 사람이 직접 써 볼 자리를 실행 끝에 목록으로 짚는다(D10).
- 탐색에서 본 것 · 동시 작업 · 사람 자리를 R1 의 근거 칸과 결과 표시에 넣는다.

## Non-goals

- 쓴소리 리뷰어의 판단 규칙 · 질문 상한 · 답 기록(R1).
- 지휘자가 에픽 머지 뒤 · 로드맵 끝에 자동으로 부르기와 두 박자 잇기(R3) — R2 는 경계만 둔다(§8).
- qg 고치기 반복 걷어내기(R4).
- 확인 걷기의 규칙 · 판정 칸을 바꾸는 것.
- 리뷰어 agent 에 실행 도구를 주는 것 — 실행은 오케스트레이터가 하고 리뷰어는 읽기 전용이다(R1 K19 · S29 의 모델 추론을 이 설계가 다시 보고 그대로 둔다. 이유: 실행은 사람 승인을 받아야 하고, 질문 도구가 없는 하위 agent 는 승인을 받을 수 없다).

## Anti-goals

- 탐색에서 본 것이 qg 판정(통과 · 막힘)을 바꾸는 것(U1).
- 모델이 승인받지 않은 명령을 이 컴퓨터에서 실행하는 것(D12 · K13).
- 실행 격리 장치를 크게 세우는 것(RC13 — 격리가 목적이 돼 폐기한 전례).
- 모델이 대신 써 본 것으로 사람이 써 보는 것을 대신했다고 하는 것(K1 · «sim-users»).
- 확인 걷기의 통과 · 실패가 쓴소리의 근거로 읽히는 것(K12 · R1 K17).

## Constraints

- **판정 불변.** 탐색 걷기 · 동시 작업 읽기 · 사람 자리는 `qg-verdict-args` 와 `findings.yaml` 을 쓰지 않는다. 확인 걷기의 e2e 칸은 탐색이 시작되기 전에 정해진다(§1).
- **승인 경계(D12).** 이 컴퓨터에서 실행하는 명령은 레포 파일에서 읽은 것(출처 줄을 단다)이거나 이 설계가 정한 고정 틀(skill 걷기 · §4)뿐이다. 글자 그대로 보이고, 고른 것만 실행한다. 추천을 달지 않는다(지금 `e2e.md` 2 절과 같다).
- **읽기 전용 리뷰어.** 리뷰어는 오케스트레이터가 남긴 기록 파일만 읽는다(R1).
- **비밀 값.** 걷기 기록에 `.env` 같은 파일의 내용을 인용하지 않는다(CLAUDE.md 「Secret 기록 금지」).
- **레포 전용 값 금지.** 기본 브랜치 · 답 자리 · 상한 · 헤드리스 모델은 도출하거나 레포 설정에서 읽는다.
- **kill switch.** 새 스위치를 만들지 않는다. 탐색 걷기는 걷기 스위치(`DEVBREW_QUALITY_GATES_DISABLE_E2E`)나 쓴소리 스위치(R1 이 만든 것)가 켜져 있으면 돌지 않고, 동시 작업 읽기는 쓴소리 스위치를 따른다. 플러그인 전체 스위치는 둘 다 끈다. 안 돌면 사유 한 줄을 공시한다.
- **경로 예약.** R2 예약은 `plugins/quality-gates/references/e2e.md` · `plugins/quality-gates/scripts/` 다. R1 이 만든 파일(쓴소리 절차 · 리뷰어 정의 · 근거 조립 스크립트)과 R4 가 예약한 `SKILL.md` · `README.md` 를 고쳐야 한다 — R1 은 먼저 머지되고 R4 는 뒤에 오므로 머지 순서로 푼다(정보 · `## 미룸`).

## Approaches

세 가지를 견줬고 사용자가 1 을 골랐다(U7).

1. **들어가는 자리 둘, 절차는 따로 된 파일 하나(고름).** 탐색 절차를 새 파일 하나에 적고 qg 본문에는 들어가는 줄만 둔다. PR 은 확인 걷기 승인에 얹어 이미 띄운 앱에서 이어 걷고, 범위 모드는 쓴소리 단계 맨 앞(R1 이 끝 커밋 임시 폴더를 다시 만드는 자리)에서 걷는다. 값: R1 이 만든 파일 둘과 qg 본문을 고쳐야 해 구현은 R1 머지 뒤다.
2. **지금 걷기 문서와 기록 안에서 넓히기.** 짓는 양은 가장 적지만 확인 기록과 탐색 기록이 한 파일에 섞여 「기록을 가른다」 와 어긋나고, qg 본문이 더 길어진다.
3. **탐색을 늘 판정 뒤에.** 구조는 가장 단순하지만 PR 에서 앱을 두 번 띄우고 승인이 늘어 「PR 은 얹어서」 와 어긋난다.

## 설계

### §1 두 걷기의 사이

| | 확인 걷기(지금 것) | 탐색 걷기(새것) |
|---|---|---|
| 기대 상태 | 의도 출처가 약속한 동작 | 없음 — 걸을 목표만 |
| 결과 | 증거표 → 통과 · 실패 · 미확인 → e2e 칸 | 본 것(관찰)만 |
| 판정 | 닿는다 | 닿지 않는다 |
| 읽는 곳 | 판정 · `result.md ## e2e` | 쓴소리 리뷰어의 근거 칸 · `result.md ## 쓴소리` |
| 도는 범위 | PR 범위 | PR 범위(얹어서) · 범위 모드(주된 걷기) |

- **확인 걷기는 그대로다.** 규칙 · 질문 · 게이트 · e2e 칸을 바꾸지 않는다.
- **PR 범위의 순서.** 고른 확인 시나리오를 지금대로 걷고, 그 시나리오의 지문 대조와 판정안을 탐색을 시작하기 **전에** 끝낸다 — 앱은 내리지 않고 지문만 잰다. 그다음 같은 앱에서 탐색을 걷고, 끝나면 앱을 내린다. 탐색 뒤에 한 번 더 잰 지문이 달라졌으면 탐색 기록에 관찰로 적고 e2e 칸은 그대로 둔다. 탐색 후보가 확인 시나리오와 다른 명령을 쓰면 같은 부품으로 따로 띄운다.
- **범위 모드의 순서.** 확인 걷기는 하지 않는다 — 범위 모드에는 실패를 고쳐 다시 도는 길이 없어 통과 · 실패를 가려도 쓸 곳이 없다(지휘자 제안 · 이견 없음). 탐색은 쓴소리 단계에서, 리뷰 트리를 만든 뒤 근거를 조립하기 전에 걷는다(§3).
- **판정 밖이 구조로 지켜진다.** 범위 모드의 탐색은 판정 줄이 나오고 게시가 끝난 뒤에 돈다. PR 범위의 탐색은 판정 전에 돌지만 판정 인자를 쓰는 길이 없다 — 판정 불변 테스트가 변이로 확인한다(AC3).

### §2 탐색 후보와 승인

- **후보.** 오케스트레이터가 diff · 의도 출처 · (있으면) 로드맵을 읽고 써 볼 곳을 고른다. 후보마다 넷을 적는다 — 표면 · 실행할 명령(글자 그대로)과 그 출처 · 준비 신호 · **걸을 목표**(무엇을 써 보고 무엇을 보려는지 한두 줄). 기대 상태 칸은 없다. 명령 출처를 찾지 못하면 그 후보를 만들지 않는다(지금 규칙과 같다).
- **무엇을 고르나.** 닫힌 점검표를 두지 않는다(묶음 Non-goal). 절차 파일은 고르는 눈만 준다 — 이 변경이 사람에게 닿는 곳, 처음 쓰는 사람이 지날 길, 의도 출처가 말하지 않은 옆길(틀린 입력 · 빈 상태 · 되돌리기).
- **PR 범위 — 얹기.** 확인 걷기의 승인 질문과 **같은 `AskUserQuestion` 호출**에 둘째 질문 「탐색 걷기(판정 밖)」 를 붙인다. 선택지는 탐색 후보(둘까지)와 「안 한다」 다. 첫 질문(확인 시나리오)은 선택지 넷이 이미 차 있어 그 안에 넣을 수 없다 — 창은 하나, 질문은 둘이다. 확인 시나리오가 없어도(문서 · skill 만 바뀐 변경) 탐색 후보가 있으면 이 질문은 뜬다.
- **범위 모드 — 넓게.** 시작 전에 규모를 한 줄로 알린다 — 「탐색 <N>곳(앱 띄우기 <a> · CLI <b> · skill <c>) · skill 걷기 예상 비용 약 <금액>」. 후보마다 선택지 하나로 고르게 하고, 한 창에 다 못 싣으면 다음 창으로 잇는다. 고른 것만 걷는다. 숫자 상한은 없다(D17).
- **뒤따르는 제안.** 걷다가 더 볼 곳이 생기면 새 후보로 다시 승인받는다(지휘자 제안 · 이견 없음). 뒤따르는 제안 묶음은 기본 두 번까지이고(레포 설정 값), 그 수에 닿으면 「더 제안하지 않는다」 를 공시한다 — 승인 없이 이어지는 반복을 두지 않는다.
- **준비 명령.** 의존성 설치처럼 띄우기 전에 필요한 명령도 레포 문서에서 읽어 후보의 명령 목록에 넣고 함께 승인받는다(U3).
- **띄운 앱 안.** 승인받아 띄운 앱에서 누르기 · 요청 보내기는 걸을 목표 안에서 모델이 정한다. 지금 걷기 규칙(`127.0.0.1` · `localhost` 만 · 다른 origin 안 감 · 업로드 · 로그인 · 결제 안 함 · 레포 파일 안 고침)은 그대로 적용한다.

### §3 어디서 걷나

- **PR 범위.** 지금처럼 작업 폴더에서 걷는다.
- **범위 모드.** 끝 커밋 임시 폴더에서만 걷는다(U3). R1 의 쓴소리 단계가 범위 모드일 때 `qg-worktree.sh create-head <끝> <session-id> --range` 로 그 폴더를 다시 만든다 — 탐색은 그 폴더를 쓰고, 쓴소리 단계가 끝날 때 지운다. 걷기 부품(`e2e-state.sh` 의 fingerprint · boot)은 지금 셸이 서 있는 리포만 본다 — 걸을 폴더를 인자로 받게 넓힌다.
- **커밋에 없는 것이 필요할 때(U4).** 임시 폴더에는 git 이 추적하는 파일만 있다. 준비 명령을 돌려도 띄우지 못하고 그 까닭이 커밋에 없는 파일(`.env` · 설치된 의존성 등)이면, 건너뛰지 않고 묻는다 — 가져올 경로를 하나씩 보이고 「작업 폴더의 이 파일들을 임시 폴더로 가져와도 될까요?」. 허락하면 가져와 한 번 다시 띄운다. 거절하거나 다시 실패하면 그 후보는 「띄우지 못함」 으로 기록한다.
  - 가져올 수 있는 것은 작업 폴더 안의 경로뿐이다 — 밖을 가리키는 링크와 `.git` 은 거부한다. 방향은 작업 폴더 → 임시 폴더 한쪽이다.
  - 무엇을 가져왔는지는 걷기 기록에 적지 않는다(U5 — 지금 PR 걷기도 작업 폴더의 `.env` 를 기록 없이 쓴다). 가져온 파일의 내용은 어디에도 인용하지 않는다.
- **임시 폴더를 만들지 못하면.** R1 이 이미 「리뷰 트리를 만들지 못함」 으로 쓴소리 단계를 끝낸다 — 탐색도 돌지 않는다.

### §4 표면 — 웹 · API · CLI · skill

웹 UI · API · CLI 는 지금 걷기의 도구와 규칙을 그대로 쓴다. skill 이 새 표면이다.

**skill 걷기 — 헤드리스 실행 한 번이 걷기 한 번이다.** 지금 깔린 판(Claude Code 2.1.325)에서 잰 것(2026-11-14 · 픽스처 플러그인으로 10회):

- 헤드리스 실행(`claude -p "/<플러그인>:<skill> <인자>"`)에서 skill 은 펼쳐져 돈다. `--plugin-dir` 로 실은 플러그인이 깔린 것을 이긴다(앞선 레포 실측).
- 질문 도구(`AskUserQuestion`)는 헤드리스 세션에 없다. 질문하는 skill 은 첫 질문에서 멈추고 답을 지어내지 않았다(sonnet 모델 5회 중 5회).
- 멈춘 실행과 끝까지 간 실행은 종료 코드 · 결과 종류로 구별되지 않는다. 첫 질문의 글은 정해진 칸에 잡히지 않고 모델이 결과 글에 옮겨 적은 것만 남는다.
- 권한 모드를 주지 않으면 그 컴퓨터의 기본값을 따라 결과가 갈린다(이 컴퓨터는 쓰기가 실행됐다). `--permission-mode manual` 이면 쓰기가 거부되고 거부 기록(`permission_denials`)이 남는다.
- 실행마다 약 9초 · 약 0.13달러였고, 깔린 플러그인과 세션 시작 훅이 모두 따라 들어온다.

그래서:

- **명령은 고정 틀이다.** 헤드리스 실행 명령 한 줄을 절차 파일이 정한 틀에서 만들어 글자 그대로 보이고 승인받는다. 틀이 정하는 것 — 걸을 폴더의 플러그인을 싣는다(`--plugin-dir`) · 권한 모드를 명시해 쓰기가 거부되게 한다 · 권한 물음에는 아무도 답하지 않게 한다 · 결과를 기계가 읽는 꼴로 받는다 · 실행마다 비용 상한과 시간 상한을 건다. 모델은 레포 설정 값이 있으면 그것을, 없으면 주지 않는다. 틀의 정확한 플래그는 계획이 지금 판의 도움말에서 정한다.
- **본 것은 원문이다.** 결과 글 전문과 거부 기록을 파일로 남긴다. 「첫 질문에서 멈췄다」 를 스크립트가 판정하지 않는다 — 구별할 신호가 없다. 리뷰어가 원문을 읽는다.
- **첫 질문 뒤는 근거가 아니다.** 결과 글에서 첫 질문 뒤에 나온 내용(모델이 답을 가정하고 이어 간 부분)은 근거로 쓰지 않게 리뷰어 지시에 적는다. 한 모델에서 다섯 번 본 것이라 다른 모델 · 「계속 진행하라」 는 문구가 있는 skill 에서는 지어낼 수 있다.
- **그 뒤는 사람 자리다.** skill 걷기마다 「첫 질문 뒤를 직접 써 보기」 를 사람 자리로 적는다(§7).
- **판이 낮으면.** 틀이 쓰는 플래그가 없는 판이면 skill 걷기 후보를 만들지 않고 그 사실을 공시한다(`dependencies.md` 의 「없을 때」 칸).
- **`/run` · `/verify`.** `/verify` 는 사람이 부를 때만 도는 Claude Code 의 skill 이라 사람 자리의 「어떻게 써 보나」 로 짚는다(D9). `/run` 은 모델이 부르지 않는다 — 띄울 명령을 그 skill 이 스스로 정해, 명령을 글자 그대로 보이고 승인받을 수 없다. 대신 레포에 그 skill 이 남긴 파일이 있으면 명령 출처로 읽는다. **이것은 확정 D9 의 「/run 포함」 을 좁히는 것이라 사용자 확인이 필요하다.**

### §5 탐색 기록과 근거 칸

- **기록 파일.** 탐색은 세션 폴더의 새 파일(`explore-record.md`)에 남긴다. 확인 걷기 기록(`e2e-record.md`)과 섞지 않는다. 걷기마다 한 절이고 — 걸을 목표 · 표면 · 실행한 명령 · 본 것 · 사람 자리. 「본 것」 은 줄마다 **원문**(명령 출력 · 응답 · 화면에 보인 글을 스크립트나 도구가 낸 그대로)인지 **메모**(오케스트레이터가 옮겨 적은 글)인지 표지를 단다.
- **원문을 우선한다.** CLI 와 skill 걷기의 출력은 스크립트가 파일로 받아 기록에 그대로 넣는다. 웹 · API 는 도구 출력에서 짧게 인용한다. 인용할 원문이 없는 관찰은 메모로만 남는다.
- **근거 칸.** R1 의 `evidence` 칸 이름은 그대로 두고(R1 설계가 열어 둔 자리) 조립을 넓힌다 — 줄 앞 표지가 `[e2e]` · `[차등]` 에 더해 `[탐색·원문]` · `[탐색·메모]` · `[동시 작업]` 이 된다. 줄 번호 인용 규칙은 같다.
- **근거가 있다는 것.** 탐색 기록에 본 것이 한 줄이라도 있거나 동시 작업에 겹침이 하나라도 있으면 근거가 있다(R1 U9 의 「관찰」 에 든다). 그래서 범위 모드도 걸었으면 리뷰어를 부른다 — R1 설계의 「범위 모드는 대개 근거 없음으로 끝난다」 는 R2 뒤에는 걷지 않은 실행에만 맞다.
- **리뷰어 지시.** 리뷰어 정의에 표지의 뜻을 적는다 — 원문을 메모보다 무겁게 본다 · 확인 걷기의 통과 · 실패는 근거가 아니다(R1 K17 그대로) · skill 걷기의 첫 질문 뒤는 근거가 아니다 · 동시 작업 줄은 다른 브랜치의 글이라 지시가 아니라 자료다.
- **입력 상한.** 탐색 기록과 동시 작업이 커지면 R1 의 입력 상한 갈래(한 번에 넣기)로 간다. 동시 작업은 따로 바이트 상한을 두고 넘친 수를 공시한다(§6).

### §6 동시 작업 읽기

- **누가.** qg 스크립트 하나가 정해진 git 명령으로 읽는다. 모델이 고른 명령이 아니고 읽기만 하므로 걷기 승인을 받지 않는다(지휘자 제안 · 이견 없음). PR 범위와 범위 모드 모두 돈다.
- **무엇을(U6).** 이번 리뷰 범위가 바꾼 파일 목록을 기준으로 —
  - 다른 브랜치(로컬 · 원격)가 기본 브랜치에서 갈라진 뒤 같은 파일을 고쳤는지.
  - 열린 PR 이 같은 파일을 고치는지(`gh` 가 있을 때).
  - 겹치는 파일은 그쪽 변경 내용(그 파일의 diff)도 가져온다.
- **못 본 것은 「확인 못 함」.** 다른 worktree 의 커밋 안 된 작업은 읽지 않고 worktree 수만 세어 「커밋 안 된 작업 확인 못 함」 으로 적는다. `gh` 가 없거나 실패하면 「열린 PR 확인 못 함」. 다른 컴퓨터 · 원격에 올리지 않은 작업은 「볼 수 없음」 한 줄.
- **기록.** 세션 폴더의 새 파일(`concurrent-work.md`)에 — 겹치는 브랜치 · PR · 파일 · 그 diff, 그리고 확인 못 한 것. 겹침이 없으면 「겹침 없음」 한 줄이고 근거로 치지 않는다.
- **상한.** 가져오는 diff 는 바이트 상한(레포 설정 값)까지이고, 넘친 브랜치 · 파일 수를 「<n>개 중 <m>개만」 으로 공시한다. 이미 기본 브랜치에 머지된 브랜치는 뺀다.
- **기본 브랜치.** 원격의 기본 브랜치에서 도출한다. 도출하지 못하면 읽지 않고 그 사실을 공시한다.

### §7 사람이 써 볼 자리

- **적는 곳.** 탐색 기록의 걷기마다 「사람 자리」 줄 — 어디인지 · 왜 사람이 봐야 하는지 · 어떻게 써 보는지(명령 · `/verify` · skill 호출 줄). 모델이 판단할 수 없는 곳이다 — 보기 좋은지 · 쓰기 편한지 · skill 의 첫 질문 뒤.
- **보이는 곳.** 쓴소리 단계의 렌더가 `result.md ## 쓴소리` 와 돌려주는 꼴에 「직접 써 보실 자리」 목록으로 싣는다. 쓴소리 질문이 없어도 걸었으면 목록은 보인다. 리뷰어는 질문에 사람 자리를 함께 가리킬 수 있다(D10 「질문과 함께 짚는다」).
- **답을 받지 않는다.** 짚기만 한다 — 답 파일도 다시 묻지 않기도 없다.
- **쓴소리 단계가 안 돌면.** 사람 자리는 탐색 기록에만 남는다(그 실행에서는 보이지 않는다). 쓴소리 스위치가 켜져 있으면 탐색도 돌지 않으므로 이 경우는 쓴소리 단계가 중간에 실패했을 때뿐이다.

### §8 두 박자를 위한 경계

인터뷰에서 지휘자 자동 호출은 두 박자로 정했다 — 첫 박자에 걸을 목록과 규모를 파일에 남기고, 게이트에서 승인하면 둘째 박자에 걷는다(S25). R2 는 그 둘을 잇지 않고 경계만 둔다.

- **목록 만들기와 걷기를 가른다.** 탐색 스크립트는 「후보 목록을 파일로 쓴다」 와 「고른 후보를 걷고 기록한다」 를 다른 명령으로 둔다. 후보 목록 파일은 후보마다 명령 · 출처 · 걸을 목표를 담아, 사람이 그 파일만 보고 승인할 수 있다.
- **R2 가 하는 것은 한 실행 안의 승인이다.** 사람이 qg 를 바로 부른 실행에서는 목록을 만들고 그 자리에서 묻는다.
- **R3 몫.** 목록 파일을 docs 에 남기고 게이트에서 승인받아 둘째 박자에 넘기는 길, 그리고 범위 모드가 걷기 승인은 묻고 쓴소리 질문은 묻지 않는(R1 D2.6) 어긋남을 정리하는 일.

## 상류 · 하류 연계

- **받는 곳.** R1 — 근거 칸 계약 · 쓴소리 단계의 걸음(리뷰 트리 · 준비 · 렌더) · 돌려주는 꼴. qg 를 부르는 쪽 — 사람 세션(PR · 범위 모드), R3 이후 지휘자.
- **넘기는 곳.** 탐색 기록 · 동시 작업 → R1 의 근거 조립 → 리뷰어. 사람 자리 → R1 렌더 → 사용자. 후보 목록 파일 꼴과 「목록 만들기 / 걷기」 경계 → R3(두 박자).
- **되돌아오는 길.** 탐색에서 본 것으로 리뷰어가 물은 질문의 답은 R1 의 길로 돌아간다. 탐색 자체는 되돌릴 것이 없다 — 판정에 닿지 않는다.
- **같은 상태를 읽는 표면.** `explore-record.md` — R1 근거 조립 · R1 렌더(사람 자리) · `result.md` 를 다시 보는 사람. 끝 커밋 임시 폴더 — R1 쓴소리 단계(리뷰어가 읽음)와 탐색(걷기)이 함께 쓴다. 지우는 것은 R1 의 마지막 걸음 하나다.
- **이음매 담당.** 근거 칸의 표지와 탐색 기록 꼴은 R2 가 정하고 R1 의 조립 · 리뷰어 정의를 R2 가 고친다. 옆 로드맵(conductor-context-economy)의 과제 폴더(`jobs/<과제>/results/`)가 정해지면 지휘자 경유 호출의 탐색 결과가 갈 자리는 R3 가 잇는다.

## Acceptance Criteria

- **AC1** 탐색 걷기 절차가 따로 된 파일에 있고 qg 본문에는 들어가는 줄만 있다. 들어가는 자리는 둘이다 — PR 범위의 확인 걷기 승인 자리, 범위 모드의 쓴소리 단계(리뷰 트리 뒤 · 근거 조립 앞).
- **AC2** 탐색 후보에는 기대 상태 칸이 없고, 탐색은 증거표 · 판정안 · e2e 칸을 쓰지 않는다. 탐색 기록은 확인 걷기 기록과 다른 파일이다.
- **AC3** 탐색 걷기 · 동시 작업 읽기 · 사람 자리가 있든 없든 qg 판정 줄은 같다 — 탐색 뒤에 리포 파일이 바뀐 경우를 포함해 변이로 확인한다. PR 범위에서 확인 걷기의 지문 대조와 판정안은 탐색을 시작하기 전에 끝난다.
- **AC4** PR 범위에서 탐색 후보는 확인 걷기 승인과 같은 `AskUserQuestion` 호출의 둘째 질문으로 뜬다. 고른 후보만 걷고, 고르지 않으면 걷지 않는다. 추천을 달지 않는다.
- **AC5** 범위 모드에서 확인 걷기는 돌지 않고, 탐색은 시작 전에 규모 한 줄을 공시한 뒤 후보마다 승인받아 고른 것만 걷는다. 뒤따르는 제안 묶음은 설정 값(기본 2)까지이고 닿으면 공시한다.
- **AC6** 범위 모드의 탐색은 끝 커밋 임시 폴더에서만 걷는다. 걷기 부품이 걸을 폴더를 인자로 받고, 인자가 없으면 지금 동작과 같다.
- **AC7** 임시 폴더에서 커밋에 없는 파일 때문에 띄우지 못하면 가져올 경로를 보이고 허락을 묻는다. 허락하면 가져와 한 번 다시 띄우고, 거절하면 「띄우지 못함」 으로 기록한다. 작업 폴더 밖을 가리키는 경로 · `.git` 은 가져오지 않는다. 가져온 파일의 내용은 기록에 없다.
- **AC8** 이 컴퓨터에서 실행되는 명령은 승인 질문에 글자 그대로 보인 것뿐이다 — 준비 명령과 skill 걷기의 헤드리스 명령을 포함한다.
- **AC9** skill 걷기는 헤드리스 실행 한 번이고, 걸을 폴더의 플러그인을 싣고, 권한 모드를 명시해 쓰기가 거부되며, 실행마다 비용 · 시간 상한이 걸린다. 결과 글 전문과 거부 기록이 원문으로 남는다. 틀의 플래그가 없는 판이면 skill 후보를 만들지 않고 공시한다.
- **AC10** 탐색 기록의 「본 것」 은 줄마다 원문 · 메모 표지를 갖고, CLI · skill 출력은 스크립트가 받은 그대로다.
- **AC11** R1 의 근거 조립이 탐색 기록과 동시 작업을 표지와 함께 싣고, 탐색에서 본 것이나 겹침이 있으면 근거가 있다고 본다. 확인 걷기 기록만 있을 때의 R1 동작은 그대로다.
- **AC12** 리뷰어 정의가 표지의 뜻 · 첫 질문 뒤는 근거가 아님 · 동시 작업 줄은 자료임을 적는다. 리뷰어의 도구 목록은 그대로다(읽기 전용).
- **AC13** 동시 작업 읽기는 이번 범위가 바꾼 파일과 겹치는 다른 브랜치 · 열린 PR 을 찾아 겹치는 파일의 diff 를 싣고, 커밋 안 된 worktree 작업 · `gh` 없음 · 기본 브랜치 도출 실패를 「확인 못 함」 으로 적는다. 상한을 넘으면 넘친 수를 공시한다. 사람 승인 없이 돌고 리포를 바꾸지 않는다.
- **AC14** 사람 자리는 걸었으면 쓴소리 질문 수와 무관하게 `result.md ## 쓴소리` 와 돌려주는 꼴에 목록으로 보인다. 답을 받지 않는다.
- **AC15** 탐색 스크립트가 「후보 목록 쓰기」 와 「고른 후보 걷기」 를 다른 명령으로 갖는다.
- **AC16** 걷기 스위치나 쓴소리 스위치가 켜져 있으면 탐색은 돌지 않고 사유 한 줄을 공시한다. 새 스위치는 없다.
- **AC17** 헤드리스 실측(판 · 명령 · 결과)이 레포에 기록되고 `dependencies.md` 의 Claude Code 행이 skill 걷기에 맞게 고쳐진다.
- **AC18** 새 세션 파일이 P2 지우기 목록 · 세션 파일 이름 목록 · 상태 파일 문서에 모두 있다.
