# 스위치와 상태 자리 이전 — 설계

플러그인을 통째로 끄는 길을 Claude Code 의 플러그인 끄기로 바꾸고, 끄는 환경변수를 27개에서 7개로 줄이고, 플러그인 폴더 아래의 일회용 작업 사본을 플러그인 이름이 없는 worktree 폴더(`.claude/worktrees/`)로 옮긴다. 상태 파일은 옮기지 않고 어디에 두는지의 규칙만 성격별로 고쳐 쓴다.

## Context / Why

사용자가 이 일을 하는 이유는 이것이다 — 「일단은 공식이 모델을 학습시키고 클로드 코드를 만들었으니 따라가는건데」. 공식 장치는 모델이 이미 알고 Claude Code 가 받쳐 주므로, 그 위에 서면 이 레포가 따로 가르치고 지켜야 할 것이 준다.

인터뷰는 방향을 「환경변수 kill switch 를 없애고 공식 설정만 쓰며 런타임 상태를 공식 데이터 폴더로 옮긴다」(D21)로 정했고, 옮기기 전에 재라고 했다(D31 · D35). 앞 에픽 P1 이 쟀다(`official-device-probe.md` — Claude Code 2.1.325 · macOS · 화면 없는 세션). 그 결과가 방향을 좁혔다.

1. **샌드박스를 켠 세션에서 Bash 로 도는 스크립트는 공식 데이터 폴더에 쓰지 못한다.** 쓰기 허용 설정으로도 풀리지 않았다. 이 레포의 상태 쓰기는 전부 skill 이 Bash 로 부르는 스크립트다(spec-distill · quality-gates 에는 훅이 없다). 작업 폴더 밖 파일은 Read 에도 승인이 필요했고 하위 agent 도 같았다.
2. **플러그인 사용자 옵션(userConfig)은 스크립트에 닿지 않는다.** skill 본문의 글자 치환과 훅 프로세스에만 닿고, 프로젝트 설정에서는 읽히지 않으며, 값을 주지 않으면 기본값도 오지 않았다.
3. **플러그인 끄기는 통째로만, 새 세션부터 먹는다.** 훅 하나 · skill 하나만 끄는 공식 길은 없다.

지금 레포의 모습(조사 보고 — 계획의 첫 과제가 다시 확인한다):

- 끄는 스위치가 27개다 — 플러그인 통째 끄기 4, 기능 끄기 17, 이름 붙은 한 곳만 끄는 자리 6(`DEVBREW_SKIP_HOOKS` 의 토큰). 그 가운데 넷은 읽는 코드가 없고 skill 글의 문장으로만 꺼진다. 값을 정하는 변수 21개는 따로 있다.
- 설치되는 훅은 project-init 의 하나뿐이다.
- 상태 자리는 열여덟 곳이다. 공식 데이터 폴더를 쓰는 코드는 0 이다.
- 일회용 작업 사본을 플러그인 폴더 아래에 만드는 곳은 셋이다 — quality-gates 의 비교용 사본, plugin-audit 의 자체 테스트 사본, 지휘자(spec-distill)의 스위트 대조 사본. 이 설계가 옮기는 것은 앞의 둘이다.

사용자는 이 사실을 보고 설계 대화에서 방향을 다시 정했다(결정 기록). 통째 끄기만 공식으로 옮기고, 상태는 성격으로 갈라 작업 사본만 옮긴다. 그리고 「끄는거가 꼭 필요한지도 생각해보고」 라는 말에서 시작해 스위치 자체를 줄였다.

## Goals

- 플러그인을 통째로 끄는 길이 Claude Code 의 플러그인 끄기 하나다.
- 끄는 환경변수는 7개만 남는다. 남은 것마다 없으면 막을 길이 없는 이유가 하나씩 있다.
- 끄는 환경변수가 켜져 있으면 skill 을 부를 때마다 첫머리에 보인다.
- 옛 변수를 켜 둔 사용자가 판을 올렸다고 조용히 다시 켜지는 일을 겪지 않는다 — 한 판 동안은 그대로 듣고 알리며, 그 뒤에는 「더 듣지 않는다」 를 알린다.
- 품질 게이트와 감사가 플러그인 폴더 아래에 만들던 작업 사본 둘이 `.claude/worktrees/` 로 옮겨진다 — 하니스가 worktree 를 두는 폴더와 같은 이름이다. 지휘자의 스위트 대조 사본은 옆 로드맵이 옮길 때까지 지금 자리에 남는다.
- 상태를 어디에 두는지의 규칙이 CLAUDE.md 에 성격별 네 갈래로 적힌다.

## Non-goals

- 상태 파일을 공식 데이터 폴더로 옮기지 않는다. 지금은 옮길 것이 없다 — 규칙만 적는다(설계 4).
- 플러그인 사용자 옵션(userConfig)과 skill 거부 규칙은 쓰지 않는다.
- 값을 정하는 변수 21개는 그대로 둔다.
- 대화 중에 「이번만 끄기」 를 만들지 않는다. 남는 7개는 미리 막아 두는 안전장치다. 그때그때 건너뛰는 것은 앞 에픽 F4 가 만든 「모델 판단으로 건너뜀 — 이유」 가 맡는다.
- Claude Code 의 최소 판을 강제하지 않는다(설계 7).
- 문서 리뷰 원장 · 품질 게이트 세션 폴더 · 감사 실행 폴더와 보고서는 지금 자리에 둔다. docs 로 새로 옮기는 것도 없다.
- 지휘 기계 상태와 지휘자의 스위트 대조 사본은 손대지 않는다 — 옆 로드맵(지휘자 맥락 경제)이 그 파일들을 예약하고 지휘 구조를 다시 짓는다.
- 실측을 다시 하지 않는다(P1 의 몫이었다).
- 이미 은퇴한 옛 이름들의 알림은 없애지 않는다. 다만 그 알림이 대신 쓰라고 권하는 이름이 이번에 은퇴하므로, 권하는 길은 둘째 판에서 새 길로 고친다(설계 3).

## Anti-goals

- 꺼 둔 것이 판을 올리자 알림 없이 다시 켜지는 것.
- 하니스의 worktree 폴더에서 사용자나 다른 도구가 만든 worktree 를 지우는 것.
- 문장으로만 꺼지는 스위치가 다시 생기는 것.
- 공식 장치로 옮긴다며 샌드박스를 켠 세션에서 리뷰와 인터뷰가 서는 것.

## Constraints

- 공식 자료는 따라야 할 기준이 아니라 참고다(D34). 이 설계가 공식 쪽으로 옮기는 것은 둘이다 — 통째 끄기와 작업 사본 자리.
- 끄기 변수는 보안 컨트롤이다(CLAUDE.md · 철학 P21). 특히 남의 코드를 실행하는 일을 막는 둘은 없애면 보안을 약하게 하는 변경이 된다.
- CLAUDE.md 는 kill switch 를 은퇴시킬 때 CHANGELOG `Removed` 와 README 공시를 요구하고, 제거 전에 minor 한 판의 예고 창을 요구한다.
- 진입 사전 검사 파일(`shared/entry/entry_preflight.py`)은 네 플러그인이 링크로 싣는다. 고치면 넷의 판이 모두 오른다.
- 이 설계가 닿는 파일을 다른 에픽과 다른 로드맵이 함께 고친다(상류 · 하류 연계).
- 락을 고치면 변이로 실패를 보이고 양성 대조를 둔다.
- 이 세션과 하위 agent 는 Claude Code 를 안에서 다시 띄워 잴 수 없다. 재지 못한 사실은 재지 못했다고 적는다(남는 한계).

## Approaches

갈린 것은 셋이다. 셋 다 사용자가 골랐다.

**상태 자리**

- **다 — 성격으로 가른다(고름).** 세션과 리뷰어가 읽고 쓰는 파일은 작업 폴더에 두고, 일회용 작업 사본만 `.claude/worktrees/` 로 옮긴다. 스크립트만 쓰는 캐시가 생기면 그때 데이터 폴더로 보낸다. 샌드박스 세션에서도 지금처럼 돈다. 옮기는 양이 가장 적다.
- **가 — 전부 데이터 폴더, 막히면 멈춘다.** 인터뷰의 원래 방향이다. 샌드박스를 켠 사용자는 리뷰와 품질 게이트를 쓸 수 없게 되고, 리뷰어가 읽는 파일마다 승인이 필요해진다.
- **나 — 데이터 폴더 먼저, 막히면 프로젝트 안으로.** 자리가 둘이 되어 같은 문서의 원장이 세션에 따라 다른 곳에 생긴다. 방어 코드와 테스트가 두 배가 된다.

사용자: 「다로 가자」.

**스위치를 무엇으로 옮기나**

- **A — 통째 끄기만 공식으로(고름).** 통째 끄기 4개를 공식 플러그인 끄기로 바꾸고, 나머지는 환경변수로 둔 채 공식 설정의 `env` 칸에 적는 길을 안내한다.
- **B — 기능 스위치도 사용자 옵션으로.** 실측에서 값이 스크립트에 닿지 않았다. 닿게 하려면 skill 본문마다 치환 줄을 두고 값을 스크립트 인자로 넘겨야 하고, 프로젝트 설정으로는 줄 수 없다.
- **C — 섞기.** 스위치마다 길이 달라져 끄는 법이 더 어려워진다.

사용자: 「A로 가자, 끄는거가 꼭 필요한지도 생각해보고 끄면 기능상 문제 있는거 아닌가」.

**얼마나 남기나**

- **7개만 남긴다(고름).** 기준은 하나다 — skill 이 묻지 않고 자동으로 하는 일 가운데, 사용자가 막고 싶을 수 있는데 공식 장치로는 막을 길이 없는 것만 스위치가 필요하다.
- **코드 실행을 막는 2개만.** codex 가 깔린 기계에서는 늘 내용이 나가고, 열린 PR 에는 늘 코멘트가 달린다.
- **전부 없앤다.** 믿지 못하는 코드를 리뷰할 때 실행을 막을 길이 없어진다.

사용자: 「저기서 불필요도 빼고 가자」 — 지휘 세션은 이 말을 「7개만 남긴다」 로 읽었고, 다음 메시지에서 그렇게 읽었다고 보였다(정정 없음).

## 설계

### 1. 끄는 길

**통째 끄기.** 플러그인을 통째로 끄는 길은 Claude Code 의 플러그인 끄기다 — `/plugin` 화면, `claude plugin disable`, 설정의 `enabledPlugins`. 끄면 그 플러그인의 skill 과 훅이 함께 꺼진다. 새 세션부터 먹고, 도는 세션은 `/reload-plugins` 뒤에 먹는다(실측). `DEVBREW_<PLUGIN>_DISABLE` 넷은 은퇴한다.

**남는 끄기 변수 7개.**

| 변수 | 막는 일 | 남는 이유 |
|---|---|---|
| `DEVBREW_SPEC_DISTILL_DISABLE_CODEX` · `DEVBREW_QUALITY_GATES_DISABLE_CODEX` · `DEVBREW_PLUGIN_AUDIT_DISABLE_CODEX` | codex 가 깔려 있으면 문서와 코드를 다른 회사 모델로 보낸다 | 막을 다른 길이 없다 |
| `DEVBREW_QUALITY_GATES_DISABLE_DIFFERENTIAL_TEST` | 리뷰 대상 저장소의 테스트를 실행한다(e2e 부팅도 함께 막는다) | 믿지 못하는 코드를 리뷰할 때 |
| `DEVBREW_PLUGIN_AUDIT_DISABLE_RUNTIME_SANDBOX` | 감사 대상 플러그인의 테스트를 실행한다 | 같은 이유. 옛 이름 `DEVBREW_QUALITY_GATES_DISABLE_RUNTIME_SANDBOX` 도 지금처럼 듣는다 |
| `DEVBREW_QUALITY_GATES_DISABLE_PUBLISH` | 열린 PR 이 있으면 묻지 않고 코멘트를 단다 | 바깥에 글이 올라간다 |
| `DEVBREW_SPEC_DISTILL_DISABLE_WEB` | 인터뷰와 brief 리뷰가 웹을 조사한다 | 웹이 안 되는 환경에서 인터뷰 검사가 웹 근거를 요구하지 않게 하는 일도 한다 |

**없어지는 20개와 대신할 길.**

| 없어지는 것 | 대신할 길 |
|---|---|
| 통째 끄기 넷 `DEVBREW_<PLUGIN>_DISABLE` | Claude Code 의 플러그인 끄기 |
| 보안 리뷰어 끄기 `DEVBREW_QUALITY_GATES_DISABLE_SECURITY_REVIEWER` | 없다 — 보안 리뷰는 늘 돈다(읽는 코드가 없던 스위치) |
| 재비판 끄기 `DEVBREW_SPEC_DISTILL_DISABLE_RECRITIC` · brief 리뷰 끄기 `DEVBREW_SPEC_DISTILL_DISABLE_BRIEF_REVIEW` | 없다 — 재비판은 작은 일에서 건너뛰는 것을 모델 판단이 이유를 적고 한다(F4). brief 리뷰는 첫 검토가 늘 돌고, 작은 일에서 재비판 · codex · 읽어 보기를 건너뛰는 것만 모델 판단이 이유를 적고 한다(결정 기록의 2026-11-18 재결정). 둘 다 읽는 코드가 없던 스위치다 |
| 워크트리 질문 끄기 `DEVBREW_SPEC_DISTILL_DISABLE_WORKTREE` | 질문에 「아니오」 로 답한다(읽는 코드가 없던 스위치) |
| 설계문서 리뷰 끄기 둘 — `DEVBREW_SPEC_DISTILL_DESIGN_MODE_DISABLE` · `DEVBREW_SKIP_HOOKS=spec-distill:review-entry` | 그 skill 을 부르지 않는다 |
| 문서 비평 끄기 `DEVBREW_QUALITY_GATES_DISABLE_CRITIQUE` | 그 skill 을 부르지 않는다 |
| 품질 게이트 이름의 웹 끄기 `DEVBREW_QUALITY_GATES_DISABLE_WEB` | 남는 `DEVBREW_SPEC_DISTILL_DISABLE_WEB`. 이 변수가 실제로 끄는 것은 spec-distill 의 brief 리뷰가 codex 에 여는 웹 검색 하나뿐이다(품질 게이트 자신의 codex 호출은 웹을 늘 꺼 둔다) — 잃는 것이 없다 |
| 감사의 codex 웹 검색 끄기 `DEVBREW_PLUGIN_AUDIT_DISABLE_WEB` | codex 끄기. 감사에서 codex 는 쓰되 웹 검색만 막는 길은 없어진다(남는 한계) |
| e2e 끄기 `DEVBREW_QUALITY_GATES_DISABLE_E2E` | e2e 는 원래 묻고 돈다 — 「아니오」 로 답한다. 실행 자체를 막으려면 차등 테스트 끄기 |
| 의도 점검 끄기 `DEVBREW_QUALITY_GATES_DISABLE_INTENT_CRITIC` | 없다 — 읽기만 하는 단계다 |
| project-init 훅 끄기(`DEVBREW_SKIP_HOOKS` 의 그 훅 토큰) | 플러그인 끄기, 또는 설정의 `disableAllHooks`(모든 플러그인의 훅이 함께 꺼진다) |
| 로드맵 지도 끄기(`DEVBREW_SKIP_HOOKS=spec-distill:statusline`) | 상태줄 설정을 지운다. 이 스위치는 지휘자의 상태 계산까지 꺼서 지휘를 멈추게 했다 |
| 원장 정리 끄기 둘(`spec-distill:SessionEnd` 와 그 별칭 · `spec-distill:spec-distill-gc`) | 유예 시간 변수 `DEVBREW_SPEC_DISTILL_TTL_HOURS` 를 크게 준다 |
| 세션 폴더 정리 끄기(`quality-gates:qg-gc`) | 유예 시간 변수 `DEVBREW_QUALITY_GATES_TTL_HOURS` 를 크게 준다 |

`DEVBREW_SKIP_HOOKS` 변수는 토큰 여섯이 모두 없어지므로 통째로 은퇴한다.

**환경변수를 주는 길.** 남는 변수는 셸에서 주거나 Claude Code 설정의 `env` 칸에 적는다. `env` 칸의 값이 Bash 로 도는 스크립트에 닿는지는 이 레포에서 재지 않았다(공식 문서만 읽었다). 그래서 README 는 확인하는 법을 함께 적는다 — 적은 뒤 skill 을 부르면 첫머리에 「꺼져 있다」 줄이 보인다(설계 2). 보이지 않으면 값이 닿지 않은 것이니 셸 환경변수로 준다.

### 2. 꺼져 있는 것 보이기

진입 사전 검사가 지금 내는 감시줄 한 줄 아래에, 그 플러그인의 끄기 변수 가운데 켜진 것을 변수마다 한 줄로 낸다. 켜진 것이 없으면 아무 줄도 더하지 않는다 — 출력은 지금과 글자 그대로 같다.

```
[devbrew-entry] ok plugin=spec-distill skill=spec-review root=/…/repo
[devbrew-switch] 꺼져 있다 — codex 리뷰(DEVBREW_SPEC_DISTILL_DISABLE_CODEX=1)
[devbrew-switch] 꺼져 있다 — 재비판(DEVBREW_SPEC_DISTILL_DISABLE_RECRITIC=1). 이 변수는 다음 판부터 듣지 않는다 — 작은 일에서 건너뛰는 것은 모델 판단이 한다
```

- 줄의 종류는 셋이다 — 남는 변수(「꺼져 있다」), 은퇴 예정 변수(「꺼져 있다 … 다음 판부터 듣지 않는다 — 대신할 길」), 은퇴한 변수(「더 듣지 않는다 — 대신할 길」).
- 진입 skill 아홉의 진입 단계에 한 문장을 더한다 — 감시줄 아래에 `[devbrew-switch]` 줄이 있으면 감시줄이 무엇이든 그 줄들을 사용자에게 그대로 보인다. 그 뒤는 감시줄 판독 표대로다 — `ok` 면 보이고 가고, `disabled` 면 `disabled` 줄과 함께 보이고 멈춘다. 감시줄 판독 표는 바꾸지 않는다.
- 끄기 변수는 값이 정확히 `1` 일 때만 켜진 것으로 본다(지금과 같다). `DEVBREW_SKIP_HOOKS` 하나만 값이 쉼표로 나눈 토큰 목록이다 — 사전 검사는 지금의 판정과 같은 규칙(쉼표로 나누고 양끝 공백을 걷은 전체 토큰 대조)으로 자기 플러그인의 토큰을 찾아 토큰마다 한 줄을 낸다. 표는 토큰 여섯을 한 행씩 싣고, 같은 자리를 끄는 다른 이름(훅 이름과 이벤트 이름 · 원장 정리의 별칭)은 그 행에 함께 적어 어느 이름으로 꺼 두었든 줄이 나오게 한다. 테스트는 토큰 꼴마다 줄이 나오는지를 본다.
- **끄기 변수 표.** 어떤 이름이 어느 종류인지는 플러그인마다 표 하나가 주인이다 — 칸은 이름 · 무엇을 끄나(쉬운 말 한 구절) · 상태(남음 · 은퇴 예정 · 은퇴) · 대신할 길. 사전 검사는 자기가 불린 플러그인의 표를 읽고, README 의 「끄는 길」 절은 그 표와 같다(테스트가 대조한다). 표의 파일 꼴과 자리는 계획이 정한다.
- 사전 검사는 불린 플러그인의 표에 실린 이름만 보인다. 표에 싣는 기준은 이름이 아니라 듣는 곳이다 — 그 플러그인의 코드(링크로 실은 공유 스크립트 포함)가 듣는 끄기 변수는 이름이 다른 플러그인 것이어도 그 플러그인의 표에 싣는다. 알림이 실제로 꺼지는 자리에서 보이게 하려는 것이다. 지금 이름과 듣는 곳이 다른 것은 셋이다 — `DEVBREW_QUALITY_GATES_DISABLE_WEB`(spec-distill 의 brief 리뷰가 듣는다) · `DEVBREW_QUALITY_GATES_DISABLE_RUNTIME_SANDBOX`(감사가 옛 이름 별칭으로 듣는다) · `DEVBREW_QUALITY_GATES_DISABLE_DIFFERENTIAL_TEST`(지휘자의 스위트 대조가 공유 테스트 러너를 거쳐 듣는다). 계획의 첫 과제가 듣는 곳을 다시 찾아 빠진 것을 올린다. 한 이름이 여러 표에 실릴 수 있고, 스위치 수는 이름으로 센다.
- 사전 검사는 지금처럼 rc 0 만 낸다. 표를 읽지 못하면 감시줄은 그대로 내고 `[devbrew-switch]` 줄 대신 「끄기 변수 표를 읽지 못했다」 한 줄을 낸다 — 못 읽은 것과 켜진 것이 없는 것은 다른 사실이다.
- 내부 skill(사전 검사가 없는 brief 리뷰)은 부르는 진입 skill 의 줄로 덮인다.

### 3. 없애는 순서

두 판에 나눈다. 계획도 둘이다.

**첫 판 — 알림과 옮김.** 옛 변수 20개는 지금과 똑같이 끈다. 달라지는 것은 설계 2 의 줄이 생기는 것, README 와 CHANGELOG(`Deprecated`)가 은퇴 예정과 대신할 길을 공시하는 것, 그리고 설계 4 · 5 다. 통째 끄기 변수가 켜져 있으면 사전 검사는 지금처럼 `disabled` 감시줄을 내고 skill 은 멈춘다 — 그 아래에 은퇴 예정 줄이 붙는다.

**둘째 판 — 실제 은퇴.** 옛 변수를 읽는 코드와 펜스, skill · reference · 템플릿의 문장을 지운다. 그 뒤로 옛 변수가 켜져 있으면 사전 검사가 「더 듣지 않는다 — 대신할 길」 을 보이고 skill 은 정상으로 간다. 함께 없어지는 것:

- 사전 검사의 `disabled` 감시줄과 진입 skill 아홉의 그 행 · 「이 표가 보는 kill switch」 문장.
- 훅과 이름 붙은 자리의 스위치 판정 — `shared/killswitch/` 정본과 플러그인 사본 셋, 훅 해석기(`shared/python/devbrew-python.sh` 와 그 사본)의 스위치 갈래, 그리고 정본을 거치지 않고 변수 이름을 직접 적어 읽는 두 자리(`plugins/spec-distill/scripts/control_plane.py` 의 지도 끄기 판정 · `plugins/spec-distill/scripts/review_entry.py` 의 리뷰 진입 판정).
- spec-distill · 품질 게이트 · 감사의 진입 skill 은 은퇴한 통째 끄기 변수(`DEVBREW_SPEC_DISTILL_DISABLE` · `DEVBREW_QUALITY_GATES_DISABLE` · `DEVBREW_PLUGIN_AUDIT_DISABLE`)가 켜져 있으면 「더 듣지 않는다」 줄을 보인 뒤 계속할지 한 번 묻고, 사용자가 계속을 고를 때만 간다. 물을 수 없는 자리(화면 없는 실행 등)에서는 가지 않고 멈춘다. 변수를 풀면 질문은 사라진다. 세 플러그인은 내용을 바깥으로 보내거나(codex · 웹 조사) 남의 코드를 실행하거나 바깥에 글을 올리므로, 변수로 막아 두었다고 믿는 사용자에게 알리는 순간과 다시 켜지는 순간이 같지 않게 한다. 사전 검사가 끄기 변수 표를 읽지 못했다는 줄을 낸 때도 세 플러그인은 같은 질문을 한다 — 켜진 것이 있는지 알 수 없기 때문이다. project-init 과 그 밖의 은퇴 변수는 알리고 간다.
- 이미 은퇴한 옛 이름의 알림(spec-review 진입 검사가 내는 것)은 남기되, 그 알림이 대신 쓰라고 권하는 길을 새 길(플러그인 끄기 · 그 skill 을 부르지 않기)로 고친다. 그 알림이 옛 토큰을 알아보려고 `DEVBREW_SKIP_HOOKS` 를 읽는 것은 끄는 판정이 아니라 알림용이라 남는다.
- project-init 훅은 다시 돈다. 옛 변수가 켜져 있으면 훅이 알릴 것이 있어 말할 때 그 알림 끝에 「더 듣지 않는다 — 플러그인 끄기를 쓴다」 한 줄을 덧붙인다. 그 알림만을 위해 말하지는 않는다. 훅은 옛 이름을 스크립트에 적지 않고 project-init 의 끄기 변수 표의 「은퇴」 행에서 읽는다 — 표를 읽지 못하면 그 한 줄을 덧붙이지 않고 그대로 돈다.
- 철학 문서 P13 · P21 과 저술 가이드의 kill switch 구절을 새 규칙(설계 5)의 뜻에 맞춘다.

**둘째 판의 때.** 이 로드맵의 다른 에픽(F3 의 둘째 계획 · F5)이 머지된 뒤에 낸다. 이유는 둘이다 — 「한 판 동안」(D39)이 실제 기간이 되고, F5 가 앞단 skill 의 이름과 글을 다시 짜므로 그 글에서 스위치 문장을 한 번만 지우면 된다.

**판 번호.** 첫 판은 minor(예고), 둘째 판은 major(제거)다. 번호는 머지 직전에 정한다.

### 4. 상태 자리

**규칙 — 성격으로 네 갈래.**

1. 세션과 리뷰어가 읽고 쓰는 런타임 state → 작업 폴더의 `.claude/<plugin>/`(지금 그대로). 샌드박스 세션에서도 쓸 수 있고 리뷰어가 승인 없이 읽는 자리가 여기뿐이다.
2. 플러그인이 스스로 만드는 일회용 작업 사본(git worktree) → 지금 작업 트리 꼭대기의 `.claude/worktrees/`. 예외 하나 — 지휘자의 스위트 대조 사본은 지휘 기계 상태 폴더 아래에 둔다(옆 로드맵이 옮길 때까지).
3. 스크립트만 쓰고 잃어도 다시 만들 수 있는 캐시 → 공식 데이터 폴더(`${CLAUDE_PLUGIN_DATA}`)에 프로젝트마다 갈리게. 쓰는 스크립트가 쓸 때 재고, 쓰지 못하면 알리고 캐시 없이 돈다. 플러그인을 지우면 이 폴더도 지워지므로 다시 만들 수 없는 기록은 두지 않는다. **지금 이 갈래에 드는 것은 없다.**
4. 세션을 넘어 남아야 하는 기록 → docs 의 추적 파일(지금 그대로). 새로 옮기는 것은 없다.

**작업 사본 옮기기.**

- 자리는 지금 작업 트리 꼭대기의 `.claude/worktrees/` 다. 꼭대기를 정하는 법은 지금과 같고 폴더 이름만 바뀐다 — `.claude/<plugin>/worktrees/` 에서 `.claude/worktrees/` 로. 본 체크아웃에서 부르면 하니스가 worktree 를 두는 바로 그 폴더이고, 에픽 worktree 안에서 부르면 그 worktree 안의 같은 이름 폴더다. 본 체크아웃 한 곳으로 모으지 않는 것은 그 자리가 worktree 안의 세션에게는 작업 폴더 밖이기 때문이다 — 샌드박스를 켠 세션은 작업 폴더 밖에 쓰지 못했고(P1), 이 경우는 재지 못했다.
- 이름은 플러그인이 드러나는 꼴이다 — `qg-base-<8자>` · `qg-head-<8자>` · `audit-rt-<8자>`.
- 본 체크아웃의 그 폴더에는 사용자와 지휘자의 worktree 가 함께 산다. 그래서 지우기 규칙이 좁아진다 — 자리가 그 폴더이고 이름이 자기 꼴일 때만 지운다. 그 이름이 브랜치를 쥔 worktree 면 지우지 않고 멈춘다(자기가 만든 것은 늘 브랜치를 쥐지 않는다). 만들기 전에 같은 이름이 남아 있을 때도 같다 — 링크면 링크만 지우고(따라가지 않는다), 브랜치를 쥔 worktree 면 멈추고, 그 밖(브랜치를 쥐지 않은 worktree · 등록이 풀린 폴더)은 지금처럼 지우고 다시 만든다. 비정상 종료가 남긴 폴더 때문에 그 세션이 막히지 않게 하는 지금의 복구 동작을 지킨다.
- 만들 때 그 자리가 레포 밖으로 풀리면(링크) 만들지 않는다. 품질 게이트 쪽에는 이 검사가 있고 감사 쪽에는 없다 — 감사 쪽에 더한다.
- 품질 게이트의 리뷰 범위 · 봉인 · 지문에서 빼는 것은 지금의 좁은 규칙을 새 자리로 옮긴 것이다 — 이 세션이 만들어 등록된 자기 이름 꼴의 사본만 뺀다. 다른 세션의 자기 이름 꼴 사본은 지금처럼 「이전 실행이 남긴 트리」 로 알리고, 등록되지 않은 같은 이름 폴더는 지금처럼 크게 알린다. 그 폴더의 다른 것(사용자의 worktree 등)은 새로 빼지 않고 지금과 똑같이 다룬다 — 폴더를 통째로 빼면 리뷰 대상 저장소가 거기 둔 것이 조용히 리뷰를 피한다.
- 감사 샌드박스의 작업 트리 복사는 지금 자기 폴더를 통째로 조용히 뺀다(등록 확인도 알림도 없다). 새 자리에서도 같은 동작이다 — 자기 이름 꼴(`audit-rt-…`)의 것은 어느 세션 것이든 복사에서 뺀다. 그 폴더의 다른 것은 새로 빼지 않는다.
- 옛 자리에 남은 사본은 첫 판의 만들기가 치운다 — 새 자리에 만들기 전에 옛 자리(`.claude/<plugin>/worktrees/`)에 자기 이름 꼴의 것이 남아 있으면 같은 복구 규칙으로 지운다. 지우기 명령도 옛 자리의 경로를 받는다. 이 둘은 둘째 판에서 뺀다.
- 끝나고 남은 사본이 `git worktree list` 와 지휘자의 정리 목록에 보이는 것은 지금도 같다(등록된 worktree 는 자리와 무관하게 두 목록에 나온다). 옮겨서 달라지는 것은 폴더 이름뿐이다 — 플러그인 폴더 아래가 아니라 worktree 를 두는 폴더에 있다.

### 5. 규칙 문장과 검사

CLAUDE.md `### 런타임 상태 & 훅` 의 두 글머리를 아래로 바꾼다. 다른 두 글머리(훅 공존 · graceful degradation)는 그대로다.

**상태 글머리**(바뀌는 곳은 첫 문장을 네 갈래로 바꾼 것과 끝의 인터뷰 문장을 ④ 로 옮긴 것이다. 수명 넷과 그 뒤 문장들은 그대로다):

> - **JSON이 아니라 마크다운 state.** 상태 자리는 성격으로 가른다 — ① 세션과 리뷰어가 읽고 쓰는 런타임 state 는 `.claude/<plugin>/` 하위에 산다(git-ignored) ② 플러그인이 스스로 만드는 일회용 작업 사본(git worktree)은 작업 트리 꼭대기의 `.claude/worktrees/` 에 그 플러그인이 드러나는 이름으로 만들고 자기가 만든 것만 지운다(예외 — 지휘자의 스위트 대조 사본은 지휘 기계 상태 폴더 아래에 둔다) ③ 스크립트만 쓰고 잃어도 다시 만들 수 있는 캐시는 Claude Code 의 플러그인 데이터 폴더(`${CLAUDE_PLUGIN_DATA}`)에 프로젝트마다 갈리게 두고, 쓰지 못하면 알리고 캐시 없이 돈다 ④ 인터뷰처럼 세션을 넘어 남아야 하는 기록은 docs 의 추적 파일에 두고 산출물과 함께 커밋한다. ① 의 수명은 넷이다 — (이하 「세션 단위」 부터 「링크 검사 없이 만든다.」 까지 지금 문장 그대로) **Secret 기록 금지** — placeholder 참조 사용 (철학 P21).

**끄는 길 글머리**(「모든 훅에 kill switch」 글머리를 통째로 바꾼다):

> - **끄는 길은 공식 장치 먼저.** 플러그인을 통째로 끄는 길은 Claude Code 의 플러그인 끄기다(`/plugin` · `claude plugin disable` · 설정의 `enabledPlugins`) — 통째 끄기용 환경변수를 두지 않는다. 끄는 환경변수(`DEVBREW_<PLUGIN>_DISABLE_<기능>=1`)는 skill 이 묻지 않고 하는 일 가운데 사용자가 막고 싶을 수 있는데 공식 장치로 막을 길이 없는 것(내용을 바깥으로 보냄 · 남의 코드를 실행 · 바깥에 글을 올림)에만 둔다. 끄기 변수마다 읽는 코드가 있다 — skill 문장으로만 꺼지는 스위치는 두지 않는다. 켜진 끄기 변수는 진입 사전 검사가 skill 첫머리에 한 줄로 보인다. 끄기 변수는 보안 컨트롤이다 — 읽는 코드는 그 값을 무시할 수 없고, 은퇴는 한 판 동안 옛 이름을 그대로 듣고 알린 뒤에 하며 CHANGELOG `Removed` 와 README 에 공시한다.

이 문장은 첫 판에서 한 번만 고친다. 첫 판 동안 통째 끄기 변수가 아직 듣는 것은 같은 문장의 은퇴 절차를 따르는 중이기 때문이다.

**검사.**

- 감사 검사의 「훅마다 kill switch」 요건(`check-shape-completeness.py` 의 `hooks_killswitch`)과 「훅이 있는데 README 에 kill switch 가 없다」 사실(`check-staleness.py` 의 그 갈래)을 첫 판에서 뺀다. 훅을 끄는 길이 플랫폼의 플러그인 끄기가 되어 훅이 스스로 읽을 것이 없다. 그 요건의 문장 앵커도 함께 뺀다.
- 감사 agent 에게 주는 지시문(`audit-workflow.js`)의 「kill switch 가 실제로 존중되는가」 줄도 첫 판에서 새 규칙에 맞춘다 — 훅과 통째 끄기 변수 대신 남는 끄기 변수가 실제로 존중되는지를 묻는다.
- 둘째 판에서 감사 검사에 요건 하나를 더한다 — 플러그인의 skill 과 README 가 이름 댄 끄기 변수마다 읽는 코드가 있다. 「읽는 코드」 는 그 변수의 값에 따라 그 일을 건너뛰는 스크립트나 skill 펜스다 — 사전 검사와 끄기 변수 표는 세지 않고(그것까지 세면 늘 통과한다), 표의 「은퇴」 행과 README 의 은퇴 표에 적힌 이름은 대상에서 뺀다. 검사가 기계로 세는 것은 그보다 좁다 — 그 플러그인의 스크립트나 skill 펜스에서 주석과 출력 문구 밖에 그 이름을 환경에서 읽는 꼴이 있는가다. 읽고서 실제로 건너뛰는지는 검사가 재지 못한다(그 변수를 켰을 때의 동작 테스트가 잰다). fixture 는 셋이다 — 읽는 곳 있음 · 어디에도 없음 · 주석이나 안내 문구에만 있음(뒤의 둘은 gap). 새 규칙의 「끄기 변수마다 읽는 코드가 있다」 를 지키는 자리다. 첫 판에 넣지 않는 것은 문장으로만 꺼지는 넷이 첫 판 동안 남아 있기 때문이다. 첫 판의 「표의 남음 이름마다 읽는 코드가 실재한다」 테스트도 같은 뜻으로 센다.
- 규칙 락(`test_governance_no_capability_caps.sh`)의 두 글머리 단언을 새 문장에 맞춘다. 새 두 글머리는 줄 전체를 한 번 묻는다 — 구절만 물으면 뒤에 부정하는 말을 붙여도 통과한다(설계 6 의 다섯째 지적).

묶음의 근거를 지금 코드로 다시 본 결과다(조사 보고 둘 — 지휘 자원 폴더의 `relay/F7/research-switches.md` · `research-state.md`).

- **다른 에픽이 예약한 파일.** 이 설계는 로드맵의 F7 경로 예약보다 넓게 닿는다 — 재분해 신호로 적는다(Handoff Context).

## Rejected Alternatives

- **가 · 나 · B · C · 「2개만」 · 「전부 없앤다」** — Approaches.
- **한 판에 다 지우기** — 켜 둔 사용자가 알림을 볼 기회 없이 다시 켜진다(D39 와 어긋난다). 다른 에픽이 고치는 skill 글과도 한꺼번에 부딪힌다.
- **개별 skill 끄기를 skill 거부 규칙으로 옮기기** — 사용자가 직접 부른 skill 을 그 규칙이 막는지 문서에 없고 재지 못했다. 부르지 않으면 되는 일에 장치를 두지 않는다.
- **「꺼져 있다」 줄을 skill 글 없이 사전 검사 출력만으로 보이기** — 모델이 그 줄을 사용자에게 보일지는 skill 글이 정한다. 문장 하나가 없으면 보이는 것이 약속이 아니다.
- **끄기 변수 표를 공유 사전 검사 파일 안에 두기** — 플러그인 넷의 이름이 공유 파일에 박히고, README 와 대조할 주인이 플러그인 밖에 생긴다.
- **작업 사본을 임시 폴더에 만들기** — 「그냥 워크트리」 라는 사용자의 말과 다르고, 하니스가 worktree 를 두는 폴더가 아니다. 품질 게이트의 실행 메모는 이미 임시 폴더를 쓰지만 그것은 worktree 가 아니다.
- **작업 사본을 본 체크아웃의 `.claude/worktrees/` 한 곳으로 모으기** — 처음 설계였다. worktree 안에서 도는 세션에게 그 자리는 작업 폴더 밖이라, 샌드박스를 켠 세션에서 만들기가 막힐 수 있다(재지 못했다). 다른 worktree 에서 도는 세션의 사본이 한 폴더에 모여 서로를 「남은 트리」 로 세는 일도 생긴다.
- **`.claude/worktrees/` 를 리뷰 범위에서 통째로 빼기** — 리뷰 대상 저장소가 그 폴더에 둔 추적 안 된 것이 조용히 리뷰를 피한다.
- **은퇴를 알리려고 훅이 꺼진 채 한 번 말하기** — 「알렸음」 을 적어 둘 상태가 새로 필요하다. 끈 사용자는 조용하기를 바란 것이다.
- **리뷰 원장을 데이터 폴더로 옮기기** — 리뷰어 agent 가 그 폴더의 파일을 읽을 때마다 승인이 필요하고, 샌드박스 세션에서는 쓰지 못한다.
- **Claude Code 최소 판 강제** — 새로 기대는 장치가 오래된 것 하나뿐이다.

## 남는 한계

- 설치본을 `claude plugin disable` 로 끄는 길은 재지 못했다(P1 이 잰 것은 설정의 `enabledPlugins` 다). 설정의 `env` 칸이 Bash 로 도는 스크립트에 닿는지도 재지 못했다. 둘 다 사용자가 손으로 한 번 확인할 수 있게 적는다.
- 감사에서 codex 는 쓰되 웹 검색만 막는 길이 없어진다. 감사의 웹 끄기 변수를 켜 둔 사용자는 둘째 판부터 감사의 codex 웹 검색이 다시 켜진다 — 한 판 동안 알린다.
- 자기 이름 꼴의 등록이 풀린 폴더는 지우고 다시 만든다. 사용자가 그 폴더 안에 `qg-base-<8자>` 같은 이름으로 직접 둔 것이 있다면 지워진다 — 지금 플러그인 폴더 아래에서 하는 동작과 같지만 폴더를 함께 쓰게 된다.
- 에픽 worktree 안에서 부르면 작업 사본이 그 worktree 안의 `.claude/worktrees/` 에 생긴다 — 하니스가 보는 본 체크아웃의 폴더가 아니다. `git worktree list` 에는 보인다.
- 정리 끄기를 켜 둔 사용자는 둘째 판부터 정리가 다시 돈다. 지워지는 것은 문서가 사라진 리뷰 원장과 유예 시간이 지난 남의 품질 게이트 세션 폴더다. 한 판 동안 알리고, 미루는 길(유예 시간 변수)을 함께 보인다.
- project-init 의 훅만 쓰고 skill 을 다시 부르지 않는 사용자는 첫 판의 알림을 볼 자리가 없다. 둘째 판에서 훅이 다시 돌 때 그 알림 끝에서 처음 본다. 이 훅은 알리기만 하고 막지 않는다.
- 첫 판과 둘째 판 사이에는 감사 검사가 끄는 길 규칙을 재지 않는다.
- `.claude/worktrees/` 를 git 이 무시하지 않는 저장소에서는 일회용 사본이 추적 안 된 폴더로 보인다 — 지금 플러그인 폴더 아래에 있을 때와 같다.
- 레포 쪽 수(스위치 · 파일 · 테스트 자리)는 조사 보고다. 조사에서 테스트는 돌리지 않았다.
